A team in one project

Give seats names and jobs. You can hand off work, track answers and let several writers move at once.

What you can do

Keep a builder and reviewer on a feature, add a researcher when a question needs investigation, and see who still owes an answer. Separate worktrees let writers change different parts without sharing an index or checkout.

Try it

In the project you initialized at level 1:

tap launch claude builder

If the builder opens, press Ctrl-b, then d to return to your project shell.

tap launch codex reviewer

Return to your shell the same way to inspect the roster.

tap team
tap attach builder
Add a test for the date parser and make it pass. Assign the review to reviewer, fix material findings, and tell me what you agreed.

The reviewer can read the builder’s stable diff. If both will edit, give each writer a worktree. From the team’s project root, for a new branch:

git worktree add ../parser-fix -b parser-fix
tap launch codex fixer --workdir ../parser-fix

What’s new since level 1

Names become job addresses, and questions and assignments stay open until answered. The agents write message bodies to files before using these commands:

  • tap send reviewer --ask -f question.md asks a question.
  • tap assign reviewer -f task.md hands over work.
  • tap reply <id> -f answer.md answers the incoming ask.
  • tap outstanding builder lists the builder’s unsettled outgoing messages.

For a note that needs no answer, use tap send reviewer -f note.md.
