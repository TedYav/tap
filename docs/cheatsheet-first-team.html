1 / Initialize your project

First follow the installation runbook and sign in to both agent CLIs. Then, in your project:

cd /path/to/your/project
tap init

tap init initializes Git projects directly and asks before enrolling a directory outside Git. The full guide covers enrollment exceptions.

2 / Launch both harnesses

Run these in your project terminal, one at a time:

tap launch claude
# After Claude opens, Ctrl-b then d returns to your terminal.
tap launch codex

TAP starts and registers each seat. Launch opens it from a foreground terminal; otherwise visit it with tap attach claude or tap attach codex. See the names with tap team.

Launch uses your saved permission choice, or bypass mode by default. Choose auto mode before launching if you prefer it. Finish sign-in, folder-trust and hook-review prompts yourself.

3 / Ask for the first exchange

Type into either pane, in plain language:

Run tap team to see the roster, then ask the other agent: should our first tiny project start with a README or a test? One sentence of reasoning. Show me its actual reply.

Approve the tap command if your harness asks — in that pane. Done means the asking pane shows the other agent’s actual answer text. A roster entry, delivery receipt or queued message does not prove that either agent processed it. If mail arrives while you type, type WAIT (in capitals) to hold deliveries for two minutes.

4 / Visit when needed

Detach with Ctrl-b, then d. Detaching leaves the agent running.

tap team
tap attach <seat>

The roster names detected blockers with needs you: tap attach .... Finish sign-in or permission prompts yourself. For Codex’s Hooks need review, review the expected TAP commands and trust only hooks you intend to trust. Declining or skipping leaves TAP’s guard and SessionStart hooks inactive until trusted through Codex review. Installation does not pre-trust hooks; TAP’s courier does not choose for you.

Detach again, return to the asking pane, and ask it to check the original question’s status. Inspect the receiving seat before resending a task.

Mail while you type

In auto mode, TAP waits for an empty composer, including for urgent delivery. In bypass mode, a draft gets a grace period before TAP uses the input box; a red flash warns of the handoff. An interrupt may clear a draft, keeping the text TAP can capture. Pasting it back is conditional; when it does not happen, tap draft recovers it. OpenCode drafts always need tap draft, and pasted content or images may not be captured. Type WAIT in caps to hold deliveries for two minutes.

Queued follow-ups can also hold delivery. The command reference covers delivery and draft recovery.

5 / Stop and return

Leave the view

Ctrl-b, then d. Work continues.

Return to the view

tap attach <seat>

Stop after work finishes

tap team down

Run from the project. The roster remains.

Back after a stop

tap team up
tap attach <seat>

Check each resumed agent’s context before giving it more work.

After the first answer

Give one agent a real task and ask another to review the change. The five levels of TAP shows what two seats can do and when to grow the team. To reuse an old conversation, follow the full guide.
