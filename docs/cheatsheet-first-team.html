1 / Initialize your project

First follow the installation runbook and sign in to both agent CLIs. Then, in your project:

cd /path/to/your/project
tap init

tap init initializes Git projects directly and asks before enrolling a directory outside Git. The full guide covers enrollment exceptions.

2 / Launch both harnesses

Run these in your project terminal, one at a time:

tap launch claude

If Claude opens, press Ctrl-b, then d to return to your project shell.

tap launch codex

TAP starts and registers each seat. Launch opens it from a foreground terminal; otherwise visit it with tap attach claude or tap attach codex. See the names with tap team.

Launch uses your saved permission choice, or auto mode by default. Choose bypass mode before launching if you prefer it. Finish sign-in, folder-trust and hook-review prompts yourself.

3 / Ask for the first exchange

Type into either pane, in plain language:

Run tap team to see the roster, then ask the other agent: should our first tiny project start with a README or a test? One sentence of reasoning. Show me its actual reply.

Approve the tap command if your harness asks — in that pane. Done means the asking pane shows the other agent’s actual answer text. A roster entry, delivery receipt or queued message does not prove that either agent processed it. If mail arrives while you type, type WAIT (in capitals) to hold deliveries for two minutes.

4 / Visit when needed

Detach with Ctrl-b, then d. Detaching leaves the agent running.

tap team
tap attach <seat>

The roster shows a seat waiting on a prompt as blocked, and a seat whose last turn failed (an API error or usage limit) as error; tap team doctor explains each one and names the command that helps. Finish sign-in or permission prompts yourself. For Codex’s Hooks need review, review the expected TAP commands and trust only hooks you intend to trust. Declining or skipping leaves TAP’s guard and SessionStart hooks inactive until trusted through Codex review. Installation does not pre-trust hooks; TAP’s courier does not choose for you.

Detach again, return to the asking pane, and ask it to check the original question’s status. Inspect the receiving seat before resending a task.

Mail while you type

In auto mode, TAP waits for an empty composer, including for urgent delivery. In bypass mode, a draft gets a grace period before TAP uses the input box; a red flash warns of the handoff. An interrupt may clear a draft, keeping the text TAP can capture. Pasting it back is conditional; when it does not happen, tap draft recovers it. OpenCode drafts always need tap draft, and pasted content or images may not be captured. Type WAIT in caps to hold deliveries for two minutes.

Queued follow-ups can also hold delivery. The command reference covers delivery and draft recovery.

5 / Stop and return

Leave the view

Ctrl-b, then d. Work continues.

Return to the view

tap attach <seat>

Stop after work finishes

tap team down

Run from the project. The roster remains.

Back after a stop

tap team up
tap attach <seat>

Check each resumed agent’s context before giving it more work.

Back after a reboot

tap team up --last

Previews the seats that were running and asks first. Seats you stopped on purpose stay stopped.

Bring an existing conversation into TAP

For Claude Code or Codex conversations. Use the same harness and project directory as the old conversation, and launch the seat with the picker flag:

tap launch claude writer --resume
# The seat opens the harness's own picker: pick the old conversation
# Ask the agent to run: tap whoami

TAP binds the picked conversation as the seat's identity when the harness's SessionStart runs (Codex: once its hooks are trusted), so a later tap session resume writer reopens it. If nothing binds, run !tap in from the seat. --resume=<id> resumes a known id directly. Other harnesses have no picker: launch them fresh, resume inside, then !tap in. The name proves the handle, not the conversation: before leaving the old conversation, have its agent print its id (echo $CLAUDE_CODE_SESSION_ID or echo $CODEX_THREAD_ID), then compare it with the seat's recorded id from the project directory:

jq -r '.seats["writer"].harness_session_id // empty' .tap/team-registry.json

They must match; an empty or different value means the binding is unverified and a later resume may open another conversation.

After the first answer

Give one agent a real task and ask another to review the change. The five levels of TAP shows what two seats can do and when to grow the team. To reuse an old conversation, follow the full guide.

TAP and tmux

TAP runs every seat inside tmux. First-run setup can install two optional integrations, removable and never touching your own lines: the lookup key (tap keybinding install, prefix C-g opens the teammate picker) and managed tmux defaults (tap tmux-defaults install). The defaults are one TAP-owned file plus a single marked source-file line inserted before your own ~/.tmux.conf settings, so your settings always win: true color, mouse on, 10 lines of scrollback per wheel notch, middle click leaves copy mode, focus events, 10,000 lines of history, and a clipboard that works (pbcopy on macOS, wl-copy/xclip on Linux, OSC 52 over SSH). tap tmux-defaults remove undoes it.

Shift+Enter types a newline

Run Claude Code’s /terminal-setup, or map Shift+Enter in your terminal. Ctrl+J works everywhere. Advanced: set -g extended-keys always forwards composer keys into tmux but can confuse older TUI programs.

One scrollback, not two

In iTerm2, leave mouse reporting on and set Scrollback in Alternate Screen to 0, so the wheel scrolls tmux instead of a competing buffer.

Copies reach only the tmux buffer

A stale SSH_CONNECTION in the session environment (from attaching over SSH once) makes Claude Code skip the local clipboard. Run tmux set-environment -t <session> -r SSH_CONNECTION, then restart the seats. Details: the full guide.
