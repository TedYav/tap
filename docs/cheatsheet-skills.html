Skills for you and your agents.

Skills you invoke

These are instructions you give an agent. The examples use native plugin names; ask your agent to load the named skill if its harness uses another spelling.

tap:help

Get started, or diagnose something that seems off. Getting started gets two harnesses exchanging a real reply, then chooses the next useful capability. Diagnosis starts from your symptom (mail not arriving, a stuck seat, copy or Shift+Enter not working, odd colors), runs checks that leave your setup alone, and changes nothing without your yes. Type it as /tap:help; bare /help is the harness's own help.

tap:config-wizard

Help you configure TAP, including advanced settings, presets, permissions and notifications.

tap:extend

Customize your installed TAP: a launch default, a new harness, a new command or any changed behavior. It tries your settings first, then changes TAP's source in your clone, and helps you keep or share the change.

tap:lead

Lead the team: choose a strategy, staff the work and ensure it gets an independent review.

tap:self

Run a supported command in its own harness, with the agent composing the argument. For example: “Your context is getting full; /tap:self compact.” Compact, rebrief, goal and loop support depends on the harness; the skill handles required handoffs. In Claude Code it can also switch the seat's model and effort after the reset, before it resumes work. clear is a deprecated alias of rebrief.

tap:collab

Work with one or more other agents on a task as equal collaborators, for example “Collab with reviewer and tester on X.” They agree who writes, challenges and decides, then use pair or discuss. With several peers, the agent you asked leads the group.

tap:pair

Pair program: one agent writes and the other independently reviews after each work turn, tied to the published unit or commit range. It also works for prose and research.

tap:adapt

Give a modern frontier agent permission to use its judgment to simplify a legacy skill or make it useful across TAP teams. It records the proposed changes and preserves authority boundaries. Interactive mode waits for your go; mode:agent applies the changes and records its decisions.

tap:escalate

Reach you out of band when it needs your decision, through your configured notifier. Notifier acceptance does not prove you saw the question.

tap:discuss

Discuss a plan, review or decision with one or more other agents using a defined protocol, and arrive at a recommendation. Exchanges are bounded and open issues are recorded.

For larger teams, you can also ask for these roles or workflows:

tap:crew

Bring in a short-lived consult or review seat when the conversation needs follow-up. Crew seats share the current tmux session; they are not parallel implementation writers.

tap:drive

Give an agent ownership of one implementation lane, including custody, commits, checks and closeout.

tap:conduct

Have an agent assist a leader with staffing, dispatch, review routing and escalation under the leader's charter.

tap:context

Ask an agent to choose the least disruptive context recovery at a safe task boundary: leave alone, compact, clear and rebrief, or restart. It preserves assignments and writer custody.

Agents may select these skills themselves when their assignment calls for them, except tap:help, which is meant for you to start. Claude Code and Codex hide it from agents entirely, so its onboarding and diagnosis text loads only when you ask. Some other harnesses ignore that setting and still list its one-line description to agents. Agents use tap help and tap:tap instead. This split tells you which skills are useful to ask for, not who is allowed to load a file.

Run a shell command directly

For a simple TAP command, use your harness's shell shortcut, such as !tap in, instead of the skill form (/tap in or /tap:in). It uses fewer tokens and is simpler. Use the skill when you want the agent to manage a lifecycle or make decisions.

Skills an agent invokes

You normally describe the work and let the agent use these helpers. send, assign, reply, outstanding and team are deliberately absent from the user slash menu; the rest also work when you type them.

tap:tap

Apply the shared messaging, liveness and tree-custody rules.

tap:in

Register or reconnect the current pane when its binding changes or is uncertain.

tap:out

Unregister a seat and free its handle, with a handoff when needed.

tap:team

Inspect the roster and choose a recipient.

tap:send

Send a note or a question; use assign for work orders.

tap:assign

Send a work order with a tracked reply obligation.

tap:reply

Answer an incoming request and settle it; a progress reply keeps unfinished work open.

tap:outstanding

Check sent messages that still await settlement before yielding.

tap:ask

Run one stateless harness question and print the answer, without a TAP seat or follow-up lifecycle.

tap:choreography

Coordinate readers, writers, review evidence and supervision.

tap:calibrate-gc

Consolidate old notes in the optional calibration store when tap calibrate suggests it. The store is off until you run tap config set calibration.enabled true.

Find the canonical instructions

Claude and Codex use native plugin names such as tap:lead. Other harnesses use flat names such as tap-lead; the all-seat entry is tap. To find the canonical file for your installed version, run:


tap help skill lead

Open the returned file before using the skill. Namespaced and flat names resolve there too. The native plugin exposes all 25 skills. Flat hosts start with tap, tap-in, tap-send, tap-escalate, tap-config-wizard, tap-help and tap-extend; the full-kit setting adds the rest. Skills guide agent behavior; TAP transports messages rather than enforcing a fixed workflow.

Your team can write its own role skills, such as a coach, monitor or context genie. See the five levels of TAP for roles and growing teams, or browse this reference as a web guide.
