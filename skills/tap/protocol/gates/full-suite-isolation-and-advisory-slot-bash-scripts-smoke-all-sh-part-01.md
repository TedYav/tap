## Full-suite isolation and advisory slot (`bash scripts/smoke-all.sh`)

**Unattended admission (tap-7r3fn.53).** Before allocating a sandbox or entering the slot, a full invocation requires either a TTY on stdin, stdout, or stderr, or literal `TAP_RUNNER_ALLOW=1`. Otherwise it exits 78 with the allowance remedy. Full invocations print their own PID and up to 32 ancestors (PID, PPID, executable name; no arguments). `--only` and help bypass this admission check, with argument validation still owned by the parser. CI and deliberate unattended callers supply the allowance; workers do not inherit it. The shared regress runner has the same admission rule.

**Interrupted worker waves (tap-7r3fn.53).** Session launch restores SIGINT and SIGQUIT defaults before spawning Bash, so asynchronous dispatch does not make worker INT traps inert. The public smoke entry forwards INT, TERM, and HUP to its recorded live child and waits for cleanup before removing its sandbox. The suite body exits 130, 143, and 129 respectively. Cancellation during asynchronous launch is deferred until the parent has captured its child PID. Cleanup signals that still-live child even before it has published a ledger, then reaps the recorded dispatcher session, including wrappers that have not yet registered a worker, then reaps recorded worker sessions and removes its private tmux sockets and paths. Existing completed-session and reused-leader exclusions still apply; no process-name matching authorizes a kill. This covers signals to the public smoke entry; it does not change the outer regress stamp/tee wrapper's signal handling. Controls: `runner-admission-signal.test.sh` and `wave-session-reap.test.sh`.

Each invocation owns a sandbox and one unique short tmux root under `/tmp`. Each worker mints private descendants for `HOME`, `TAP_INDEX_HOME`, `TAP_LOCK_DIR`, `TAP_SESSION_MANIFEST`, `OPENCODE_DB_PATH`, `TAP_VERSION_SEEN_PATH`, `TMUX_TMPDIR`, and `TMPDIR`; its `worker-roots` receipt names them. The index starts with an empty current-format marker and the three state files start absent. `TAP_LOCK_DIR` is the worker-private delivery lock root; the distinct `TAP_SUITE_LOCK_HOME` admission path remains machine-wide. The standalone sandbox pin carrier supplies a private lock root for unset or empty `TAP_LOCK_DIR`. `TAP_SUITE_SANDBOX` remains the run ownership root. Temporary fixtures use the short tmux tree because macOS limits Unix socket paths to 104 bytes. Setup failure records a file failure without executing its body. Workers start through `env -i`, with `TMUX`, `TMUX_PANE`, and `TAP_HOME` absent; this preserves busless shell controls and makes bare tmux calls use the private worker namespace. The shared PATH guard resolves the effective socket in tmux precedence order (`-S`/`-L`, then `TMUX`, then `TMUX_TMPDIR`), refuses paths outside the run root or at the platform floor, and writes a marker so captured stderr or a swallowed exit cannot hide the attempt. The precheck separately refuses literal operator-HOME resets and external socket names. Controls include `runtime/bun/test/smoke-worker-state.test.ts`, which runs eight components with identical state and session names and rejects a shared-HOME mutation.

The PATH guard is not process authority. A worker can actively reconstruct a clean environment and invoke the system tmux without it. Known `env -u TMUX_TMPDIR` and PATH-reconstruction source shapes are printed as notes, never treated as proof that the class is closed. Every smoke, regress, and `--only` wave snapshots the operator `~/.tap` file hashes and operator tmux session names before and after workers. A changed TAP tree is evaluated semantically: protected registry/lock deletion, wave-root or non-seat global-registry rows, wave-owned team-registry rows or locks, and unreadable changed state fail with attribution; unrelated operator registrations may pass. The suite slot's own lease (`locks/smoke-all.lease.json`) is exempt from the deletion arm by EXACT path match (tap-h37qp): `suite_slot.py` owns that path and clears it on every holding exit, while the lock home is shared machine-wide, so a peer suite finishing inside this run's window would otherwise be reported as this run's attributable violation. The match is exact rather than suffix because a peer can only ever own the canonical path; a nested path ending in the same name is this run's own doing and is still attributed. What the exemption gives up: a real sandbox escape deleting exactly that canonical path is no longer caught by this arm. The guard records the exact name supplied to every accepted private `new-session`, even when the worker later removes that private session. A new operator session with one of those names fails post-wave. A pre-existing operator session that disappears during the wave is temporal evidence only: it prints a note because the operator may have closed it independently. Post-wave failures are accounted separately from file failures in the terminal red receipt. These predicates detect attributable effects after execution, not read-only reach, so direct destructive real-tmux calls still require an explicit private socket. The runner's tmux shim also records every rejected call (tmux-escape) in a per-run marker as one line per call: file, effective socket, sandbox root, socket limit and argv, with backslash, tab, newline and carriage return escaped in each field and the space escaped in argv words. A file with a record is classed `tmux-escape` even when its test swallowed the shim's stderr, and its FAIL block replays up to five of those records inside `SMOKE-FAIL-BEGIN`/`END`; a marker that cannot be read reds the file rather than passing it (tap-l7qg1).

An obligation lock's non-minted key is a temporal note, not a wave attribution:
production durable notices and quarantine also use custom keys. Attribution still
requires a wave PID witness (held marker or content), or exact equality between a
canonical minted key's sender and a recorded wave handle. Do not infer senders from
custom-key prefixes or enumerate notice families. A custom fixture lock released
before observation, with no remaining actor witness, is therefore not attributable.

Held-marker attribution also resolves an uncensused live PID against the original
recorded worker session ids at the point of attribution. Those session ids are
preserved before the descendant census expands the PID ledger; a descendant that
later creates another session does not make that new session a wave root. A dead,
foreign-session or unobservable PID supplies no new attribution evidence. Since
attribution follows worker completion, a still-live recorded leader is PID reuse
and its session supplies no new evidence, matching cleanup's exclusion. This is
an observation only; cleanup and signaling authority are unchanged.

Registry snapshots retain the observed JSON bytes with their hash. Row attribution
compares those before/after observations and examines only added or modified team
or seat rows and changed top-level team-registry metadata fields. Unchanged
historical rows or metadata cannot be blamed for a concurrent operator registration. Changed malformed/unreadable registries and protected file deletions
still fail. Row removal alone does not identify a wave actor.

Kernel-lock handshake markers are also ephemeral (tap-gvwhp): `panelock.ts` `acquireKernelLockAt` creates them on grant and removes them on release. A deleted basename matching `*.lock.held.<pid>.<rand>` or the long-filename fallback `.held.<pid>.<rand>` prints a temporal note when its PID is outside the wave census. Matching uses the existing anchored suffix parser: decimal PID and one to eight lowercase base36 characters. The rule applies at every directory depth, including `locks/obligation-long`; redirected paths and wave-PID markers still fail. Permanent locks, malformed markers, and ordinary protected files retain deletion failures. This exception cannot distinguish a peer's normal release from an escaped deletion of exactly that peer's marker, so the latter is no longer detected by this arm.

Teardown enumerates sockets only beneath the recorded private tmux root, issues `kill-server` with explicit `-S`, and removes that exact root only after `lsof` reports no owner; it never uses an unqualified destructive call or a `/tmp` glob.

The machine-wide flock is now observational for ordinary FULL suites. The first full runner holds it and writes the lease; a contender prints holder/load context, continues, and reduces concurrency. **A one-file run (`--only`) neither observes nor acquires the slot (tap-h37qp).** The acquisition happens before argument parsing, so a focused run used to take a machine-wide lease it never needed and enter the same contention as a 350-second gate; a peer's ordinary lease release inside that window then fired the post-wave operator-state guard on whichever run was still going. `--only` is detected in the same pre-acquisition scan `--help` already uses — deliberately looser than the parser, which still owns validation, so a malformed `--only` skips the slot and is then refused: refusing an argument needs no machine-wide lease. `TAP_SUITE_SLOT_PROBE=1` is NOT exempted, so acquisition itself stays testable. `TAP_SUITE_SLOT_PROBE=1` remains acquire-or-refuse for controlled measurements, where `error_class=suite_slot_busy` is still an admission refusal rather than a checkout red. The permanent `.lock` file is not a busy signal; the lease names the observed holder, and the kernel releases flock on process death. `suite-slot-unlock.sh` refuses a live lease pid and clears stale sidecars only after it is gone. `TAP_SUITE_SLOT=bypass` is the loud disaster-recovery escape.

`smoke-all.sh --only <file>` runs one smoke through the same boundary and emits a `smoke-one` receipt, never the canonical gate token. The classic loop and direct `bash path/to/test.sh` bypass the runner; direct destructive real-tmux calls therefore still require an explicit private socket. Tests: `suite-env-hermeticity.test.sh`, `suite-tmux-isolation.test.sh`, `suite-name-receipt.test.sh`, and `suite-slot.test.sh`.

`smoke-all.sh --list <path>` runs a newline-separated list of repo-relative test paths through that same boundary, with a `smoke-selected` or `regress-selected` subset receipt. It retains unattended admission and advisory slot handling; unattended callers supply `TAP_RUNNER_ALLOW=1`. Selected files execute without a second unchanged-input carry decision, including serial files.

**Successful receipt identity (tap-jnoz).** The single terminal success line begins with the checkout receipt and reaches `ok` only afterward, so no canonical line prefix reaches the success token before identity. A clean checkout carries one captured `HEAD^{tree}` and `HEAD`; every later graph or path query uses that captured commit. A dirty checkout says `tested-tree=uncommitted` and `worktree=dirty` rather than attributing uncommitted inputs to the commit. A versioned checkout with an unreadable or moving `HEAD` says `unverified` / `git-observation=failed`, `head-unavailable` (the second `HEAD` read could not be taken) or `head-moved`; a copied runner with no Git metadata says `unversioned`.
