**Regression last-run stamp (tap-52ys).** `scripts/regress-all.sh` writes `.tap/regress-last-run.json` — `{at, head, exit}` — so "did this box ever run the regression suite" is a file rather than a memory; `--last-run` prints it. Nothing reads it automatically: the stamp is only this machine/run's queryable record. REGRESS can be invoked by an operator or the nonblocking daily GitHub Actions workflow, and a `tap doctor` warning would be the first step back toward it nagging like a gate. `.tap/` is gitignored wholesale, so the stamp is machine-local by construction, which is what its question needs.

The stamp is replaced **only by a run that executed files**, keyed on one of four terminal accountings: `— ok — all N files passed`, `N/M FAILED`, `— ledger mismatch —`, or `— STRADDLED —`. Exit status alone cannot separate a pre-run usage/preflight refusal from an authored red. A pre-run refusal leaves the prior stamp byte-identical. A straddled run stamps although it is a refusal, because it executed files and the stamp answers when this box last ran the suite, never whether the run passed — the same reason a red and a ledger mismatch stamp. The list is an ENUMERATION, so every shape added after it was written matches nothing and silently leaves the stamp claiming the previous, healthier run; that is the failure `— ledger mismatch —` was added to close, and `— STRADDLED —` is the second instance of it (tap-1f45b). Tests: `regress-stamp-guard.test.sh` (arms (a) through (e)).


**Proof receipts (tap-qqmwv).** A passing file's stdout is discarded with its log, so a mutation witness's proof would not reach the gate artifact. A file declares a retained proof with a column-0 line shaped `SMOKE-RECEIPT: <proof>`. Before worker logs are deleted, the runner copies exactly those lines, with their source file, under `=== SMOKE RECEIPT <relative-path> ===` into aggregate output, after any declared-skip blocks; `smoke-all.log` and the uploaded evidence directory carry them. Only passing files are ledgered: a failing file's complete log is already replayed in its FAIL block. Indented or mid-line mentions, unprefixed continuations and all other stdout are not retained, no census counts receipts, and the terminal summary and `declared-skips=K skip-files=M` format are unchanged. Receipt lines are not skip declarations and still pass the undeclared-skip scan, so a receipt that reads as skip prose fails the file. A failure to read a passing log for receipts fails closed as a skip-accounting error. It sits beside the SMOKE-SKIP accounting on the previous page. Tests: `suite-skip-accounting.test.sh` arm 9 (two files at `-j 2`, tab and vocabulary-shaped payloads, continuation, failing file, replay-dropped mutant); `ci-gate-verdict.test.sh` declares its restoration-mutant count as the first witness.
