The runner never fetches or mutates refs. When local `origin/main` resolves, the receipt names its one captured SHA and labels freshness `caller-owned`; the reviewer fetches before the run when current-remote comparison is required. `behind=0` means zero only against that printed local ref. A positive behind count always produces `BASE DRIFT`. A measured overlap is an unambiguous JSON-style array of Git path display tokens (`[]`, `["path"]`); a failed path observation says `overlap=unknown`, never an empty set. The intersection is prioritization evidence only, and the same clause reminds the reader that disjoint files may still interact. No local merge base and a merge-base command failure remain distinct observations. Base drift is advisory in v1: exit 0 means the identified checkout's suite passed, not that an untested future merge result was certified. Tests: `suite-tree-receipt.test.sh` (identity-first citation order, local/missing/diverged bases, dirty/unverified/unversioned states, unambiguous paths, and injected Git observation failures).

**Successful skip accounting (tap-5n6t).** Before worker logs are deleted, the runner recognizes only exact lines shaped `SMOKE-SKIP: <reason>`. A declared skip remains green and is copied into aggregate output under `=== DECLARED SKIP <relative-path> ===`; each marker contributes one event, while each emitting file contributes once to the terminal `declared-skips=K skip-files=M` census, even if that worker also fails. Checkout identity and this census both precede the first `ok`. An exit-zero file that instead emits singular skip-shaped prose (`skip`, `skipped`, or `skipping`) fails as `undeclared-skip` with its complete log and declaration remedy; normal success assertions ending `: ok` are not skip receipts. A malformed reserved marker and any failure to read or classify a passing log or retain its declared receipt fail closed as policy errors. The same accounting failure on an already-failed worker keeps that worker's original failure and makes the red census `declared-skips=unknown skip-files=unknown`; it never claims a numeric partial. The trailing pass count still records files, while the census records declared skip events rather than total arms or assertions. It does not detect repeated execution; `tap-dz9e` owns that separate signal. Tests: `suite-skip-accounting.test.sh` (declared, failed-declared, zero, undeclared, malformed-marker, and scanner-error real-runner fixtures) and `suite-tree-receipt.test.sh` (identity and zero accounting share the sole green).

**Canonical terminal receipt identity (tap-inhn).** Once discovery and preflight admit the suite, the runner captures one checkout receipt after all workers return. Capturing at that boundary keeps the receipt's mutation detector live across the worker window: a checkout dirtied or moved mid-run cannot produce a terminal verdict that names the pre-run clean tree. Every authored result after worker accounting places `known-defect: N; declared-skips=K skip-files=M` after that checkout receipt. Red-run declared-skip values cover completed worker logs; `known-defect` values cover every completed worker log, passing or failing, each counted once, and a red receipt labels the value as an all-files census, not failure attribution; a ledger-mismatch line also states that its file ledger is incomplete. The worker-failure summary, including its post-wave variant, reuses one captured value for both its stdout copy (beside the replayed failing-file logs) and stderr copy; the post-run ledger-mismatch summary and the identity-first green use the same snapshot. The green line's byte shape is unchanged. The red summary also names the failing files (tap-kg3fb) as `; failing: <files>` (capped at 20), mid-line before the `known-defect` census, because `ci-gate-verdict.py` and `regress-record.py` end-anchor the counts tail. These red receipts identify the checkout state observed after the failed run, but that identity does not establish that a failure is a branch regression rather than a flake, and red receipts from different trees are not comparable evidence about whether the same failure recurred. Tests: `suite-tree-receipt.test.sh` (ordinary-worker and ledger-mismatch accounting) and `suite-name-receipt.test.sh` (post-wave accounting).

The terminal-path inventory keeps refusals distinct from results. Help and the identity-first green are successful terminal paths. A **straddled** run (tap-1f45b) is a post-worker REFUSAL rather than an authored result: the runner pins the checkout after the suite slot is held and before the worker wave, compares it against the receipt's own head observation, and when they differ emits one `— STRADDLED —` line naming both checkouts, to stdout and stderr, exiting non-zero with no `ok` line and no red summary. Classifying it as a refusal is what keeps the authored-result rule above true without qualification, and it deliberately carries no known-defect or declared-skip accounting: those numbers are quoted later by readers who cannot tell that the head observation behind them was void. The comparison is HEAD-primary — for a clean checkout `tested-tree` is `HEAD^{tree}`, a function of HEAD — and the tree is compared only when the receipt observed a clean worktree, so a run whose own redirected output dirties the checkout is not reddened for a difference the receipt already reports as `dirty`. An unpinnable start — an unborn or orphan checkout, or one whose HEAD will not resolve — is an ENDPOINT STATE rather than an exemption (review finding): it agrees with a finish that is also unresolvable, which stays silent because two ends agreeing on "no commit" is the checkout this check has nothing to say about, and it refuses with `reason=unpinnable-start` against a finish that resolves, because a head appearing inside the worker window is a commit landing under the run. The receipt's own two head reads stay distinct: a second read that returns a different head refuses as `reason=moved-inside-receipt` (`git-observation=head-moved`), while a second read that cannot be taken at all refuses as `reason=receipt-head-unreadable` (`git-observation=head-unavailable`, or `failed` when the `status` between the reads failed) — the checkout could not be re-read, which is an observation failure and not an observed move, so its `— STRADDLED —` line says the run cannot show the checkout stayed put rather than claiming it moved. It detects a checkout that differs between suite start and receipt, and nothing weaker or wider: **moved-and-back**, **dirtied-and-cleaned**, and **receipt-versus-suite-source** stay uncovered, because two endpoint samples are not proof that the path between them was constant. It does not make freezing the tree redundant; detecting a mixture after the fact does not return the time the run spent building one. Tests: `suite-tree-receipt.test.sh` (red-3; red-5 for the unpinnable-start endpoint; red-6 for the receipt-head-unreadable and moved-inside-receipt reads, end to end through a `git` shim; and the bidirectional half asserting an unstraddled run never acquires the token). Entry prerequisites, argument validation, sandbox invariants, escape precheck, discovery, and interpreter preflight refuse before a complete worker ledger and carry no red receipt. A controlled probe's `error_class=suite_slot_busy` is likewise an admission refusal, never a checkout red. An exec failure, unset-variable abort, signal, or other abrupt infrastructure termination that prevents either canonical summary has no authored terminal verdict; a post-worker incomplete ledger receives the canonical ledger-mismatch receipt. Tests: `suite-tree-receipt.test.sh`.

**Two suites, one runner, distinct receipts (tap-52ys).** `scripts/smoke-all.sh` drives both suites; `TAP_SUITE_DIR` selects which (`smoke` = the smoke census and focused PR checks, `regress` = the optional operator-run suite, anything else is a usage error exiting 64). Shell membership follows `skills/*/scripts/smoke/*.test.sh` or `skills/*/scripts/regress/*.test.sh`; re-bucketing a shell file is a move, with no manifest to update. Smoke also discovers Bun files recursively under `runtime/bun`, including colocated source tests: names end in `.test`, `_test`, `.spec` or `_spec` followed by `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.mts`, `.cjs` or `.cts`. Discovery skips hidden directories and `node_modules`, does not follow directory symlinks, and refuses matching file symlinks, nonregular files and unsafe relative paths. Regress discovery stays shell-only. The full smoke census excludes the aggregate `skills/tap/scripts/smoke/bun-suite.test.sh` to avoid repeating its children; explicit selections may still run that adapter.

Each discovered Bun file runs through `runtime/bun/test/run.sh` in the same worker pool as shell files, with `runtime/bun` as cwd and `TAP_POC_REF_BIN` naming this checkout's Bash reference entry point. The Bun runner supplies private child state, overrides inherited `TAP_LOCK_DIR` with its own scratch lock root, and unconditionally sets `TAP_NOTIFY_USER_BIN=/nonexistent/tap-smoke-must-stub-notify-user`, including focused invocations: an unstubbed escalation fails instead of reaching the operator. Notifier tests may install their own stub inside the test. The runner ends with `run.sh: ran N files: ...`, the test entry files Bun loaded (resolve-only hook), and exits nonzero with `run.sh: no test files ran` when none did, even if Bun exited 0; Bun's own failing status is kept. Passing Bun rows gain the existing `: ok` suffix for skip accounting; failures remain unchanged. Controls: `runtime/bun/test/smoke-bun-pool.test.ts` and `runtime/bun/test/claude-live-guard.test.ts`.

`*-serial.test.sh` is a scheduling marker inside the selected suite bucket, not a third bucket or manifest entry. After one discovery pass, the runner finishes ordinary files at the configured concurrency, then runs the serial files through the same isolated worker and pass/fail/timing ledgers at concurrency 1. The guarantee is only no sibling workers from this runner invocation; it is not a quiet-machine promise and adds no lock, wait, retry, or scheduler.

A file in either partition may select unchanged-input carry by sourcing `scripts/serial-trigger.sh` and calling `tap_serial_triggers` before fallible setup with one or more literal repo-relative path prefixes. The runner computes the changed-path ledger once from `merge-base(origin/main, HEAD)..HEAD`; the helper implicitly includes `scripts/smoke-all.sh`, itself, and the test file. With no intersection it emits one retained `SMOKE-SKIP` naming the merge-base and effective triggers, then exits zero immediately. `--only`, missing or failed Git/origin/base observation, a dirty or untracked tree, `HEAD == merge-base`, or a malformed declaration (no triggers, or a trigger that is empty, absolute, has leading or trailing whitespace or a `//`, or contains a `.` or `..` segment) fails open to RUN. There is no glob DSL.

Every terminal line is prefixed with the execution class: `smoke-all`, `regress-all`, `smoke-one`, `regress-one`, `smoke-selected`, or `regress-selected`. Only `smoke-all` identifies a full smoke census; full runs belong to nightwatch, while focused checks are on the PR merge path. `TAP_SUITE_DIR` crosses the entry allowlist, and `--only` validates that its one path belongs to the selected suite membership above. `--list` accepts the same membership (mixed shell/Bun for smoke), requires ordinary files, rejects empty lists, duplicate paths and combination with `--only`, prints each selected path with `rule=explicit-list`, and forces scope-state `run`. A subset receipt cannot replace a full-suite receipt or the full regress last-run stamp. Tests: `suite-name-receipt.test.sh`, `runtime/bun/test/smoke-selection.test.ts`, and `runtime/bun/test/smoke-bun-pool.test.ts`.
