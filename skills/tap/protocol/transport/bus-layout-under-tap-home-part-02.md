- **`payloads/` holds only canonical, courier-written payloads.** `tap send` and `tap command`'s auto-settled audit writer are the **only processes that write to `payloads/`** (spool redelivery / digest drain only *move* a previously placed spool copy back into `payloads/`). `tap send` uses `canonicalPlaceLocked` (runtime/bun/src/courier.ts) under the custody it already holds; `tap command` privately prepares its possible immutable audit envelopes and receipts before pane input. Both paths stamp and validate under `$TAP_HOME/tmp/` on the same filesystem, then atomically rename only the selected canonical envelope into `payloads/<id>.md`. A half-written, zero-byte, validation-failed, or unselected audit outcome never appears in `payloads/`. Draft or input source files belong elsewhere; never write directly into `payloads/`. `_*.md` names are reserved for drafts/private and are **ignored by `tap poll`** — a defensive guard so an id-less draft accidentally dropped in `payloads/` can't jam a peer's inbox (the F9/PLACEHOLDER footgun class).
- **Courier attribution is place-time (tap-ejpf).** Every successful rename into `payloads/` by `canonicalPlaceLocked` (and `tap command`'s audit commit, which bypasses that helper) writes `receipts/<id>.placed`. That mark is the authority for "this file is courier mail," including exit-5 submit-unverified paths that deliberately omit `.sent`. A payload with neither `.placed` nor legacy `.sent` is still listed by `tap poll` (LABEL, never hide) as `provenance=unattributed`; `tap doctor` reports the set as a warning that does not flip bus-integrity `ok`. Unsanctioned `reply:` values outside `expected|settle-only` are likewise labeled on read — poll refuses to emit a protocol next-step that invents a verb; doctor warns. Forged id timestamps are out of scope (same-human bus; well-formed fakes are trivial).
- **Settlement is recipient-gated.** `tap read <id> --by <me>` settles a note only under the recipient authority checks below; `tap reply` settles an ask through its private primitive; a confused agent cannot settle a peer's item. The `.done` records the actor + an optional `--epoch` so `/tap:discuss`'s seal predicate can reject a zombie's stale-epoch ack (D4). TAP itself never interprets the epoch — it records what it is told.
- **Settlement records provenance.** New recipient settlement receipts carry `via: read|reply`. Historical `via: done|courier-auto` receipts remain readable and are never rewritten; the courier no longer creates `.done`, including when recovering old autosettle entries. These legacy receipts attest only what the older writer recorded, not recipient processing. A note read writes `via: read` and no reply fields; the retired public `done` tombstone writes no receipt. `tap reply` writes `via: reply` plus `reply_id` (the outbound id), `reply_sha256` (SHA-256 of the exact durable outbound body bytes after the closing frontmatter fence, including any final newline), and `reply_preview` (that body decoded as UTF-8 with replacement, non-printable characters replaced by spaces, whitespace collapsed, then capped at 160 characters). The receipt never stores the full reply body. A `.done` from `tap read` or `tap reply` also carries `instance`: the settling seat's current instance in the selected registry, or the explicit `unresolved` when that registry supplies none. It is read from the registry and compared with the envelope's `recipient_instance`, never copied from it, so a matching settle and a same-handle predecessor-bound settle (which still writes, with `reason: instance_retired`) differ by `instance`. An adopted predecessor's settle keeps `adopted_from` beside the successor's `instance`. The refuse-vs-write policy is unchanged. Evidence is derived from the outbound file on the bus only after `tap send` reports a durable exit 0 or validated exit 5; it is never derived from `tap reply`'s in-process message/source variables. For `0/queued, delivery=spool`, correlation requires the courier-owned `spool/<id>.md` plus its matching metadata sidecar and validates the envelope's canonical destination; a concurrent spool-to-canonical move is followed exactly. Other accepted outcomes correlate against canonical `payloads/<id>.md`. The transport validates id/path and `in_reply_to` before settlement; semantic comparison of reply content belongs to the sender.
- **Settlement replay is a hard error, with one named carve-out.** If `.done` already exists, `tap reply` exits `1` with `error_class=already_settled`, reports the original receipt time, and lists the actor's currently open inbound ids on that bus. A stale id therefore cannot look like a successful settle while newer obligations remain untouched. **The carve-out: `tap reply` on a payload whose receipt is `via: courier-auto` DELIVERS the answer instead of refusing**, and attempts no second settlement (the receipt keeps its original `courier-auto` provenance). The seat never ran a settle verb, so refusing would close the problem-report door — §Reply expectation's "reply only to report a problem" — with a mechanism the seat never invoked. `tap done` on the same id refuses as retired (exit 1, `done_retired`) and settles nothing.
- **A terminal receipt closes the obligation.** `tap_is_done` recognizes `.done` or `.cancelled`; pending scans also exclude superseded `.resent` originals, and a `.read` observation alone never settles an ask.
- **Overdue age has one clock at both ends.** Sender-side `tap outstanding --stale <secs>` and the recipient's dispatcher warning both compute inclusive age (`age >= threshold`) from the original UTC timestamp embedded by the courier's id minter (`mintId`, `runtime/bun/src/ids.ts`); payload mtime, redelivery, spool movement, and other bus activity never reset it. A future-stamped id (clock drift / hand-mint) clamps to age 0 and emits a `future-stamped` stderr warning rather than a negative age that silently escapes every threshold (tap-56ig).
- **No `.started`.** No `.done: deferred` body convention. A deferred item remains pending while no terminal receipt exists and the receive-authority gates still admit it; `tap poll` lists that eligible mail. If re-list noise bites, AESOP (not TAP) owns a parked-set.
- **All writes are atomic** (`tap_atomic_write`: temp + rename). A `.done` receipt is immutable after its first write; reply settlement replays refuse except for the named courier-auto reply door, while repeat `read` leaves it unchanged. Native-runtime payload staging and atomic receipt temps are created mode `0600`, so Bun-produced `payloads/<id>.md`, `.placed`, `.sent`, and `.done` artifacts stay owner-only regardless of ambient umask. Phase 1 has no native `.attempts` writer; any future one inherits the same owner-only requirement.

### Repository ignore rule and the missing-local-team onboarding preflight (v0.23)

**`tap init` keeps ignore policy at the root it anchors.** Inside a git worktree, after resolving
`ROOT` from `git rev-parse --show-toplevel` (a linked worktree resolves to its own root), init
appends `.tap/` to `<ROOT>/.gitignore` unless `git check-ignore --no-index .tap/` already reports a
covering rule. The write is append-only and byte-preserving: existing content is never rewritten, a
separator newline is added only when the file does not already end in one, and CRLF is used when the
existing bytes contain it. The file is opened `O_NOFOLLOW` and refused when it is not an ordinary
unshared file, so a symlink or hard-linked `.gitignore` is never followed or amended. Failure is the
named `gitignore_failed` refusal (exit 1) telling the caller to fix the repository ignore rules and rerun.
Outside a git worktree init skips the write and keeps its existing not-inside-a-git-worktree
warning. This is the **Git-root** rule; the `.tap/.gitignore` that self-ignores `.tap/bus/`
(§Bus layout) is a different file and is unchanged.

**The preflight runs before any command effect.** A local command issued where no local team exists
offers to create one — ahead of `route()` in the native entry point, so no bus directory, body
read, or registry write can precede consent. `TAP_ONBOARDING_CHECKED=1` marks the check performed,
so it fires once per invocation rather than once per hop when the router hands the `init` leaf the
command. Bun is an installed prerequisite: without it `bin/tap` refuses every verb with the Bun
install command and `./install.sh`, so no verb runs without the preflight.
