| `registry_invalid` | `register`, `init`, `admin`, `attach`, `attach --next`, `peek` | Registry/index JSON could not be safely read or updated (`admin`: the marker-selected machine index — the dashboard’s exit-1 cannot-check case). | `old_store` | every verb that selects, binds or reads a team registry (native: `register`, `in`, `send --remote-registry`, `team doctor`, `team reset`, `session list`, `session complete`, resume; Python: `session new`/`restart`, `clear`, the relaunch worker, the cross-team pane lookup); `admin migrate-registry` | A store is in an old TAP format; nothing is written, exit 1. A team registry is current only as `schema: "0.20"` with a `seats` object, no `agents` key, and `team`, when present, an object; an existing `{}` is old, an absent file is not. Machine-wide scanners (`admin`, `admin refresh`, `doctor`, `teams`, the attach picker, relaunch) keep scanning and report the team in its own `old_store` row; `admin` and `admin refresh` exit 1, and `doctor` reports an error finding without changing its torn-state exit. Detail: `<path> is an old TAP registry format (<reason>); <what this TAP reads> and never converts old files`. The action depends on the store: an agents-axis or bus team registry is upgraded by hand (rename `agents` to `seats`, add `"schema": "0.20"`) or moved aside before `tap init`; a pre-v0.20 `teams.json` machine index is moved aside, then `tap init` enrolls each team root; a launcher `sessions.json` manifest is moved aside (or `TAP_SESSION_MANIFEST` unset) and the needed seats relaunched.
