- `health --json` → object with `status`, `attention`, `unsettled`, `roster`, `watch`, `supervision`, and `events`; exit `0` when healthy, `2` when attention is needed.
- `admin dashboard --json` → `{teams, attention, cannot_check}` (§Admin namespace); a malformed machine index is an ordinary `{"ok":false,"error_class":"registry_invalid",...}` failure, not a report shape.
- `admin refresh --json` → `{ok, dry_run, trimmed, retire_candidates, cannot_check}` (§Admin namespace).
- `admin retire --json` → `{ok, team, root, forced}` on success.
- `admin rebuild-registry --json` → `{ok, dry_run, planned, applied}` on full success, with optional `preserved` diagnostics for observed poll/suspended rows; when any enrolled team is skipped for unreachable/invalid acting authority → one document `{ok: false, dry_run, planned, applied, skipped, skipped_reason}` and exit `1` (not a second error-object) — §Admin namespace.
- `doctor --json` → `{ok, bus:{home,rule}, findings[], summary:{torn, clean}}`; each finding is `{severity, name, detail}` with a stable `name` (e.g. `torn_payload`, `external_path`, `stuck_spool`, `spool`, `spool_orphan_meta`, `input_backup`, `input_backup_pruned`, `input_backup_malformed`, `watch_log`, `watch_log_pruned`, `watch_log_malformed`, `registry_no_team`, `registry_legacy_entry`, `suspended_agent`, `registry_unreadable`, `no_registry`, `codex_seat_node_unresolvable`, `codex_seat_pane_name_drift`). Bus authority failures, including `old_store`, and `torn_payload` set `ok:false`, `summary.clean:false` and exit `1`; other informational findings do not change the exit code. The human bus header is printed on stdout; stdout is the single JSON object. `codex_seat_node_unresolvable` probes each active codex seat's process environment and warns when `node` is unresolvable on that seat's PATH (TAP's own hooks run on bun and bash; the warning protects third-party Codex plugin hooks that call bare `node`, which would exit 127); `codex_seat_pane_name_drift` reports when the stored pane id disagrees with the pane id observed at that row's exact session name and stored address. The name-derived check is read-only and absence/unobservable evidence produces no drift claim; non-codex, suspended, and poll-mode rows are skipped.
Doctor keeps bus integrity separate from seat health: `summary.seat_attention` counts distinct handles with warning findings; `ok`, `summary.clean` and the exit code keep their bus-integrity meaning. `seat_unavailable` names stored-active seats observed gone/offline; `seat_binding_missing` reports an unresolved pane binding without declaring the seat dead. Their `detail` includes handle, observed status, reason and next action. Suspended durable seats use the launcher resumability predicate for named-resume advice. Unknown probes and foreign socket observations do not establish absence. Sessions discovered on alternate sockets suppress unavailable-seat recovery for their matching handles, including legacy rows without a recorded socket and sessions beyond the display sample. The same evidence replaces suspended-seat and retained-failure recovery with the matching socket export. Simple crew recovery uses `tap team refresh` followed by `tap crew add` with the recorded preset or an explicit model and the recorded cwd; absent model metadata requires a model placeholder. Explicit env/options without a preset or permissions differing from the current harness policy require manual recovery: point to the stored registry recipe and crew help before removing the row, without printing environment values. It never recommends durable registration. Cursor rows with a stored chat id use the launcher artifact check with the recorded workdir and environment, falling back to the selected team root rather than the caller cwd: a missing store recommends an explicit fresh launch rather than a refused resume. The age-based `tmux_server_stale` finding is replaced by one informational `tmux_other_servers` finding with `detail:{count,sockets:[{pid,socket,age_seconds}]}`. Normal human output summarizes it; `tap --verbose doctor` and JSON expose the inventory. Socket age is not a health verdict. Normal doctor remains read-only.

- `init --json` → `{ok, team:{name, root}, bus, in_git, already_initialized, migrated, primary_counts, late, late_counts}`; init no longer migrates, so `migrated` is always `false` and the three migration fields are `false`/`null`. Refusals are ordinary failure objects with no success object: `old_store`, `unenrolled_seats`, `confirmation_required`, `git_unobservable`, `invalid_team_name`, `team_name_conflict`, `invalid_flip`. The non-git `--yes` warning stays on stderr.
- `peek --json` → `{ok, handle, pane, harness, input_state, transcript}`; `input_state` is `empty`|`unsubmitted-sentinel`|`other-text`, and `transcript` is a single JSON-escaped string (the pane tail with the active input region stripped). Ordinary failures (`unregistered`, `pane_gone`, usage) follow the structured-failure contract under `--json`.
- `session list --json` → `{ok, sessions[], count, scope}`; each session has `name`, `harness`, `cwd`, `live` (bool: at least one pane in any session window has `pane_dead=0`), `seated` (bool), `restorable` (bool), `revive` (tier word: `exact`, `picker`, `latest`, `fresh`, `-`, or `stale` for a Cursor seat that is neither resumable nor attachable — its stored chat id has no conversation store, the same refusal `session resume` gives; a present non-shell tmux session counts as attachable and keeps its stored-id tier), `model`, `tag`, `handle` (the CANONICAL roster handle from `session_handle()` — tag plus index where index>1, falling back to a name-derived handle only when the record carries no tag; consumers must READ this rather than re-derive one, since neither `name` nor `tag` alone reproduces it for a noncanonical session name or an index>1 seat), `last_seen`, `last_launched` (null when absent), and optional `preset:{name,source_path,config_digest}`. `scope` is `cwd` or `machine`. Retained all-dead sessions have `live=false` and are excluded by `--live`; ordinary listings and tmux completion names retain them. Such sessions are candidates for deliberate ghost cleanup, while mixed live/dead sessions remain live. The listing itself never reaps a pane or deletes history.
- `session repair --json` → `{ok, repaired[], failures[], dry_run}`; each repaired entry has `name`, `harness`, `handle`, `status` (one of: `already_current`, `repaired`, `would_repair`, `not_registered`, `pending_mismatch`, `user_removed`, `pane_mismatch`, `non_agent_pane`, `pane_owned`, `not_live`), and `dry_run`.
- Session dry-run (`--dry-run`): bare `--dry-run` renders human prose (`tap session: would launch <name> (<harness>) in <cwd>`); `--dry-run --json` emits compact JSON (`{name, harness, cwd, env, argv}`) plus optional `preset:{name,source_path,config_digest}` when preset provenance exists. Launch `--dry-run` skips pre-mint, so a fresh Cursor argv will not include `--resume` even after tap-rs1q; a fresh OpenCode row likewise carries neither `--session` nor `--continue` until its plugin captures the running TUI's id. `tap clear --dry-run` still mints and shows the Cursor flag. OpenCode resume and restart dry-runs show `--session <captured-id>` when the row has one; an id-less row shows a fresh bare argv and one stderr notice. `resume --all` continues past either OpenCode shape. Other `resume --all` and `restart` invocations under `--json` emit one JSON object per record on stdout with no prose contamination; bare `resume --all --dry-run` emits the invocation receipt, a durable `[n/N] would resume <name>` line per record, and a final total. An empty `resume --all --dry-run --json` (no stopped sessions) emits a single envelope object `{"ok":true,"sessions":[],"count":0,"scope":"cwd"}` rather than NDJSON — the empty-vs-non-empty shape asymmetry is intentional (envelope for zero, NDJSON for N>0).
- **ok envelope rule:** new JSON surfaces (added Wave 5a+) carry a top-level `"ok": true` on success; existing JSON shapes (send, poll, outstanding, team, register, health, admin) are never retrofitted — their shapes are stable contracts.


Launch syntax refusals (`tap launch` and `tap session launch`) use exit 2 and the
standard error object under `--json` or inherited `TAP_JSON=1`, with empty stderr.
Human syntax refusals are one stderr line, `tap launch: <cause>; next: tap launch
--help`, with empty stdout. The same parser validates before onboarding, so a
fresh unenrolled directory cannot hide a syntax error or create enrollment as a
side effect. Missing values and extra positional arguments do not print legacy
`session new` usage blocks or arbitrary operand text. TAP help precedence,
value ownership, and explicit/implicit harness tails remain unchanged.
