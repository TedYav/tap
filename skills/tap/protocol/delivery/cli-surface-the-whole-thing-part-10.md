The native Bun adapter runs TAP's pinned private fzf executable. Type to fuzzy
search, use arrows to navigate, and Enter to select. Escape cancels without an
attach; Ctrl-C exits 130. The adapter ignores user fzf option/config environment,
passes stable opaque IDs separately from display labels, and checks returned IDs
against the offered candidates. It never downloads a tool at command time or
falls back to fzf on PATH. The installer verifies the platform archive and
executable, retains licenses, and records exact owned files for uninstall.
Filtering never changes registry data or bypasses the final attach identity check.

Team attachment uses the selected seats' recorded tmux socket for catalog reads,
client probes, viewer commands, and manual fallback commands. A selection spanning
multiple sockets refuses before opening viewers; narrow it with `--only` or
`--except`. Verification requires a distinct new client for each planned viewer,
including when multiple selected rows share one session.

```text
<h,...>]   # stop this team's verified tmux sessions and suspend their seats (status_reason=session_stopped); acting registry and bus are retained; poll seats retained unchanged; unverified pane rows refuse rather than invent a kill target; teammates first, self last; pair with tap team up
tap team up [<team>] [--dry-run] [--json | --attach [--tabs]] [--except|--only <h,...>]   # relaunch this team's stopped relaunchable seats through session resume --all, up to 4 at a time; a named <team> resumes from that team's enrolled root; --attach then opens viewers onto exactly the seats that came up (tap team attach's viewer)
tap team refresh [--hard] [--dry-run] [--json]   # one pass: rebind positively observed unbound durable rows through tap register, retain relaunchable/ambiguous durable rows, and collect proven-gone or ephemeral residue; --dry-run reports rebind-ready; --hard's earlier parked-row lifecycle cut wins and never rebinds
tap team shutdown [<team>] [--dry-run] [--yes|--force] [--keep-self] [--json] [--except|--only <h,...>]   # end verified team tmux sessions, then delete the acting registry (requires tap init); the bus remains; stops teammates first and self last; warns without blocking on unprocessed inbound; --yes/--force are compatibility no-ops; --keep-self spares the caller session and retains spared seats in-file instead of deleting
# down, shutdown and up take an optional enrolled <team>, resolved through the machine index exactly as `tap team roster <team>` (never cwd); bare, each means this team. Dry-run previews the named team's targets; selectors name its seats. A caller whose pane is not a seat of the named team never has its own session stopped, even when a named row shares it. Unknown, retired and unreachable names refuse with the roster's error classes (tap-lg1a5).
tap team purge <archive> [--dry-run] [--yes]   # delete one exact durable bus reset archive; preview is non-mutating, real deletion prompts on TTY and refuses non-interactively without --yes

tap doctor [--prune-input-backups] [--prune-watch-logs] [--fix] [--json]   # bus-integrity report: torn payloads (exit 1), registry health including aggregate unbound seats and dangling v0.20 team-index rows + backup metadata + checkout freshness (warnings). The doctor's body writes nothing without --fix (the ordinary dispatcher prologue may still invalidate a changed server generation); --fix prunes root-missing index rows through the locked de-enrollment writer, then execs the routed tap team refresh and renders that receipt. NO content scanning. Prune flags remove their reviewed local artifacts and are not combined with --fix
tap presets [--json]   # read-only list of the launchable preset catalog at ${XDG_CONFIG_HOME:-$HOME/.config}/tap/config.toml, rendered PRESET | HARNESS | FAMILY | MODEL | ROLES | DESCRIPTION. FAMILY is vendor lineage: `metadata.model_family`, else the single vendor a claude, codex or agy harness implies, else `-`; never derived from the model or the notes-bridge `family` key. ROLES is `metadata.primary_roles` — the same field `tap team --json` metadata publishes, so one preset reads identically on both machine surfaces — and DESCRIPTION is the catalog's short `description`; `metadata.summary` is long prose and is NEVER substituted for a missing description, or the column stops being a column. DEGRADES RATHER THAN ERRORS: an unreadable, malformed, or insecure catalog prints a stderr notice naming the failed path plus repair advice, and exits 0 — the same policy `tap session launch` applies to `[harness.*]`, and the load-bearing property here, because an operator asks what they can launch exactly when the config is what is wrong. An absent or empty catalog prints a neutral no-saved-presets notice naming its source (or `config.toml` when absent), the bare example `tap launch claude newcomer`, and optional `tap setup --machine` guidance. `--json` is the stable machine surface `{"ok": true, "source": <path|null>, "presets": [{name, harness, family, model, description, roles}, ...]}`, where a null source distinguishes "no catalog readable" from a catalog holding zero presets, and sparse presets carry empty strings rather than absent keys, except `family`, which is null when absent. Runs in Bun on the SAME resolved catalog `tap session launch` reads — not a second reader over the same file, which is what it was. A listed row IS a preset the launcher resolved, so discovery cannot advertise what launch refuses and cannot hide what launch accepts; both directions were live. A catalog whose `version` is retired reads no presets, so it lists none, and `retired` follows the incumbent's `version == 1` rather than an identity test — `1`, `1.0` and `true` are all retired, and a discovery check that read only `1` listed presets `launch` then refused with `preset_not_found`. A `family` is blank by Python's `str.isspace`, which does not contain U+FEFF, so a preset padded with it stays listed and launchable; a JS-trimming discovery check dropped it. DESCRIPTION is stripped for the cell by the same rule (`str.strip()`, not `trim()`), and the stored value is untouched. The degradation notice is ONE operator sentence: it names the file that actually failed — the legacy `presets.toml` when that is the file the loader reached and could not read, never a reconstructed `config.toml` path — says `invalid preset config` exactly once, and carries no machine `error_class` token. An ABSENT catalog uses the neutral empty state without permission-repair advice. Per-section legacy fallback is the launcher reader's, shared rather than owned here. The Bash adapter invokes the same native implementation; never writes

tap team reset [--dry-run] [--yes] [--allow-nonstandard-bus-path] [--kill-self] [--json]   # fenced copy-verify-cut team checkpoint under archive/team-reset/<bundle>/; leaves a blank acting registry (reboot); stops verified non-caller sessions without a confirmation gate; --yes is a compatibility no-op; --force refuses; path-shape override is --allow-nonstandard-bus-path; --keep-registry removed (use tap team down)
tap team restore [--archive <id|path>] [--dry-run] [--again] [--json]   # restore a COMPLETE team-reset checkpoint onto a pristine generation; state only, rows suspended; --again bypasses only the already-restored check
tap init [--json] [--yes] [--team <name>]   # create or recreate the blank acting team registry (+ bus layout); a new team is named after the folder, or a derived slug when the folder name is outside the team-name rule, or --team <name>; adds .tap/ to the Git-root .gitignore when no rule covers it; pane-less / TMUX-unset safe; refuses old_store for a legacy-only bus; never migrates; distinct from tap in (seat bind)
tap reset   # compatibility tombstone: use tap team reset (exit 1, error_class=renamed_verb)
tap admin [dashboard] [--json] [--full] [--stale-after <secs>]   # machine-wide read-only sweep over the team index: per-team classification (active/dormant/dangling) + pre-triaged attention[]; exit 0 reported (attention rows included) / 1 cannot-check

tap admin refresh [--dry-run] [--json]   # machine-wide seat-trim: delete only exact-name GONE seats, purge data-gone index rows, and report retire_candidates[]; live-team de-enrollment remains retire-only; exit 0 clean / 1 cannot-check

tap admin rebuild-registry [--yes] [--json]   # bare preview of live-pane recovery; --yes atomically upserts only pane-observed rows and never prunes poll/gone-pane provenance
tap admin migrate-registry   # removed-verb stub for one release: always old_store, exit 1; TAP never converts old registries
tap admin prune   # tombstone: renamed to tap admin refresh + tap admin retire <team> (exit 1, error_class=renamed_verb)
```

Team reset and restore execute in Bun through every entry point. Reset calls the existing native stop engine in-process, with registry policy `none` and caller retention until the checkpoint commits. A COMPLETE checkpoint is published after the copy and inventory persist; only then may reset cut live components. A failed cut retains the checkpoint and reset fence for retry.

All `tap team` forms, plus per-handle `tap teardown` and `tap restore`, now enter Bun through either runtime selector. Named team discovery uses the shared native roster. Team up validates selections and passes the positive only-set to launcher, which applies it against actual resume candidates. Team purge executes in `runtime/bun/src/team/purge.ts`, with the archive root fixed by team context and native exact-target validation, scratch protection, and confirmation. Detach holds registry custody through its late co-tenant check and client detach; it neither removes rows nor stops sessions.
