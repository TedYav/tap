**A pane effect requires an AUTHORIZED `TAP_HOME` (tap-ncd4).** `TAP_HOME` redirects only the spool/canonical paths a drain reads and writes — `pane`, `pane_id`, and `target_registry` are plain arguments, stored verbatim in a park's metadata, and are untouched by that redirect. A caller holding real, stored specimen values (pane/pane_id/target_registry from a live park) while `TAP_HOME` points at a bus nobody ever bootstrapped — the shape that let a probe of this exact path inject into a live pane, rc=0, no warning — is refused. The authority signal is a durable marker, `$TAP_HOME/.tap-bus-authority`, written once by `Bus.ensureDirs` — the function every real bus (canonical-shaped or an arbitrary supported custom home alike, per the resolution rules above) passes through before its first write. A production bus is stamped for free the moment any real `tap` verb touches it; a bare directory nobody ever ran `tap` against carries no marker. The native drain (at its own entry, before Phase A ever probes a pane), redelivery, and digest injection each check this marker and return 1 without touching a pane if it is absent. **Rejected: a `TAP_HOME` path-shape check** (`<root>/.tap/bus` / legacy `<root>/tmp/tap`) — decorrelated review broke it in both directions: it is trivially spoofed by naming a sandbox `.../.tap/bus`, and it wrongly refuses the arbitrary-custom-home layout this same section already permits, which would make the escape hatch below the thing every genuine custom-home deployment has to set — exactly the incident class this guard exists to prevent. Ceiling, stated honestly: the marker is an intent gate, not a provenance proof — a caller who reads this section can `touch` the marker or set the override just as easily as a real bus earns it; what it buys is that genuine use never has to. A caller that deliberately wants live injection out of an unstamped `TAP_HOME` (a hermetic fixture faking `tmux` on `PATH` that never calls `Bus.ensureDirs`, for instance — most fixtures should just call it) sets `TAP_SPOOL_PANE_EFFECTS_UNSTAMPED_HOME_OK=1` to say so explicitly. **Considered and not taken:** deprecating the arbitrary-custom-home layout entirely would remove the ambiguity this marker exists to resolve, but that is a protocol ruling on the bus-layout resolution order above, not a call this guard gets to make unilaterally — named here as the standing alternative if custom homes are ever retired.

If redelivery crashes after moving the payload canonical but before removing its sidecars, the live claim remains the short-lived ownership fence: a watcher must not treat canonical visibility as delivery while submit verification can still fail and re-spool. The watcher takes that same per-entry claim as an observation lock before deciding canonical/spool/settled state, closing the claim-check/canonical-check TOCTOU rather than layering a second lock protocol. Once a drain claim is stale or gone, canonical `payloads/<id>.md` is authoritative: the orphan metadata/claim are reconciled without another injection, and a watcher tracking that id starts its response clock from the canonical observation rather than waiting forever on stale sidecars. Every destroyer of a claim (steal, reap, release, resend) runs under one spool-wide leaf mutex, `spool/.claim.lock`, and unlinks only the claim identity (dev, ino, mtime) it judged stale, so a successor created after that judgment is never removed; creation stays an unlocked exclusive create. A destroyer that cannot take the mutex within its bound (up to 1 s for steal and release, since the lock primitive rounds waits up to whole seconds; zero for reap) leaves the claim (steal reports it held; release lets it age to stale). A claim body carries a random `nonce` and `claimAcquire` returns it as the holder's token; release unlinks, under the same mutex, only a claim whose nonce matches, so a slow holder whose claim was stolen cannot remove the stealer's (a legacy claim without one is never released by a token and ages out). A lock taken through `acquireFlock`/`acquireFlockAsync` (the pane, registry, index and spool locks) is a claim on an inode: after the grant, the descriptor's dev and ino (compared as BigInts) are checked against the file now at the path (lstat when the open refused symlinks, so a path swapped to a symlink fails the check) and, if it was unlinked or replaced in between, the grant is dropped and the current file locked, so no two holders lock different files under one name; a bounded wait gives up after 16 such retakes, an unbounded one (`Infinity`) keeps following the path until the successor is stable. `digest-window.ts`'s own `acquireNoFollowLock` (an `O_EXLOCK` open on macOS, `/usr/bin/flock` on Linux) is not one of these callers and does no recheck. A sidecar lock file is unlinked only while held (tap-yyu28).

Native single and digest redelivery call the shared courier submit owner and applies its receipt, removal or repark disposition in the same process before diagnostics can start a child. Missing result evidence never permits retry. The shared first-effect attempt writer holds reset custody only for admission and releases it before the key. A staged wire is submitted without retyping; an evidenced zero-Enter re-probe requires that exact wire. Draft clearing retains the shared backup pipeline, recipient-client notice and guarded short-draft restore. Digest admission checks every member before minting any marker, under one reset-custody span. All markers must exist before the first key; partial markers after an I/O failure or crash remain conservative evidence and never permit replay.

No-input-prompt defers remain spoolable only for harnesses without a safe queue prefix. Hermes default sends use `/queue ` and do not spool for that reason. Stuck copy-mode is retryable and queues; once escalated past its deadline, `tap nudge <to>` requeues it on proof of no effect ([nudge](./nudge.md#stuck-sentinel-recovery)); dead panes remain exit 3; terminal safety failures exit 1 without artifacts. A `--polite` send bypasses the readiness question entirely (see §Delivery policies) — it always parks after the denylist/pane-validity safety gate passes, without canceling copy-mode (tap-lek8), regardless of harness.

**Visibility (U15).** `tap outstanding <me>` reports spooled sends `from == me` WITHOUT draining — a ready-but-undelivered entry stays listed, surfaced, not advanced. The spool loop applies the same settled test as the payload loop and the drain's own settled-reap (`tap_is_done`): a settled-but-still-parked entry is not listed, so no delivery action by `tap outstanding` is needed for a row to clear. Delivery of a parked entry rests on the watcher tick, the detached deliverer started at its park (bounded by the park's deadline, except for a held live entry — §Placed-but-undelivered); those consumers retain the existing escalation rules. Registration binds the seat without draining mail inline. Sending or replying does not advance a different recipient's queue. If a detached owner stops, a watch tick supplies the next automatic delivery opportunity, still subject to the stored binding and readiness checks. With no automatic owner, the recipient can discover and explicitly read parked mail through `tap poll` and `tap read`. `tap doctor` reports every spool entry (informational, never affects its exit code, same class as its registry/backup/watch-log sections) and flags one **past its stuck threshold** (its own `timeout_seconds` if set, else a generic 30-minute floor) as `STUCK-SPOOL`, naming a genuine needs-a-human condition rather than watcher-arm state.

**Persistent spool backlog CONDITION (tap-nr7b, tap-0on2s).** The CONDITION fires for count≥2 unsettled, non-autosettle parks and max `busy_pending_probes`≥3. `busy:pending` observations increment that counter; `busy:noprompt` does not. `tap send`, `tap outstanding`, and `tap doctor` share one report. Oldest queue age is separate from a named witness payload's probe count and parking-to-last-busy-observation interval. Count and interval always come from that same witness. Parking time is not a first-probe timestamp; the interval does not establish continuous occupation. Missing or inconsistent timestamps mean unknown. These historical observations establish neither a current wedge nor whether the composer changed. The report directs readers to payloads and delivery receipts; it never authorizes nudge or Enter from queue history.

### Courier digest (tap-ix63)

**Digest submit outcomes:** only a verified submit (rc 0) advances the recipient delivery clock. Unverified (5) and timed-out (124) submits preserve canonical members and the digest index, notify eligible senders as unconfirmed, and stop automatic pane retry. The digest helper preserves 5 or 124; the drain reports either as unverified (5). The native submit operation applies the shared `digestOutcome` in the same process before diagnostics can start a child. It promotes members under reset custody and releases claims through their shared ownership record; a late failure never releases a successor's claim. Missing Bun refuses before submission with `runtime_missing`; no Bash fallback decides delivery.


When a spool drain finds **N≥2** plain-redeliverable entries bound to the **same recipient** in one claim snapshot, the courier MAY inject a single `digest`-tagged sentinel whose id resolves a courier-owned index listing those N payloads in claim-time order. N wakes collapse to **one doorbell**; the coalescing is always-on at N≥2, with no threshold knob.

**N≥1 for the auto-settle class only (tap-31it).** A `policy=autosettle` entry has no per-id path to fall back to — the doorbell IS its delivery — so a batch containing one flushes at N=1. Ordinary spool keeps N≥2 unchanged: a lone busy-pane park still takes its own solo redelivery rather than a digest envelope. A group flushes only due entries; an ordinary ready entry never pulls an in-window held item into its doorbell.

The digest is a **delivery envelope only** — never a settleable obligation. Each listed payload keeps its own `reply=`, receipts, `in_reply_to`, and `tap outstanding` visibility; the digest never collapses N obligations into one. `tap reply` on the **digest id refuses** with `error_class=not_obligation`. Reply names the index and per-id actions. Reading the digest applies each item's own obligation (`tap reply <id>` for asks, `tap read <id>` for notes).

**Sentinel shape:** `[[TAP v0.23 note <digest-id> digest]]`. The `digest` tag is courier-reserved. The id's own handle field is literally `courier` (minted off `TAP_COURIER_IDENTITY`), and the id slot can never take a `<team>/` prefix: the digest renders both route halves off the same `to_team`, so it is same-team by construction. `tap read <digest-id>` and `tap show <digest-id>` resolve `spool/digests/<digest-id>.json` on that bus, so the sentinel omits `path=` (§Sentinel). The default view lists items; `--item <id>` or `--all` reads their bodies through each item's ordinary verb semantics. Reading the index never settles the digest envelope.

A drain that meets a team-reset fence leaves every body where it is: a spooled body stays in `spool/`, a body already made canonical stays in `payloads/` with its spool metadata, and nothing is reparked, retried or replayed. Each durable drain effect runs under short reset custody, as described in [reset custody for courier drain effects](../identity/registry-unit-1-part-02.md), so the checkpoint copies a body on exactly one side of any move.
