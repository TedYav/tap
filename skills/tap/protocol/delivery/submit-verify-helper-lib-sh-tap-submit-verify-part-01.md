## Submit-verify helper (native courier `submitVerify`; formerly `lib.sh` `tap_submit_verify`)

**OpenCode startup is a named pre-effect defer (tap-7r3fn.36).** An active
OpenCode pane whose `╹▀`-anchored input band is not drawn is `booting`, not an
empty ready band and not a generating turn. Native `opencodeBoxText` answers its
no-box verdict — a `null` reading, not a shell status — for that shape; the
courier checks it before urgent Escape or any submit-body pane effect and
holds with the `booting` defer reason. (The shell pending reader that mapped
absent geometry to status 3 was deleted with the Bash submitter in R4.) Public `tap send` therefore returns a durable
queued receipt, keeps `.placed`, writes no `.sent`, and records spool
`reason=booting`. Drain readiness reports `busy:booting`; it holds and retries
until the band appears or the bound seat departs, and it does not bank
no-band observations toward a forced injection. A present empty band and a
present `esc interrupt` band retain their idle and generating behavior. This
adds `booting` as the third typed rc-4 origin; the older two-origin inventory
later in this section is historical carrier prose and is superseded here. Its
separately tracked lock-park spool-label collapse remains unchanged.

The per-harness input-band and submit decision stays shared rather than per caller: native band selection lives in `runtime/bun/src/pane/reader.ts` (`inputLine`), and the one submit entry is the native courier's `submitVerify` (`runtime/bun/src/courier.ts`), whose Enter loop `submitStagedLocked` nudge also runs. Send, redelivery, `tap self` and peer `tap compact` all call it; none reimplements it — it must **never** be reimplemented per-caller. The Bash `tap_submit_verify` was retired in R4 (2026-09-24).

**Ordinary sentinel submission:** after injection, a complete visible TAP sentinel in the active input region authorizes Enter. Native courier, Bash verification and `tap nudge` share `submit-frame.ts`; Bash calls it through `tap_bun_call`. Matching tolerates ANSI styling, NFC normalization, whitespace and visual wraps. Other text and unknown status chrome do not veto the key. Localization uses available composer geometry and falls back to the last prompt/input tail (OpenCode's last left-border band); a missing bottom border or unparsed footer does not erase visible text. This heuristic is bounded by the transcript-negative controls, not a claim of perfect transcript discrimination.

agy paints a paste progressively (about 4.5 ms per character), so its id is visible before the wire is whole; so does Codex mid-turn (tap-2ajq8). On both, native landing therefore requires the full wire to classify as staged; an id-only sighting is not landing. The wait is bounded at 1 s plus 8 ms per wire character, capped at 10 s, and Enter is never pressed before staged. On timeout the attempt is `unverified` with the detail `<agy|Codex> composer on '<pane>' shows our sentinel id but never the full wire; not submitted, and the input may be partial`. The attempt fence still forbids any automatic retry (tap-aimey).

A recognized human approval prompt from any harness with a blocked screen rule (Claude, Codex, Cursor, OpenCode, agy, Hermes) always holds delivery, even with affirmative harness liveness. Bash and native check before any urgent interrupt key and again before paste or draft clearing; native readiness returns no-band, and the pending-input reader returns blocked, which forced delivery never overrides. Rules fit real default- and auto-mode captures; a startup workspace-trust dialog (Claude, Codex, agy) is a prompt too (tap-3oox6). A trailing group of unboxed queued-input rows below Claude’s live approval footer remains part of the modal, including physical continuations after a full-width row; a newer boxed composer supersedes it. The message stays pending through ordinary, interrupt, no-spool and forced direct-attempt paths, and delivery can resume after the operator answers. Team activity, seat state and the attention list (sorted first) report recognized prompts as blocked. Codex blockers are anchored to the current last nonempty line (confirmation/cancellation, answer submission, or allow-command controls), so stale confirmation text above a current composer does not block.

Other obvious active dialogs/menus and feedback panels withhold Enter unless the current identity guard supplies affirmative harness liveness. Native bound authorization already requires that evidence; an armed Bash guard carries the same result. Optional guard success or pane existence alone supplies no override; a rowless caller must attest its session, pane id and harness. A paste chip or liveness never supplies missing text. URL-entry surfaces require a concrete active-entry specimen before adding a detector; URLs in footer or sentinel text are ordinary text. Pre-inject human-draft protection remains unchanged. Slash and exact-mode controls retain whole-input matching and their existing arrival proof.

Once injection lands, ordinary sends may press Enter at most four times, waiting 0.5s after each of the first three and 1.5s after the fourth. Every press requires fresh composer and identity evidence; every wait ends with another frame. A known empty composer or a new anchored Working/interrupt state after the composer disappears verifies submission. An id disappearing into unknown or changed text does not. Claude may also consume a delivered wire only at turn end: the message parks as an indented prompt row directly above the active box's top fence while the live composer holds newer input or sits empty, and the Claude Bar footer replaces the interrupt hint, so this state carries no working chrome. That bounded queue-row geometry — parsed by the same reader that localizes the active box, indented so transcript prompt rows at column 0 never count, and refused whenever the same wire is still inside the composer — verifies the submission as queued on the Enter already sent, exactly like the empty-composer and Working answers, and never authorizes another key. An unknown outcome records Enter-sent and unverified, preserves custody, and never authorizes reinjection. Codex uses Enter during a turn as well as while idle; Tab queues until turn end and is never used for submission. The `tab to queue` cue means `mid-turn`, not acceptance. Exhaustion returns rc 5 with the last classification and width. Phase records retain the number of issued Enters and the verification result. These are transport facts; recipient processing remains unconfirmed.

`tap nudge` extracts one complete visible sentinel from the same localized region, then retains its canonical-payload recipient and pane-generation checks before invoking the shared decision: the courier's `submitStagedLocked`, in-process, with the same reauthorization and fences before every Enter as ordinary sends. Each nudge Enter is a recorded recovery effect; a refused effect presses nothing and returns submit-unverified (rc 5). Identity drift found before nudge's first Enter is nudge's recipient-drift refusal, with no key sent; after an Enter, every failure is submit-unverified. Each family gets one Enter, only if the wire is the composer's sole text. Truncated or ambiguous markers are preserved; nudge never reconstructs one from an id. OpenCode can retain its mode footer, bottom border, and even a blank input row while the observed `claude-mem-capture` Worker POST failure overprints the input rows; report-only names that torn geometry instead of calling the composer empty. Arbitrary tagged failure text is still a user draft, not recovery evidence. An acted nudge repaints the named overprint — or a band that never painted — before localization; it reports the band observed before and after, exits with a documented attention code while still stuck, and, once healed, continues the ladder without submitting here. The pane-only form first resolves exactly one active acting-registry binding for that repaint effect; the visible sentinel still supplies the canonical recipient checked afterward. Whether recovery starts from that named overprint or a normally readable sentinel, nudge performs at most one exact-window one-column resize and restoration under the recovery effect owner, and requires two post-repaint samples to parse the same complete wire id before its one allowed Enter. The resize transaction is serialized by physical tmux server plus window id because panes in one window share geometry. Both the original dimensions and the prior explicit-or-inherited `window-size` policy must be observed after restoration; unreadable state, changed or ambiguous id, or identity drift refuses without an Enter. The repaint frames remain in the recovery artifact. A still-staged modern or legacy sentinel after that Enter returns submit-unverified rather than receiving another key.

Before injecting, the OpenCode courier also uses that bound input-free resize/restore when the composer reader detects the child-process overprint above — through the geometry-gated arm or the unanchored scan that runs from the composer box top, so a wrapped line that destroys the footer row or bottom border is still named — then classifies the returned frame again. Spool readiness admits that input-free state to the locked submit path instead of parking it as startup, so already-spooled entries reach the same recovery owner, and an OpenCode band that never painted at all (the `input_band_absent` boot signature, distinct from a real shell or a dead pane) joins the cure after a short persistence bound. The cross-attempt budget is one episode record per pane at the effect, keyed by cause, spent count, and two times — never frame bytes, which a working turn changes constantly — and its decision and spend recording run under the window repaint lock so concurrent attempts cannot double-spend. Repaints are cooldown-spaced and capped per episode; only a ready read — the band observable again — retires the record; a held or exhausted episode sends nothing. Exhaustion raises a report-only alarm once per record — a registry event naming the manual `tap nudge` cure, plus a roster suffix — and never repaints on its own again; the ungated manual nudge stays the documented cure, reporting the band before and after and exiting nonzero while still stuck. After injection, the courier uses the same operation only when ordinary post-Enter verification would otherwise return submit-unverified. It then re-observes once: a visible harness queue is accepted as queued and a readable id departure is verified delivery; every other answer stays unverified. Neither repaint authorizes a second Enter or reinjection, so possible-effect retry prohibition is unchanged.

**Native submit boundary:** after injection is attempted, identity, fence, capture, and budget failures remain possible-effect and preserve canonical custody. Native reauthorizes identity and fences before every Enter and checks binding again before returning verified submission.

**Possible-effect admission is the first pane effect, not redelivery entry.** Routing, binding, copy-mode, composer, modal, and draft-preservation checks may refuse without creating `receipts/<id>.attempted`; that marker would make a retry-safe refusal look like an ambiguous delivery and let the grace deadline abandon it. Immediately before the first interrupt, survey recovery, draft clear, existing-sentinel submit, or payload injection, the shared submit path atomically creates the marker for the payload (or every digest member). A marker write failure withholds the pane effect. From that boundary onward, failures remain retry-unsafe even when the first keystroke cannot be verified. Native delivery drivers use the same boundary after their read-only builder, pane-lock, and recovery checks.
