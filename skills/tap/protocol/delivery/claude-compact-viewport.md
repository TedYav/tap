# Claude compact in scrolled and collapsed composers

- **A scrolled composer proves the typed `/compact` from its visible suffix (tap-vho8h).** Claude's composer is a viewport of about the pane height minus fifteen rows (five rows at height 20, fifteen at 40, twenty-five at 60 on Claude Code 2.1.283). A focus that wraps past it scrolls the command row out of frame and repaints the prompt glyph on the first visible row, so the whole-frame match reads `changed` and the worker withheld Enter with the text left in the composer. On the typed-prefix `/compact ` arm only, the pre-Enter frame may stage from its visible suffix: the head was already proven on the prompt line before the first payload chunk and the tail read back after the last one, and every payload chunk is read back before the next one goes in (the visible rows must be a suffix of everything typed so far and end with that chunk, so the overlapping windows chain across the head and middle the final frame cannot show), so at Enter the courier requires every visible row to be an exact width-bounded slice of its own control under the same wrap rules as the full match, anchored at the marker and ending exactly at the control's end, with exactly one alignment. A prompt glyph on the first visible row does not make it the start of the control; other prose ending in the marker, a different marker, a `/goal` or `/loop` control, and an ordinary wire all keep the whole-visible-wire rule. A box with no prompt row stays unreadable unless it has the explicit collapsed border described below; ordinary draft and submit reads still require the prompt. When the proof still fails after typing, the courier result, the worker's terminal receipt and its `self-helper.log` line say the text is in the composer, that Enter is the operator's move, and that nothing is retyped. `tap self compact` refuses a focus over 2,000 characters before any pane effect; detail belongs in the handoff.
- **Claude's collapsed border identifies a visible input tail (tap-lv5rh).** On Claude Code 2.1.327 at 58×24, a long focus hides both the command row and the prompt glyph behind `─── ↑ N more ─…`. The courier opts its typed-control region reads into this column-zero border only with a positive hidden-row count, a matching-width bottom rule, and two-space-indented body rows containing visible text. Approval overlays, a newer prompt below the box, and incomplete geometry still refuse. The captured composer bytes are kept in `runtime/bun/test/fixtures/claude-compact-collapsed.json`.

  The typed `/compact` path uses those rows with the existing per-chunk suffix checks and the unique, marker-anchored wrap proof before Enter. The border itself proves neither the hidden bytes nor arrival: unreadable or mismatched text still leaves the partial command in place with Enter withheld and a receipt. Both `composerInput` and `pendingInputRegionText` default this opt-in to false, so ordinary delivery readiness, draft classification and submit verification do not read the glyphless box as a complete draft. Chunk sizes, retry rules, and the one-Enter limit are unchanged.
