Catalog integer fields are read exactly through ±(2^53−1); a larger magnitude REFUSES `preset_config_unrepresentable`, naming the field and the value. **Preset `metadata` (display only).** An optional table on a preset. Known string keys (published on roster surfaces): `pronouns`, `intelligence`, `cost_basis`, `cost_level`, `budget_capacity`, `speed`, `summary`, `model_family`. Known list keys: `primary_roles`, `secondary_roles`, `avoid_roles`, `banned_roles` (arrays of role names matching `[A-Za-z][A-Za-z0-9_]*`). `model_family` is vendor lineage (tap-gp75), so a panel can take one seat per family: lowercase vendor names such as `anthropic`, `openai`, `google`, `xai`, `zhipu`, `moonshot`, `deepseek`; Opus and Sonnet are both `anthropic`, sol and astra both `openai`. It is published only when set, and is distinct from the preset-level `family` key, which is the `[notes]` bridge above and never lineage. `tap presets` (FAMILY, JSON `family`) and `tap team` (family column, JSON `family`) show the explicit key, else only what a single-vendor harness implies (claude `anthropic`, codex `openai`, agy `google`); opencode, cursor and hermes run several vendors and show `-` / null without it. For a seat, a preset matched from the handle text is not claimed, so its family is the harness's. Unknown metadata keys are legal and CARRIED VERBATIM — the catalog holds every `metadata.*` key it finds rather than a whitelist, and display surfaces render the unrecognized ones labeled by key, so an operator can add a field and reading models can work out what it means with no code change. Values are normalized to JSON-serializable types first (TOML dates and times become ISO-8601 strings), because a raw date would make `tap team --json` drop every preset fact through a guarded writer rather than fail visibly. The four role lists remain the parsed exception. A metadata problem costs that FIELD or that ROLE and never the preset: nothing here reaches argv or the environment. It MUST NOT influence the invocation — not argv, not model, not environment — and resolution is required to produce byte-identical tuning for every value of it. It is not persisted on the session row. Core PUBLISHES it on two existing surfaces: `tap team --json` (optional `preset` + `metadata` object, including the four role lists) and a launch-time `emit_notice` sibling of the family-note faucet (`tap session: <preset> — <roles> — <summary>`). Default human `tap team` does not print a roles column. A roster handle joins a preset by exact catalog name, else the longest catalog name such that the handle is `<name>-…`. Unjoined handles omit the JSON keys — emptiness is by design. A catalog that cannot be read omits ROLES and METADATA (they live in the catalog) but preserves a row's RECORDED `preset` alongside `preset_catalog_unavailable`; it never fails `tap team`. `resume`/`restart` MUST NOT reopen the catalog to reprint metadata (same stale-prose class as notes). `avoid_roles` is a soft preference (the seat can do the work; prefer not to route it there). `banned_roles` is a hard exclusion (must not be assigned). A role name may appear in at most one of the four lists. Overlap is an authoring error that costs the ROLE, not the preset: it is dropped from EVERY bucket with a notice, since keeping the first would make the surviving ranking depend on iteration order and could let a `banned` role read as merely discouraged. The capability tag for "implements code" is `implementer`; `executor` is retired in this vocabulary (it remains the staffing-form word in CONCEPTS.md) and is dropped with a notice naming `implementer` as the replacement. `[roles]` binds like `family`/`[notes]`, and on the same terms: an unbound role, or metadata naming roles while `[roles]` is missing or empty, is a NOTICE rather than a refusal. Roles are hints about briefing text and never decide whether a seat can launch (§Schema tolerance), so a vocabulary typo must not take preset resolution down for the whole machine.

**The disposition is asymmetric on purpose (tap-4xst).** An unbound role — one `[roles]` never defines — is KEPT: it still resolves into its list and still publishes, because the reader cannot tell a genuine typo from a role deliberately not yet described in `[roles]`, and refusing would take resolution down over prose that never reaches argv or environment. A role appearing in more than one of the four lists is the opposite case — DROPPED from every bucket — because there the reader has enough information to know the entry is wrong (a role cannot mean two conflicting things for the same preset) and keeping any one placement would make the surviving ranking depend on iteration order. Same NOTICE-not-refusal severity both ways; the asymmetry is in what happens to the VALUE, not in how loud the reader is about it.

**Tuning translation (tap-ppo7).** `TUNING_CAPABILITIES` in `runtime/bun/src/launcher/tuning.ts` is the single source of truth for which TAP axes each canonical harness supports, the exact flag spelling, and the value domain where the harness publishes one. Operator launch tuning and crew `--model` resolve through it; preset `params` are already harness argv and bypass TAP-axis translation; a seventh harness must declare a row to exist (an enumerating pin reds a harness in `HARNESSES` with no row). Translation happens before the pane spawns. Unsupported axis → `launch_<axis>_unsupported` / `preset_unsupported`, naming the harnesses that do support it. Value outside a published domain → `launch_arg_invalid` / `preset_config_invalid`, naming the harness, the axis, the offered value, and the legal domain; TAP never clamps. An axis with no published domain (agy model keys; codex effort tiers) passes through; an unknown agy model key still stalls at runtime (`cli.log` "unknown model key") because that set is not static. Cursor has no TAP `--effort` axis (effort is a model parameter on that CLI). OpenCode `provider` fuses into `model` as `<provider>/<model>` and is not a flag.

Current rows (flag / domain): Claude `--model` (open), `--effort` (`low|medium|high|xhigh|max`); Codex `--model` (open), `-c model_reasoning_effort="<value>"` (open); OpenCode `--model` (open), `provider` fusion; Cursor `--model` (open); agy `--model` (open), `--effort` (`low|medium|high`); hermes `--model` (open), `--reasoning` from TAP `--effort` (`none|minimal|low|medium|high|xhigh|max|ultra`).

The source is opened by descriptor with nonblocking read semantics. `fstat` MUST prove a regular file with neither group nor world write permission; the resolved path MUST still name the same inode before bytes are consumed. Violations refuse `preset_config_insecure` or `preset_config_invalid`. Provenance hashes the exact opened bytes as `sha256:<hex>` and records the resolved source path.
