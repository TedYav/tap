| Class | Typical verbs | Meaning |
| --- | --- | --- |
| `preset_config_missing` | `session launch` with preset intent | The sole preset catalog path does not exist; create it or launch a canonical harness directly. |
| `preset_config_invalid` | `session launch` with preset intent | The catalog path, UTF-8/TOML, descriptor read, or path-stability check failed; fix the named source. Schema/value tolerance is described above. |
| `preset_config_insecure` | `session launch` with preset intent | The catalog is not a regular file or is group/world writable; replace it with a regular operator-controlled file and remove those write bits. |
| `preset_name_conflict` (retired catalog refusal) | Historical preset diagnostics | A harness-named preset is now omitted with a notice; requesting the omitted preset does not resolve it. |
| `preset_not_found` | `session launch --preset` | Explicit preset intent named no loaded entry; choose one of the listed presets or edit the catalog. |
| `preset_config_retired` | Bun `session launch` with a requested preset | The catalog uses retired version 1; migrate it to version 2 or 3. |
| `preset_config_unrepresentable` | Any catalog read | An integer field is outside ±(2^53−1); change it to a value the reader represents exactly. |
| `harness_or_preset_not_found` | `session launch <unknown>` | The first positional could have meant either namespace; choose one of the named canonical harnesses or loaded presets. |
| `preset_harness_mismatch` | `session launch <harness> ... --preset` | The compatibility-form harness disagrees with the preset's harness; remove the redundant harness or make them match. |
| `preset_env_forbidden` | `session launch` with preset intent | A named environment key crosses the identity, transport, process, or policy fence; remove that exact key. |
| `preset_unsupported` | `session launch` with preset intent | A strict field has no mapping for its harness; remove the field or choose a supported harness. |
| `preset_passthrough` | `session launch` | `--preset` appeared after harness passthrough began; move it before passthrough because TAP never forwards this flag. |
| `preset_not_composable` | `session launch`, `ask`, `crew add` | A preset names every tuning value, so `--preset` with `--model`/`--effort`/`--env` refuses instead of inventing a precedence order. |
| `preset_harness_mismatch` | `session launch`, `ask`, `crew add` | The requested harness disagrees with the preset's; the position is compatibility information, checked rather than silently overridden. |
| `harness_or_preset_not_found` | `session launch`, `ask`, `crew add` | The positional names neither a canonical harness nor a configured preset. Raised only for a POSITIONAL, which may be either; an explicitly named `--preset` keeps the sharper `preset_not_found`. |
| `arguments_joined` | `session launch`, `ask`, `crew add` | A harness or preset argument contains whitespace, which means the caller's shell joined separate words (zsh keeps an unquoted `$var` as one word). Argv-decidable, so it answers before any catalog read; pass each word as its own argument. Seat names keep their sanitizing, and message bodies are free text. |
| `preset_adapter_conflict` | `ask` | A preset param restates a flag the ask adapter fixes for that harness (e.g. cursor's `--mode ask`). Refused rather than resolved: repeating the flag makes the harness pick, and one reading turns a bounded question into an acting agent. |
| `preset_config_changed` | `crew add` | The catalog changed between crew's preflight and its final render. DELIBERATELY A LATE REFUSAL: the preflight guarantee covers ARGV-DECIDABLE refusals, which arrive before any effect; this one depends on a file changing DURING the launch, so it cannot be decided from argv and is detected at the only moment the change is visible. Crew carries the digest it planned against and rolls the window and row back, which converts a silently-different seat into a loud one. Making it early would require carrying the resolved snapshot through registration rather than re-resolving (tracked). |
| `retired_flag` | `crew add` | `--harness` is retired in favour of the positional. Named as retired rather than unknown, so the refusal carries the replacement invocation instead of a generic parser message. |
| `unregistered` | `send`, `whoami` | Register the pane or pass the explicit identity flag. |
| `generation_unverifiable` | self-resolving `send`, `escalate`, `draft`, `recap`, `refresh`, `register`, `unregister`, `team stop`, `watch`, and settlement (exit 1); `whoami` (exit 2) | The caller's pane WAS observed but its identity record cannot be verified: the server generation is unobservable, the pane/tty binding changed between the inventory scan and the targeted re-query, or the targeted record carried no session name. Action: `wait for tmux to answer, then retry — do NOT re-register`. The do-not-re-register half is the point — a seat that re-registers here splits its identity from the row every other seat writes to. Deliberately NOT `malformed pane id`, which is `not_in_tmux`: a garbled id is not a verifiable pane at all, and suppressing re-registration for it would strand a seat that genuinely needs to register. Numeric exits are verb-local: `whoami` uses 2 so this class stays separable from that verb's exit-1 `not_in_tmux`; state-changing watch, settlement, and Bash consumers use 1 for refused/no-change. Consumers key on `error_class`, not a cross-verb numeric exit (Fable adjudication, 2026-09-17). |
| `not_in_tmux` | `whoami` (exit 1) | No pane could be observed for the caller: no controlling tty in the process ancestry, a tty owned by no pane on this server, a tty mapping to more than one pane, a record that is not exactly four tab-separated fields, or a malformed pane id. The detail names WHICH observation failed — `caller pane is not observable (<reason>; pass --pane <tmux-target>)` — because the remedies differ and a fixed sentence prescribes none of them. Distinct from `generation_unverifiable` above: that class means a pane was observed and could not be verified; this one means no pane was observed. |
| `unregistered_sender` | `send`, `nudge` | `--from` is not an active sender seat (for `nudge`, also: no sender derivable and no interactive terminal to ask the operator; see [nudge.md](./nudge.md)). The remedy is computed from the CALLER's pane state, never constant (tap-hgzj): a caller inside an observable pane is told to register from that pane, naming the handle; only a caller with no observable pane is told to register a poll seat. A pane-backed seat that registers `--delivery poll` receives nothing while its senders get success receipts, and poll mode then exempts it from every liveness check. The remedy has THREE forms, not two: a caller whose acting registry is absent or unreadable is standing on a decoy bus and is told to name its team (`--team`) rather than to register, because registering there splits its identity from the team every other seat writes to. A READABLE but seat-less registry is a real team root (post `team reset` / `init`) and still gets the identity remedy. **tap-mcg0:** the no-`--team` decoy-bus sub-case above is no longer reached here — `unanchored_bus` (below) now refuses it before `send` ever resolves an identity or touches a directory. This row's decoy branch still applies when `--team` names a team whose own acting registry turns out unreadable. The reserved watcher identity is the exception to every registration remedy: it cannot register, so its refusal points to a supervisor kind (`probe`, `notice`, or `progress`) sent settle-only — the carve-out keys on the absence of a reply obligation, so `--ask`/`--expect-reply` on a supervisor kind refuses (`--fyi` remains the accepted deprecated spelling of that same settle-only default, tap-7rpf0); reply-required mail must come from a registered pane-backed seat. |
| `sender_liveness_unobservable` | `send` | The send-time sender-facts read did not finish, so whether `--from` is live is UNKNOWN. Distinct from `unregistered_sender` on purpose (tap-qa6e2): the boot-id predicate crosses a runtime boundary, and reading its exit status made a Bun that could not run indistinguishable from a boot that genuinely differed — a valid pane sender was refused as unregistered and told to reclaim its own handle. The door now answers with a TOKEN (`boot-ids:match` / `boot-ids:differ`); anything else is the third state and refuses here instead of becoming a registration verdict. The remedy names the runtime (`bun --version`), never registration, and the detail says the handle must not be reclaimed. An unreadable current boot is machine-wide, so a boot-stamped sender refuses here before any recipient attestation could report `boot_id_unobservable` (tap-fsmgm). |
| `unanchored_bus` | `poll`, `outstanding`, `peek`, `send`; and, through the onboarding preflight, every local verb (§Repository ignore rule and the missing-local-team onboarding preflight) | The cwd-derived bus has no acting registry, and the caller pane is registered on a DIFFERENT enrolled team's root — the classic wrong-worktree case (e.g. cd'd into a lane checkout to read code). Refuses with `cd <enrolled-root>` (or, where the verb accepts it, `--team <name>`) rather than certifying an empty result or bootstrapping a fresh bus at the wrong cwd; a caller with no observable pane and no enrolled match gets the same class with a bare `--team`/`TAP_HOME` remedy instead. Checked and refused BEFORE `tap_ensure_dirs`, on purpose (tap-mcg0): mkdir'ing payloads/receipts at an unenrolled cwd first, then failing, leaves a self-concealing decoy bus for the next caller there — a bare `.tap/` from git checkout does NOT itself cause this (verified: identical refusal with or without one on disk); only a verb creating bus dirs from the wrong cwd does. `send`'s own exit-code contract retires 4, so it refuses with 1 here where `poll`/`outstanding`/`peek` use 4. **Three distinct situations now share this class, and their actions differ.** (a) The calling pane is registered on a DIFFERENT enrolled team's root — the wrong-worktree case described above; the action stays `cd <enrolled-root>` (or `--team <name>` where the verb accepts it). (b) The caller has no observable pane and no enrolled match — the bare `--team`/`TAP_HOME` remedy above. Both are unchanged.
