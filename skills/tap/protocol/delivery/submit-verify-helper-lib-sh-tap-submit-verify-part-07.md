- **The prefix's own success is verified, not trusted.** `send-keys` returning success is not proof the prefix actually rendered (dropped/swallowed keystrokes are a real, if rare, class). After the settle and identity recheck, the courier reads the pane's current typed-input text (`pendingInputText`) and compares it against the prefix (its one mandatory trailing space stripped, since the pending-input extractor trims trailing whitespace). A mismatch fails closed (`unverified`) **before the payload is ever injected** — a dropped prefix behind a landed payload would otherwise submit as plain prose, the exact bug class this mechanism exists to fix, one layer down.
- **The comparison is against the band's TYPED text, with harness chrome already removed (tap-tx3s, tap-tx3s.1).** Claude Code paints an argument-placeholder hint after any recognized slash command whose argument is still empty. **Four** commands are affected, and they share no text grammar: `/compact  <optional custom summarization instructions>`, `/goal  [<condition> | clear]`, `/loop  [interval] [prompt]`, `/clear  [name]`. That text is chrome — the pane owner never typed it and the harness never submits it. Removing it is the **band reader's** job (`pendingInputText` in `runtime/bun/src/pane/reader.ts`), not this caller's, so every consumer sees typed text rather than typed text plus decoration; `/clear` reaches the same reader through `match_mode=exact`, which is why the fix covers it by construction rather than by a second rule. The reader identifies the hint by where it sits **and** the placeholder's own text. Two properties are required **together**, plus one width variant:
  - it is preceded by **exactly two blank columns**, the committed space that made the token a command plus the column the cursor reserves; and
  - the command token and the suffix text are **one of the four pairs above, verbatim**, **or** a non-empty proper prefix of that placeholder followed by exactly one U+2026 (`…`) **and** the full plain prompt row fills the observed pane width (Ink truncate-end on a pane narrower than the placeholder). An unreadable width refuses the truncated form and still accepts the verbatim form.

  One measured production cause: geometry. At pane width 53 the prompt row is 53 cells ending U+2026 (exact fill); the verbatim table lookup cannot match a truncated placeholder, whatever the paint. The full `/compact` row is 56 cells; a pane too narrow to fit it truncates. Recapture of the live pins requires `CLAUDE_CODE_TMUX_TRUECOLOR=1` under tmux (TAP's launcher setdefaults it; a hand-rolled session does not), `COLORTERM=truecolor`, no `NO_COLOR` / `FORCE_COLOR=0` from the launching client, and a capture census of zero `38;5`. On those truecolor bytes at width 80, BASE's colour conjunct matches and the row reaches the table.

  Colour is not an authority. A muted-achromatic 38;2 conjunct used to sit here; it left because the text table already names the hint. Zero `38;5` was observed on sampled production panes (`%44` incident, `%179`). A colour conjunct additionally binds the reader to the capture/pane environment (`rgbToAnsi256` downgrade when truecolor is not advertised: missing `CLAUDE_CODE_TMUX_TRUECOLOR` under tmux, or a colour-stripped client). That is deletion rationale, not a second measured incident cause. The third conjunct is not belt-and-braces. Position describes WHERE the hint sits and cannot establish that it IS the hint: a band carrying a pane owner's real typed draft, in that position, satisfies the blank-column rule and would be stripped without the table — constructed and demonstrated in review, and pinned as a negative fixture (`muted-real-draft`). The pairs are **enumerated, never generalized** to an angle/bracket grammar; that generalization fits a pane owner's own bracket text just as well, which is the defect it would be introduced to prevent. A reworded placeholder therefore drops out of the table and returns the caller to `5`, which is this defect's pre-existing behaviour and the direction a stale table must fail in. If the placeholder no longer fits the pane, widen the pane to check before touching the table. **Known residual:** a pane owner who types a byte-identical placeholder in the exact two-blank position is not distinguishable from the rendered band alone; separating those needs cursor authority from tmux rather than a further predicate, and is out of scope for this check's bar (arbitrary residue, a second command, an ordinary draft).
