## Command mode (`tap compact`, and the deprecated `tap command`)

**Implementation owner.** Both spellings now enter `runtime/bun/src/verbs/compact.ts`. The native owner replaces `tap-command.sh` and `tap-compact.sh`; identity, fresh pane observations, focus policy, reset bookkeeping and attention diagnostics use native owners without sourcing `lib.sh`. Peer submission runs through a cancellable native child process; focus delivery uses `courierArgv`. A missing actor still receives the enrolled-team remedy (or `old_store`), and compact accepts only a process-owned caller pane, never a background job identity. One context supplies both the acting registry and audit bus; an explicit `TAP_HOME` must name the acting bus; any other pin refuses `bus_not_acting`. This intentionally removes compact's former same-owner custom-home exception. An unenrolled sibling without a pin gets the enrolled-root remedy before bus creation or pane input. No second parser or compact policy remains in a shell entry point. Peer success requires fresh native compaction proof and accepted follow-up delivery; it does not prove a context-size reduction or recipient read.

**Surface vs engine (tap-thgv).** `tap compact <seat>...|--all [-m <focus>]` is the current spelling; `tap command compact` is a deprecated alias for it, `tap command clear` was a deprecated alias for the injection clear and is now RETIRED (tap-pz3j) — it refuses with a pointer to `tap clear`, which supersedes it. All of them run the ONE implementation described in this section — the alias translates its grammar and delegates, because two copies of this target resolution would be the twin-contract state §Seat refresh already forbids. The alias prints a deprecation note on stderr and changes no exit code, so a scripted caller keeps working. `tap command clear` is **retired** (tap-pz3j), the PR immediately after tap-utpn: tap-utpn removed its last caller (refresh delegates to `tap clear` now), so it is already a second clear engine reachable only by a deprecated spelling. It was a separate PR because four of `command-mode.test.sh`'s arms used that surface to evidence IDENTITY SPOOFING as a refusal — the only place that evidence existed. They are re-homed against the new engine in `session/tests/test_launcher.py`, and the TAP_SELF one had to be BUILT rather than ported: `tap clear` never reads that variable, so the spoof has no observable effect and the guarantee is invisible in the code. The stale-`reply_to` preflight retired WITH the injection clear rather than moving, because it existed only to preserve routing options across a re-registration this engine does not perform. `tap command compact` is not on that schedule: it delegates to the one live compact engine, which is what makes it an alias rather than a twin.

**Why the grammar differs from `tap clear`.** Compact takes several seats and `--all`; clear takes one seat and offers neither. That is a decision about recoverability, not an inconsistency: a fan-out clear discards every targeted context at once with no undo, while compacting five seats is routine hygiene. Both spell the message flag `-m`.

**Self targets require authored continuation.** A compact aimed at the initiator
by handle, same-pane alias or name-derived identity refuses with exit 1 before
input on every harness. It points to `/tap:self compact`, which authors the brief
and invokes `tap self compact --handoff FILE [--notify SEAT] -- FOCUS`.
Peer compact and `--all` keep their lifecycle; `--all` excludes the initiator.
Peer clear also keeps its self-target refusal: it replaces the invoking process
and cannot survive to verify its own result.

`tap command` is a narrow local-pane transport for context hygiene, not arbitrary remote execution. Its verb allowlist is exactly `compact` (`clear` is retired — tap-pz3j — and refuses with a pointer to `tap clear`); compact accepts explicit local peer seats or `--all`. Compact's optional `--focus` is one-line context text with no leading slash command or control byte. It exposes no goal, force, JSON, or dry-run mode. The initiator is derived from the calling process ancestry's controlling TTY and mapped back to tmux's stable `pane_id`; caller-controlled `TAP_SELF` and `TMUX_PANE` are never identity authority. `--all` excludes every handle carrying that `pane_id`; an explicit same-pane alias is a self-target and refuses as described above. Targets must be active pane-backed registry entries that carry a live, unrecycled stable `pane_id` and use a supported agent harness. A legacy row with only a mutable pane address refuses before any pane input; a stored address is used only after resolving to that same stable identity, otherwise submission targets the `pane_id` directly.

Compact `--all` enumerates only peers that already carry a non-empty stable `pane_id`; address-only legacy or incomplete rows are outside the eligible fan-out rather than becoming a late hard failure after valid peers have already compacted. Explicitly targeting such a row still fails loud with the stable-identity refusal.

A peer compact submits through the native courier `submitVerify` (R4, 2026-09-24): the draft is cleared rather than preserved, the registry row is re-read at every pane effect, and the shared staged loop allows one Enter only, with no replay after a possible effect. The peer path does not use the typed-prefix stage; `tap self compact` does. Compact is supported for Claude, Codex, and OpenCode. **Amended tap-n27ug:** a Codex TARGET refuses with exit `1` when named — explicit seat or deprecated alias — telling the caller to ask the seat to checkpoint and self-trigger through its handoff-gated worker; only the seat itself may submit `/compact` there. Under `--all`, a Codex member, or a member whose pane positively runs a known non-agent (a shell, pager or editor), is skipped with one stdout line and counts as success (CLI-EXIT-0); an empty or ambiguous harness read (such as a shallow `node`) is still a failure. `--all` with no active peer pane seats prints `nothing to compact` and exits `0`. Cursor and Hermes compact return degradation (`6`) with the manual keep-list fallback, and the message is **per-harness because the keep-list's fate is**: cursor is told `tap clear <seat> -m <keep-list>` (it takes the instruction positionally), while hermes is told to clear and re-brief over the bus, because hermes takes no initial prompt by decision and a `-m` passed there is silently discarded (tap-boiq). Retiring this file's clear half orphaned that pointer; tap-pz3j repointed it rather than dropping the sentence, and splitting the two is what keeps the repointed version true; supported targets in the same `--all` invocation still run. Any hard failure makes the aggregate exit `1`; otherwise any degradation makes it `6`; all success is `0`.

**Inline compact-focus capability (tap-zsrn).** Whether `/compact` may carry inline focus text is a harness property, not a convention: `focusMode` in `runtime/bun/src/compact-focus.ts` returns `inline` (Claude), `deferred` (Codex, OpenCode), or `unsupported` (everything else). Both `/tap:self compact` and `tap compact` consult that one table. Deferred harnesses submit **exactly** bare `/compact` — composing `/compact <focus>` turns the focus into an ordinary prompt (OpenCode) or a refusal (Codex) while the seat may still report success and context rises.

**Unresolved peer wire discrepancy (tap-usgng).** The exact-bare requirement above remains the intended deferred command contract. Current OpenCode peer behavior appends ` [[sv:<id>]]` to `/compact` at the shared-submit call, while OpenCode self compaction stages exactly bare `/compact`. The native retirement preserves those existing peer bytes, match mode and status semantics under the leader's fidelity ruling; it does not adjudicate the historical requirement or establish a live harness failure. The follow-up requires private-fixture evidence for the submitted bytes, focus delivery and verification/status behavior before changing the suffix or match mode. It does not gate this retirement.

**Where a focus that cannot ride the command line goes instead (tap-thgv).** Two rails, split by whether the target has a durable inbox:

- **Peer** — the focus is a settle-only **payload**, sent only after the shared durable proof barrier confirms compaction, and that send is also the wake. Durability is the reason: the peer path is the one nobody is watching, and an injected line the compaction eats leaves nothing, while a payload survives on the bus for `tap poll` to find later. Its receipt is also how the initiator learns the focus arrived. A send that does not land is **6 DEGRADED**, never a clean success, and prints the lost focus plus the exact `tap send` that repairs the state — the staged resume body also remains under the bus handoff directory.
- **Self** — the focus rides the resume note verbatim on Codex and OpenCode. Every self compact requires a registered seat and an authored handoff copied before arming; the note names that durable copy.

The peer resume body is staged before submission and retained as evidence; the delivered focus still travels as a payload. The earlier peer path wrote the initiator's `--focus` to a handoff file and pointed the ping at it, and the deferred self path stored it in a one-shot capsule under `~/.tap/self` consumed by the Codex SessionStart hook. **Deleting the capsule fixed a live defect rather than costing coverage:** it had exactly one consumer (the Codex hook) while the deferred branch wrote one for OpenCode as well, where nothing ever read it — `/tap:self compact <focus>` on OpenCode reported success naming a focus it had silently dropped. One capability was genuinely retired with it, and it is narrower than "auto-compact support": a capsule written for a SCHEDULED compact could also be consumed by an unscheduled auto-compaction that happened first, inside its one-hour TTL. Codex-only, and now unavailable (tap-thgv).

The explicit `tap self compact --handoff <file>` flag is NOT that machinery: the agent writes a real multi-line file, `tap self` copies it to the bus before any pane effect, and the ping names the path — path-in-ping, the same rail as everything else.

**Seat-tier switches (Claude only).** `tap self compact` and `tap self rebrief` accept `--model NAME` and `--effort LEVEL`. After fresh compaction proof, or the native session change a rebrief observes, the worker submits `/model NAME` then `/effort LEVEL` before the resume or recovery note, so the first model turn after the reset runs on the requested tier. Each switch is a local command, proven by a fresh `<local-command-stdout>` line in the bound transcript. The worker holds the pane-submit lock from the first switch to the last proof, so no other delivery starts a turn between them. Only a no-effect refusal is retried; any failed switch ends typing, so effort never changes on a model the worker could not select. An unproven switch never withholds the note: the note opens with a warning and the receipt records `switches`. Other harnesses refuse with `6` before arming.

**The narrowing gate has one owner.** `focusNarrowing` (`runtime/bun/src/compact-focus.ts`) rejects exclusive/destructive focus phrasing — `focus only`, `only on`, `ignore`, `discard`, `omit`, and siblings — word-boundary matched against the lowercased text so ordinary vocabulary (`only once`, `gitignore`) does not over-fire. Both the self path and the peer path call it. It previously lived inside the retired `self.sh`, which made the identical sentence a refusal when a seat aimed it at itself and prose discipline when a leader aimed it at a teammate.
