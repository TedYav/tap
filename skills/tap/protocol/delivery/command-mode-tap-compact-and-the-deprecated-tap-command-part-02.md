**Compaction handoff and post-compaction wake (tap-joqz).** An explicit `/compact` consumes the turn that submitted it, so with no inbound traffic nothing starts the next one and the target silently stops; the initiator meanwhile holds a clean success receipt. Compact therefore always queues something **behind** the `/compact` — the focus payload on the peer path, a deixis-free resume ping otherwise (see the two rails above). The wake is armed **unconditionally**: the agent decides whether work remains, not the arming logic. **Ordering is necessary and not sufficient (tap-ieiy).** A queued PLAIN MESSAGE is handed to a Claude Code model at a TOOL-CALL BOUNDARY — the same property that lets a TAP send wake a mid-turn seat — while a queued SLASH COMMAND waits for the turn to END. Submitted mid-turn the two are therefore on different delivery rails, not in one queue, and a ping submitted second can still be ANSWERED FIRST, in the pre-compaction context where its own instructions are meaningless (observed live and reproduced on Claude Code 2.1.233 whenever the turn keeps making tool calls). On the `/tap:self` path one detached Bun worker (`runtime/bun/src/self-compact.ts`) owns the resume on every supported family, because `tap self` runs inside the very turn whose ending starts the compaction and an in-process wait would block the state it waits for. **The resume is a TAP note to the compacting seat** (`tap send <self> --note --wake`, body file-sourced), never a raw pane submit: the courier owns lock contention, spooling and the no-retry-after-effect rule, so the worker has no retry taxonomy of its own. The note body is the deixis-free resume ping (`handoffPing` in `runtime/bun/src/compact-focus.ts`), which never asks the target to recall (the post-compaction summary is precisely the unreliable artifact); it names the absolute handoff path and points at durable state (`tap poll`, task list, `bd ready`). Per family: **Claude** — `tap self compact` validates and arms one detached worker before any pane input. The worker waits on the shared courier's draft, copy-mode and pane-lock checks, then submits `/compact <focus>` once, including mid-turn when the live composer permits it. A refusal is retryable only with explicit no-input-effect evidence; an unknown or possible effect is never retyped. The queued wait is bounded by `TAP_SELF_COMPACT_TIMEOUT_SECONDS` (default ten minutes from arming); expiry records `not-submitted`, retains the handoff and sends no resume. The worker captures the bound transcript offset, file identity and timestamp at Enter and requires a fresh complete user record with `isCompactSummary: true` and `isVisibleInTranscriptOnly: true`, matching the native session and excluding sidechains. Old already-submitted requests remain proof observers; a missing boundary without queued-request authority never becomes a new submit. **OpenCode** — the worker holds the pane-submit lock, waits for two consecutive idle reads, and submits bare `/compact` once through the locked courier seam. At Enter it captures the bound store and message boundary. Proof requires a fresh assistant summary with `finish: stop`, a completion time and no error, linked to a fresh user message with a compaction part in the same session. Both families have durable witnesses; missing bindings or unreadable witnesses never downgrade to chrome. A missing witness records `not-compacted`, preserves the handoff and withholds the resume, with `compaction-never-observable` in `wake-unverified.log`. An unverified submit is never repeated and permits a resume only if fresh proof subsequently appears. Claude receipts carry `evidence: transcript-proven`; OpenCode receipts carry `evidence: store-proven`. Both retain `compactedAt` through the terminal receipt. Native session and transcript/store bindings must still match before resume. **Codex (tap-n27ug)** — the worker holds the pane-submit lock across one authorized Escape, one locked `/compact` submit, and proof — a fresh top-level `compacted` record (timestamp and byte offset captured at the real Enter) in the bound rollout — before settling and sending the note; missing proof records `not-compacted` with the handoff preserved and nothing sent. Every family settles `TAP_SELF_PING_SPACING_SECONDS` (default 2, tap-lmbs) before the note, rechecks the seat identity, and records each phase in `<bus>/handoff/<id>.compact.receipt.json`, with a pointer line in `self-helper.log` for the terminal state (`resume-sent`, `resume-miss`, `not-compacted`, `not-submitted`, `incomplete`). A refused or failed note is `resume-miss` plus a `resume-send-failed` line in `wake-unverified.log`. The worker needs a registered seat, so `tap self` refuses an unregistered pane with exit `1` before any pane effect. On the `/tap:self compact` path exit `0` means "queued, worker armed", never "submitted" or "wake delivered". Arming failures precede pane effects; the old submitted-but-unarmed exit `7` is no longer emitted. Claude receipts retain `queuedAt`, verified `submittedAt` and proof `compactedAt`. The peer focus is deliberately weaker than the self path's, where the agent composes its own, because the initiator knows less than the target would; the ladder still prefers `tap send <seat> "run /tap:self compact"` for a seat that can be asked nicely. A peer ping that fails to land makes compact return `6` DEGRADED, so a stopped seat is never reported as a clean success. Queue-behind is anchored to a LIVE PROBE, not to a mock — a mock asserting that a ping survives compaction would only replay our assumption about compaction — and is re-established by re-running that probe after a harness update, never assumed; procedure, results, and the Codex-vs-Claude limits are in `docs/solutions/architecture-patterns/compact-queue-behind-probe.md`. A failed `--handoff` write is fatal on `tap self compact --handoff`: the agent wrote that file to be read. An EMPTY handoff file is refused outright, because unlike an absent one it survives the compaction and reads as a positive statement that nothing was in flight; on Codex an ABSENT one now refuses too, before any effect.

**Peer completion barrier (tap-u937).** A peer target can finish its own turn while the initiator waits, so its existing cancellable child owns submission, proof and follow-up. It uses `compaction-proof.ts`, the same reader and Enter-boundary capture as self-compaction. Before any pane input the parent writes a durable resume body and initial receipt under `<bus>/handoff/`, and prepares the terminal command audit. The child attempts `/compact` once, waits for a fresh bound Claude transcript or OpenCode store witness, then sends the resume as a TAP note. Both focus and no-focus paths use this barrier; neither can spend a wake on the pre-compaction context merely because submission was accepted. The same native session is checked during proof and again at envelope placement. The existing OpenCode peer suffix remains unchanged (tap-usgng).

The peer receipt `<id>.peer-compact.receipt.json` carries `transcript-proven` or `store-proven` and `compactedAt`. No witness yields `not-compacted`, retained resume text and no follow-up. Cancellation stops the child and fan-out; it preserves the last receipt and body and authorizes no retry. The parent publishes its terminal success audit only after validating the child's completion receipt. A proven compact with an unaccepted resume is `resume-miss` and exit 6; accepted delivery is `resume-sent`, not proof of recipient read. Missing proof is exit 1. The default wait is ten minutes per target, controlled by `TAP_SELF_COMPACT_TIMEOUT_SECONDS`; `--all` remains sequential. A self-target still arms its detached observer and reports completion unverified.

**Per-harness clear spelling (tap-ywvb).** The clear command is resolved from the native owner `clear-command.ts` (runtime/bun, reached as `self-rebrief.ts command`), never built as `/<verb>`: `opencode` takes **`/new`**, every other supported family takes `/clear`. This is not cosmetic — on opencode `/clear` is not a registered command, and its TUI routes an unrecognized slash string to the MODEL as an ordinary user turn with no toast, error, or log, so the seat is never cleared, a model turn is spent, and the caller still receives a green receipt (the submit genuinely verifies and re-registration genuinely succeeds). Because that failure is silent on exactly one family, an **unlisted harness refuses** rather than defaulting to `/clear`: a wrong guess is self-announcing everywhere else and invisible there. The exact-match verify path resolves the spelling from the same helper — comparing the injected text against a literal `/clear` would send `/new` down the sentinel branch and verify against an id that never appears. Version caveat: opencode's docs list `/clear` as an alias of `/new`, but that describes a build newer than 1.18.15, whose binary contains zero `/clear` command literals; `/new` is valid on both sides of that change.


Codex self-compaction accepts the exact bare `/compact` input accompanied only by its matching autocomplete description. Extra input or a different menu row still refuses Enter. The final readiness check recognizes this exact worker-owned staged command on the same captured frame; ordinary readiness still requires an empty composer. Active-work chrome, queued follow-ups, a working title, changed turn and custody holds continue to refuse Enter. A refusal before the Enter proof boundary retains the courier reason in the terminal receipt; a missing boundary never authorizes transcript proof or another Enter.

**No-actor remedies stay local (tap-4suib).** When compact cannot identify its
initiator, it recommends registration in the selected team. It checks only the
already-resolved acting registry for an old-store refusal; it does not search
machine-wide enrollments for another seat or suggest a foreign team's root.
An unanchored caller gets the generic registration remedy without a registry scan.

**Claude in-turn control verification (tap-419qs).** The typed `/compact` path
recognizes complete, naturally wrapped controls containing known single-cell
Unicode characters, including arrows. Full-width hard wraps inside long tokens
also preserve equality; a matching tail alone is insufficient. Expected multi-space
separators hidden at a wrap cannot prove their byte count and refuse; visible spaces remain exact.
Self compact strips trailing ASCII spaces from its focus before adding the
marker's single separator, so it never creates that ambiguity at the join.
At a natural soft wrap the pane cannot reveal extra separator spaces, so the
single-separator rule compares rendering equivalence, not hidden byte counts.
Visible edits, broken token continuity, expected newlines and foreign drafts
remain guarded. Busy/idle chrome
does not change the decision: exact owned composer text permits one Enter.
A queued control is accepted only when its complete owned text is immediately
above Claude's `ctrl+x ctrl+s to send now` cue and the bounded active composer
shows `Press up to edit queued messages`. Neither transcript text nor the hint
alone establishes acceptance. This queue verdict advances the worker to proof observation; the resume still
waits for fresh bound transcript proof. The typed
compact path attempts Enter once. An uncertain frame, before or after Enter,
never authorizes taking the input back; it leaves the composer intact and
reports the uncertainty. A lingering echo never authorizes another Enter.
Tmux copy-mode refuses each worker attempt before typing; the worker waits
within its queued deadline for the live view. The caller has already returned
`0` with the receipt path and must not rerun compact to check progress.
