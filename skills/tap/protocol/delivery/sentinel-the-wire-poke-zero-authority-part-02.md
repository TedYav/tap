**This REVERSES tap-0z9l, deliberately and under a ruling.** v0.21 restored `path=` unconditionally after the v0.18 diet (tap-wt0i) omitted it whenever the payload already sat at the recipient's own canonical location: a 97-second-old opencode crew seat read a path-less sentinel as a message with no body and reported it as such, and it was escalated as transport data loss though no bytes were ever lost. The diet's rationale — the pointer "carried no information the recipient did not already have" — was true only for a reader who already knew the convention, and the convention is taught by session-start injection on three harnesses, by nothing on the fourth, and by no mechanism at all to a compacted context or a human reading a pane. Nothing in the v0.23 decision chain cited that bead until the implementing lane surfaced it; **on 2026-09-04 the decision was that §13 stands**, on the grounds that the replacement is different in kind: v0.18 left a naive reader a bare 12-hex id and a convention, while v0.23 leaves them `<handle>-<UTC>-<12hex>`, a token that pastes into a verb, plus the note itself inline when it is short. **tap-0z9l acceptance 3 — the recipient must be able to TELL — is carried by the id, not by the path**, and `sentinel-pointer.test.sh` case (1) now pins that resolution rather than the retired mechanism.

**Named residuals.** The pointer decision is made at CONSTRUCTION time, so an enroll or retire between construction and read can change the answer (`tap admin retire` is an operator act, after which `tap show <team>/<id>` says `no enrolled team`). The live Bun renderer has no cross-team index probe: supported local native sends use a bare id, while cross-team and manual-relay forms delegate to Bash and its enrolled-bus probe.

**Recipient rule for a sentinel with no `path=`:** use `tap read <id>`; a digest resolves to `spool/digests/<id>.json` and lists its items. An ordinary payload is at `payloads/<id>.md` on the bus the id's `<team>/` prefix names, or on YOUR OWN bus when the id is bare — resolved by the verb’s bus selector (native enrolled-cwd selection precedes ambient `TAP_HOME`; Bash fallback retains the selected bus pin); never assemble a `<repo>/.tap/bus/...` string from cwd, which is wrong for every `TAP_HOME` seat and every legacy bus. `tap reply <team>/<id>` shares read/show lookup; retaining the team prefix disambiguates the sender bus. Explicit positional paths and `--payload` select that file rather than a local same-id payload; `--payload` must match the supplied id. Resolution never adopts parked custody or settles a message. An already-read note still refuses as already settled, while an ask remains open until its durable reply. `reply` uses `--by` for its addressee actor; `--from` errors name that option. `tap show <id>`, `tap read <id>` and `tap reply <id>` resolve message ids; `tap poll [<handle>]` lists the recipient’s queue. **Scope fence, unchanged:** this is the sentinel wire only; the envelope's own frontmatter `path:` field is unchanged. A seat that meets a sentinel shape it cannot interpret should ask the sender rather than guess — the sender is one reply away.

**Reading an unparseable sentinel never destroys it.** If a pane's input band OPENS with `[[TAP` and no id can be read out of it, the courier refuses read-only and leaves the band intact — it never backs it up and clears it. The gate is the opening anchor and only that: not a substring, because sentinel-shaped prose a human typed is their draft and keeps its ordinary clobber path; and not the closed `[[TAP` … `]]` form, because a truncated marker is the case most worth protecting and is exactly the one with no `]]` to match. The invariant holds at every site that reads a band — the native courier (which `tap nudge` shares) and the Bun delivery path. Its residual is that an anchored-but-broken marker parks that pane until someone submits or clears it, so the refusal names the remedy.

**Slash-qualified identity (tap-cnfm, re-sited by v0.23).** `from=`/`to=` are gone from the wire; the qualification they carried now rides the ID SLOT as a `<team>/` prefix, emitted iff the sender's team differs from the recipient's. The envelope frontmatter is unchanged: team-local `from`/`to` handles with `from_team`/`to_team` as the structured equivalent when stamped (§Envelope). Ids ON DISK are never qualified — the prefix is a wire-only locator that the reader splits off before opening `payloads/<id>.md`.

**Recipient corroboration without `to=` (architect ruling, 2026-09-04).** The band no longer carries a recipient, so a stuck-sentinel reader re-keys on the courier-written `to:`/`to_team:` of the payload the id names: a bare id resolves on the argv target's own bus, a `<team>/` prefix through the machine index. The band token and the payload field always shared one provenance — the courier wrote both — and the file is the stronger form, because a stale band token cannot disagree with itself. **The witness argv does not choose is the pane binding**, and it is unchanged: the observed candidate pane must equal the registry's bound pane for that handle. **Corroboration that cannot be OBTAINED is not corroboration that FAILED:** a recipient who disagrees is refused, one who agrees is submitted, and one who is unavailable (payload absent, bus unenrolled, already settled) is submitted uncorroborated and recorded as a registry event, because refusing there would stall a pane on a well-formed sentinel. A failed corroboration lookup refuses without Enter and retains the newly placed canonical payload: unreadable or malformed index evidence, failed filesystem observation, transport failure, a crashed owner, and malformed owner output do not establish absence. Native owner failures take the existing submit-unverified path, preserving the canonical without automatic retry even if an urgent interrupt already occurred; actual recipient disagreement keeps its identity-refusal behavior. A well-formed location positively observed absent or not a directory remains unavailable with its registry event. This intentionally corrects the former qualified-id lookup, which collapsed instrument failure into successful empty output and permitted submission. `tap nudge` keeps its stricter refuse-on-absent, where the operator is deliberately targeting that one sentinel, and reports absence as its own error class rather than as an identity mismatch. A digest sentinel resolves through its own record the same way (tap-8nmot): when `payloads/<id>.md` is absent but the courier's digest index `spool/digests/<id>.json` exists, `tap nudge` reads the recipient from that record's `to`/`to_team` instead of an envelope; a reaped or malformed digest record keeps the refuse-on-absent behavior.
