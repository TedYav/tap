The native courier's `submitVerify(pane, id, wire, bound, fx, authority)` (`runtime/bun/src/courier.ts`) owns the full cycle. The numeric exits below are the retired Bash `tap_submit_verify` contract, which the courier's `SubmitResult` statuses carry forward: `injected`/`harness_queued` for `0`, `pane_gone` for `3`, the pre-effect holds (`lock_busy`, `band_busy`, `copy_mode`, `recovery_held`, `rate_limited`) for `4`, `unverified`/`attempt_evidence_unwritable` for `5`, and the identity and fence refusals for `6`. **rc 4 / `no-prompt` means there is no usable input band, which is not the same as "the seat is mid-turn"** — every family but hermes queues typed input natively, so a running turn is not by itself a refusal. The class covers a pane with no band at all and, for agy, a recognized permission modal; the operator-facing remedy is to wait for the pane, not for a turn to end (tap-92v3r). A registry-bound call re-runs the full exact-session/designated-pane/boot/generation/harness authorizer before every pane effect; the narrower rowless manual form rechecks exact session-name membership and the same pane id. Identity drift returns the caller's internal identity refusal (`6`) before the effect; public verbs translate that into their existing structured failure/spool behavior. The last authorization before the sentinel paste follows the final readiness samples (copy-mode, band, paste-collapse chip), because those samples are tmux round-trips during which the registry can rebind; on both doors it also precedes the delivery-attempt record, so drift found there leaves no `.attempted` receipt (tap-wudl2). A typed-prefix submission records the attempt before its first prefix keystroke, which is itself a pane effect. The cycle is: idle-input pre-check (non-opencode, except OpenCode's known-chip protection; skipped for safe queue-prefix harnesses that can queue without a visible idle prompt) → immediately sample the input band → inject sentinel with the harness input mode → verify the minted id landed in the input band **or, only when a harness-specific paste-collapse chip transitioned from absent in that immediate sample to present after this inject, that chip visibly represents the injected content**, OR — for a **queue-prefix harness (hermes)** whose working input band carries no prompt glyph — a **glyph-less** scan of the pane for the unique minted id (a POSITIVE observation, never a blind trust: a genuine inject miss leaves the id absent and still fails closed at exit `5`) (**tap-dl3**: the glyph-ANCHORED check false-negatived the visible `⚕ ❯ /queue [[TAP …]]` line and returned exit `5` *before pressing Enter*, so senders retried and `/queue ` lines STACKED unsubmitted; deeper positive/clear verification of the hermes band is tracked in tap-ddf) → re-observe the full active composer before each Enter for fresh marker-bearing injections, including digest and typed-prefix delivery. Ordinary v0.23 wire requires complete visible-text containment under the shared blocker/liveness rule above; other text is permitted only OUTSIDE a readable bounded composer — foreign bytes fused inside one (the reader's `fused` verdict) are human input: backed up (the band minus our exact wire), cleared, and the sentinel re-injected once before Enter; a second fusion stops unverified with the backup retained (tap-maavp effect 2), and a chip alone is still insufficient. Slash controls retain exact whole-input or existing proven-chip matching. Full-pane sentinel-id searches use joined ANSI captures. OpenCode composer geometry, composer-scoped id observations, and nudge's sentinel-tail reader use physical, unjoined rows: one renderer can mark every pane row wrapped, making tmux `-J` collapse the whole screen and erase every `┃`/`╹▀` boundary. Those composer-scoped id checks remove ANSI and whitespace after parsing, so ids split across physical rows still match. Ordinary sentinels follow the bounded frame-transition loop above; controls retain the prior Enter sequence. One AGY repaint has narrower evidence than generic submit uncertainty: when the exact injected sentinel was positively observed, the next pre-Enter frame is `changed`, and the attempt has sent zero Enters, the direct courier parks that already-injected sentinel as `pending-input` for the standard 30-second bounded re-probe. The re-probe must match the full staged sentinel after AGY renderer padding and visual-wrap normalization and submit in place without reinjection; its generic possible-effect marker continues to exclude it from digest batching, and only the per-id drain consumes the narrow recovery authority. `--no-spool`, unbound relays, every post-Enter change, and every other harness retain terminal submit-unverified behavior. Its sender receipt says `injected; Enter pending re-probe.` rather than describing a possible Enter effect. Mixed content or unreadable geometry returns `5` without another keypress → verify the input region cleared (neither the id nor a latched chip remains). Id checks normalize ANSI and whitespace so a tmux-wrapped sentinel id still verifies correctly. The optional `exact` mode is reserved for short allowlisted control input that cannot carry a marker: it requires a visible active prompt, forbids queue-prefix and transcript-wide proof, matches the whole active input exactly, and disables paste-chip fallback. A paste-collapse chip observed by the **pre-inject** pending-input probe is ordinary pane-owner text: it is backed up and cleared, never auto-submitted; if it persists after bounded C-u attempts, TAP exits `5` without injecting or submitting it. Chip provenance is temporal: the immediate sample blocks a human chip that arrives after the earlier pending-input classifier, but cannot distinguish a separate paste simultaneous with the injection itself. Only a chip latched as that injection's landing proof can extend the post-Enter **retry loop**; an unlatched human paste in that window gets no retry Enter. **Scope of the fresh-composer guard (tap-7r3fn.81):** fresh marker-bearing calls pass the full expected input to the shared submit helper. Pre-v0.23 sentinel recovery and markerless `exact` controls retain their prior submission checks; nudge of current wire uses the shared visible-text decision. A glyph-less Hermes landing observation alone does not establish a readable full composer, so fresh submission refuses with `5` if the composer geometry remains unavailable. Paste-chip provenance remains temporal; the final capture and keypress are separate tmux operations and cannot exclude typing between them. Digest submission additionally refuses any nonempty draft observed by the shared pre-inject classifier (`4`), without backup, clear, or inject. Reverse-video cursor paint alone does not classify a one-character draft as placeholder chrome; actual dim hint content must corroborate that classification. Exit: `0` submitted+cleared | `3` pane-gone during inject/submit | `4` deferred | `5` inject-miss or submit-unverified; bound callers also consume internal identity refusal `6`. **`4` has three defer reasons (tap-r49z, tap-7r3fn.14):** `lock-park` — a concurrent submit held this pane's submit lock past `TAP_PANE_SUBMIT_LOCK_TIMEOUT`, transient, retry shortly ; `no-prompt` — the submit path lacks a safe prompt; and `booting` — OpenCode has not drawn its composer, so send no keys and wait. The number stays single because `4` is the courier's documented defer → spool path and renumbering would move a contract every caller reads for a message-level benefit; a caller that must tell a human WHY reads the result's status and detail: `lock_busy` is the lock-park, the band/copy-mode holds are no-prompt, and the booting hold names itself. The Bash-era shell variable `TAP_SUBMIT_DEFER_REASON` and its bare-call rule retired with the Bash submitter (R4). Consumers include `/tap:self`’s deferral messages and the courier’s OpenCode startup classification. **Named residual, not a design choice:** the courier's own spool taxonomy still collapses the two. `tap_send_defer_reason` (`tap-send.sh`) preserves `booting` and copy-mode, but a courier lock-park still enters the spool under the `no-input-prompt` label — the same lie this split ends one layer up. It is left alone HERE deliberately (changing the spool's reason vocabulary while tap-w4f7 is diagnosing the drain would make that lane's evidence unattributable, which is the same argument that kept rc 4 a single number) and tracked as tap-7eq8. It verifies exactly "transport accepted the input and cleared the input region" — never "the agent processed the message." **Settle-delay scaling:** every fixed TUI-settle pause named above (the 0.5s second-Enter beat, the ~0.15s redraw/retry waits, the C-u and copy-mode settle beats) is a *default*, applied through one settle helper and scaled by `TAP_TUI_SETTLE_SCALE` — a plain decimal in `[0.01, 10]`, default `1` (byte-identical to the historical literals). Values outside that shape or range warn once per process and run unscaled — fail-safe to production timing (the scale math runs under `LC_ALL=C`, so locale decimal commas cannot abort a courier mid-settle). A *valid* non-1 scale announces itself once per process on stderr: the knob exists for smokes against the synchronous mock tmux (they set `0.1`; a mock has no redraw race to wait out), and a smoke scale leaked into a live sender's environment must be audible, never a silent shrink of the tap-dl3 beat — production runs unset/`1`. Timeout *semantics* — e.g. the watch evaluator deadline — never route through the settle helper: scaling can stretch or shrink courtesy waits, never reorder a timeout race.
