The native Bun runtime emits twelve base keys on every row — `handle`, `harness`, `pane`, `status`, `status_reason`, `agent_state`, `agent_state_reason`, `attached`, `unattended`, `crew`, `digest_window_seconds`, and `ask_window_seconds`. Forced or fallback Bash emits the ten base keys without `agent_state` or `agent_state_reason` and does not capture panes. On native rows, `status` and `status_reason` retain their registry/lifecycle meaning; `agent_state` is a separate one-shot observation with the closed values `working|blocked|idle|waiting|booting|overprint|unknown`. **Roster activity (tap-i5fzq):** the roster and `tap health` enrich the shared classifier's answer; delivery, submit, compact and readiness readers keep the native classifier. Each change needs positive evidence. An `idle` seat that still owns background work that will wake it reads `waiting`, and its `waiting_on` array names the work. Three kinds count: `{kind:"shell",count}` from the Claude live footer's `N shell(s)` (the `← N agents` count is painted on every seat and is refused); `{kind:"terminal",count}` from Codex's `N background terminal(s) running · /ps to view` chrome row, counted only below the latest `Worked for` row (the same words above it are transcript); and `{kind:"compute",id}` for a queued, offered or running compute job whose `notify_done` is this `<team>/<handle>` and whose identity `pane_id` is this seat's current pane. A requester alone is attribution, not a wake. The reason is `background_shells`, `background_terminals` or `compute`. Working, blocked, booting, overprint and unknown are never upgraded to `waiting`. Each row also carries the pane's dating evidence as ISO-8601 UTC or null. `turn_started_at` dates a working row from its elapsed clock. `turn_ended_at` dates an idle or waiting row, and `turn_ended_source` names the witness (`transcript`). That is the time since the turn ended, not entry into the current state. Only a record carrying its own timestamp for this turn's completion may supply it: readiness-stall's `harnessEvidence(...).at` (Claude end_turn, Codex task_complete, OpenCode completed), and never through a Codex transcript whose session does not match the binding. A footer clock (`done 12:05 AM`, `Worked for … • 6:00 AM`) has no date, and a transcript's mtime is a last-write time that a background event can move, so neither dates a turn; without a record the field is null. The human `state` column appends the compact age (`● waiting 12m`). A matched screen rule names its rule id in `agent_state_reason`. Failure to establish a positive screen state fails closed to `unknown` with `no_matching_rule`, `unrecognized_harness`, `no_pane`, `lifecycle_unreadable`, `lifecycle_inactive`, or `capture_failed`. **Claude agent state heuristics (tap-ulm25):** `idle` requires a live bracketed input band (top rule matching `─{10,}(?:\s+[^─\n]+\s+─+)?`) whose prompt row contains only `❯` plus whitespace/NBSP (empty input band; typed drafts fail closed to `unknown` with `no_matching_rule`), `working`/`spinner_working` is a live spinner (`✢ Crystallizing… (8m 57s · …)`) as the nearest column-0 row above the band (tap-7txco; current Claude Code no longer paints `esc to interrupt`, still matched in the live footer), and `blocked` matches tool permission dialogs (`Do you want to proceed?` with yes/no choices) within a 15-line modal window. **Codex agent state (.165):** a braille spinner (U+2800–U+28FF) at the start of the observed pane title means `working`/`title_working`, unless a live permission rule says blocked. A `Working … esc to interrupt` row among the last four nonempty rows before a recognized painted idle placeholder also means `working`/`screen_working`, even without a title spinner. A `Messages to be submitted after next tool call` block with queued items immediately above that placeholder is also a working cue, allowing only blank or decorative Braille padding after the items; live permission rules still take priority. Idle requires the dim-painted `Ask Codex to do anything` prompt placeholder, proving an empty composer. Decorative Braille before or after that exact hint, including beside the prompt glyph, does not defeat recognition; dim paint still distinguishes the hint from typed lookalikes. Typed drafts and unpainted placeholder words do not establish idle state. Idle detection requires no status-line grammar; the status line may be customized or absent. A later prompt-like row supersedes an older placeholder, so ambiguous rows cannot hide a typed draft. Codex captures retain ANSI styling and read the title from the same immutable pane id before the post-capture server-generation check; a nonzero title-query result fails closed as `capture_failed`. **agy draft (tap-aimey):** agy hides its `? for shortcuts` idle cue while its composer holds text. A composer holding a TAP wire with no working or blocked cue is `unknown`/`sentinel_unsubmitted`, never `idle`, because idle licenses control injection. The human projection shows it as `● unsubmitted`. Any other agy draft stays `unknown`/`no_matching_rule`. Only supported, lifecycle-active, pane-backed rows are captured; a capture is accepted only when a post-capture server-generation check still matches the batch snapshot, otherwise it is `capture_failed`. This keeps pane-less, inactive, restarted, and unobservable rosters bounded and does not turn agent state into an injection-safety claim. Five more fields are conditional preset-provenance fields, and their conditions differ — they are NOT a single group gated on joining a catalog preset: `preset` whenever provenance resolves at all, whether read from the seat's record or matched from its handle; `preset_inferred` only for a handle-derived match (no record); `preset_absent_from_catalog` only when the record names a preset the current catalog no longer defines — the record still wins, and the flag says why no roles or metadata came with it, so this key appears precisely when the handle does NOT join a catalog entry; `metadata` only when a catalog entry resolved AND carries metadata; and `preset_catalog_unavailable` only when the catalog could not be read at all, which is never simultaneous with `preset_absent_from_catalog` — that one asserts the catalog WAS read. The recorded-but-uncatalogued case emits `preset` and `preset_absent_from_catalog` alone — never `preset_inferred` or `metadata`. `status` follows the shared lifecycle classifier (`active`, `unbound`, `gone`, `offline`, or `unknown`, with stored non-active states retained where applicable); poll rows are not probed. `attached` is `#{session_attached}` for pane-backed seats and empty for poll rows; it is a human-presence signal, not liveness. The native default human projection reuses this bounded observation as its lossy `status` cell (`● <label>`), but the JSON bytes and schema do not change; `--all`, `--names`, and crew projections do not observe agent state.
- `team refresh [--hard] --json` → object with `trimmed[]`, `skipped[]`, `kept[]` (local team only). Hard-trimmed items additionally carry `harness` and `last_status`; `reason=hard_session_absent|hard_session_missing` records the liveness-guarded cut. Item order within each list is code-point handle order. The strand `WARNING` rides stderr in this mode too, so stdout stays a single parseable object. A refusal in `--json` mode is itself an object on **stdout** (`{"ok":false,"error_class":...,"action":...,"detail":...}`), not a stderr line — with two exceptions, both raised in the window before flags are parsed and therefore always human-form on stderr: the mid-reset refusal, and `registry_unreachable`. The second is the acting-registry guard, which refuses a bus decoy, a live v0.20 flip marker whose enrolled `registry_location` does not exist, AND one whose location exists but is not a regular file (a directory passes an existence test and fails `[ -f ]`, so both runtimes require a regular file; a symlink TO one is accepted, since `[ -f ]` follows); an unreachable acting registry is never reported as an empty roster, because a `nothing to refresh` receipt would claim a reconciliation that never reached a registry. That refusal is labelled `tap team`, not `tap team refresh`, in both runtimes: the incumbent raises it from its team-context resolver while the parent verb is still current. String values in the success object are ASCII-escaped (`caf\u00e9`), matching the incumbent's `json.dumps` default, so runtime selection does not change the receipt's bytes for a non-ASCII handle, session, or pane. The native implementation adds one refusal the bash one cannot produce: `error_class=registry_lock_busy` when the registry lock is not acquired within its timeout — distinct from `registry_invalid`, which asserts the registry was read and is corrupt, and whose `repair_registry` action would be wrong advice for a subprocess that never produced a verdict. Two further classes once completed that trio: `roster_unrunnable` and `trim_unrunnable` (action: retry the refresh) fired whenever the registry reader or writer could not be USED — it could not be run, it was killed, or its output was truncated past the registry-scale buffer, states that were one state because each left the same nothing behind. Both followed their python children out of existence as the M3 port moved the trim and then the read in-process: a class with no child left has nothing to refuse for, and the retry-not-repair distinction retired with the spawns it defended. Bash blocks indefinitely there; the native runtime refuses rather than writing from an unserialized snapshot, because a trim is a read-modify-write against a file concurrent registrations also mutate.
