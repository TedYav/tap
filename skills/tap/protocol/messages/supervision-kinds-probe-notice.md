## Supervision kinds (probe, notice)

Three `kind` values are reserved for the supervision layer (`tap watch` and `tap goalie`, the per-team pane-less sidecars). They are **new values in the existing `kind` field, not new machinery**: settlement still follows each envelope’s `reply`, while reserved supervision kinds have explicit sender and delivery-window rules (§Envelope). The `kind` field is the protocol-number slot — the ICMP move: a supervisor stamps `kind=probe`/`kind=notice`, the recipient handles the payload like any other, and payloads + receipts on the bus are the audit trail for free.

- **`kind=probe`** — a liveness or judgment poke sent to a possibly-wedged seat. The watch template (`watch-templates/probe.md`) says to settle first, report only a blocker or credible run completion, then **resume the existing work order** — the probe reassigns nothing and is **not a stop order** (tap-hhg). The blocked-seat resume nudge (`watch-templates/continue.md`) carries the same settle-then-resume shape. The goalie template (`goalie-templates/judge.md`) is likewise settlement-first, then asks the fixed `goalie verdict` endpoint for one closed-enum judgment. None creates a reply obligation to the pane-less watcher sender.
- **`kind=notice`** — a one-shot supervisor action: watch state changes to the armer, a goalie verdict's fixed corrective wake / unsure wake-lead, or a goalie rung-2 reminder naming the original unanswered wake. Watch notices use `watch-templates/notice.md`; goalie notice bodies are fixed in code. Model-authored text is never interpolated into either.
- **`kind=progress`** — a settle-only watch advisory with two producers. **Context pressure:** to an idle seat whose gauge crossed its threshold, sent with a wake; the fixed body tells the seat to preserve its standing brief and clear only if it is idle with no unfinished review or unsettled ask, and otherwise to defer. It is a conditional advisory, not a work assignment. **Codex livelock:** to the armer, one NOTE per seat/payload pair when the seat sent an outbound after the aged ask, held for the courier digest with no wake or human-notify fallback (§Codex livelock advisory). Supervision excludes `progress` from work-activity and pending-work clocks.

**Always `settle-only`, always the reserved watcher sender.** A supervisor script has no registered pane, so it cannot receive a reply; `tap send` allows the reserved `watcher` identity only for `kind=probe|notice|progress` with no reply obligation; `--ask`/`--expect-reply` refuses, and `--fyi` is the accepted older spelling of that settle-only default (tap-7rpf0). The recipient handles a probe/notice **exactly like any settle-only payload**: use `tap read` to read and settle the body, then act per the body, and do not send a got-it. Settlement records only that the seat *saw* the ping — **never** that it resumed work; resumption is a separate observable (new non-supervision bus traffic), so a seat that settles a probe and does nothing does not reset its own escalation.

**The scoped directive rule (choreography, not transport).** The liveness rules (`/tap`) state: *a directive never rides an ordinary settle-only message* — settle-only declares "no reply owed", and a directive needs a tracked obligation. `kind=probe`/`kind=notice`/`kind=progress` are the **sanctioned exception**: their bodies are mechanical, self-contained, and defined here, so they carry an instruction without the ambiguity an ad-hoc settle-only directive would. This is a choreography convention enforced in review, **not** a courier check — TAP validates shape, never meaning.
