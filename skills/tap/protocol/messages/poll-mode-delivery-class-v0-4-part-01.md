## Poll-mode delivery class (v0.4)

A registered member with `delivery: poll` (§Registry) participates in every bus mechanism except pane injection. The class exists for daemons — the canonical consumer is the hermes gateway (launchd, no tmux pane) bridging the bus to the human's phone.

**Delivery = the durable write.** `tap send`/`tap reply` to a poll member canonicalizes, stamps, and validates exactly as for a pane member, then **stops after the payload write: exit 0 with `status=queued,delivery=poll`; no injection, no sentinel, no defer**. Courier deferred auto-settlement (§Reply expectation) never applies to this class: there is no wake to defer, the canonical stays in `payloads/` where `tap poll` reads it, and the recipient settles it itself as it does today. The classify/denylist gate is bypassed — `delivery: poll` in the registry is the authority, decided at register time, never inferred at send time (a registry that accepts a member send will refuse is lying). Send exits `3` and `5` are structurally unreachable for poll targets; public send exit `4` is retired for every target in v0.7. **An explicit `--pane` addressed to a poll member is refused** (`error_class=poll_mode_member`, exit 1, no payload written): `--pane` names the *recipient's* pane and a poll entry omits `pane`/`pane_id` by construction, so the flag can never name anything — the same refusal registration already makes for `--delivery poll --pane`. The refusal is a property of the delivery class, so it precedes the row's status checks rather than varying with them, and it reaches `tap reply` too, which forwards `--pane` to send. Before this rule the override survived into the locked placement recheck, where it compared against the absent field and surfaced as `forwarding_changed` with next step "retry the send" — a permanent condition wearing a retryable error.

**Receive = `tap poll`, on the member's own schedule.** The poll floor plus a startup `tap poll` scan (catching payloads written while the daemon was down) is the delivery guarantee. `tap poll` exits `0` whether or not items are pending, so the output (or `--json` `pending`) is the signal; `--quiet` only omits the empty line; `1` is usage.

**Team-local only; enroll per team.** A poll member is a member OF a team's bus; a **team-qualified send to a remote poll target is refused** (`error_class=poll_member_remote`, action naming the fix: register the member on the sender's team). Rationale: cross-worktree relay (§Cross-worktree relay) keeps the canonical payload on the *sender's* bus and delivers by sentinel injection — a poll member never receives injection and polls only its *own* team's bus, so a remote poll send would be durably written where the target never looks. A daemon serving several teams (the gateway) registers as a poll member on **each** team, and its poll loop iterates its enrollments (the marker-selected global registry maps each enrolled team to its root). This is deliberate opt-in per team, not auto-enrollment.

**Bus anchor for pane-less callers (`--team`).** A poll member's own verb calls (`poll`, `read`, `reply`, `send`, `outstanding`) cannot anchor the bus by cwd — a daemon's cwd is meaningless (the launchd `~/.hermes` mis-landing). These verbs accept a global `--team <name>`, resolved to the team root via the machine index — the same resolution `register --team` uses; `TAP_HOME` env remains the lower-level override. Rule: **for a pane-less caller, bus identity comes from `--team` (or explicit `TAP_HOME`), never from cwd.** Recipe: register once with `tap register <daemon-handle> --delivery poll --team <team> [--unattended]`, then send with `tap send <to> --from <daemon-handle> --team <team> -f <path>` (or `-f - <<'EOF'`). Pane members keep cwd anchoring, but the read verbs below refuse when that derived anchor cannot be grounded.

**Caller-team selector (Stage 0, tap-1t0h.1).** One Bun library (`runtime/bun/src/selector.ts`) is the selector authority. Native `context.ts` consumes `selectCaller` for caller-bus resolution on verbs that already go through `resolveContext`. Native `poll --team` shares the existing pane-less override and then selects the root-derived bus; other `--team` forms remain Bash-owned on the router. No production caller yet passes a qualified target, a mutation lock, or a detached child into this module. Native send/reply never delegate to Bash on the marker; the operator rollback file can still keep either verb on Bash. `selectTarget` / `assertSelectionCurrent` / `validateChildSelection` are unwired capability. **An absent machine marker (no `global-registry.json`) refuses `unanchored_bus` before any selection, with action `tap init  OR  tap session launch`**: every install and first launch is born live, so there is no pre-flip bus route. Caller axis: explicit `--team` wins; else a canonical-realpath cwd walk takes the nearest enrolled ancestor within the current Git checkout, including its root (outside Git the walk has no checkout boundary). An enrolled parent above that boundary cannot capture a child repository or linked worktree. SessionStart root discovery uses this same Stage 0 selector, requires cwd enrollment, and keeps silent for unenrolled linked roots; it never uses TAP_HOME or pane anchoring to infer enrollment. The existing pane-anchored messaging fallback is unchanged. At each eligible level, enrolled+readable wins; enrolled+unreachable or ambiguous refuses at that level and never walks outward; `TAP_HOME` is consulted only when that walk finds no enrollment, and is never an explicit selector. When that fallback has no `TAP_HOME`, the bus is derived from the git toplevel of the cwd (`repoRoot`), not the exact cwd — a subdir invocation must not select `<cwd>/.tap/bus` beside the repository bus. The enrollment walk itself still uses the exact cwd. A live marker with no enrollment and no `TAP_HOME` refuses unless a real bus registry file is present — it never succeeds with an empty registry path. An unindexed custom bus under a live machine marker is `authority=bus` and is revalidated against that file, not through `global-registry.json`. Its root is the bus-derived root (the bus parent, or the parent of a `.tap` bus directory) unless that root is unenrolled and the bus registry's own `team.worktree_root` names an existing absolute directory; then the stamp is the root, because registration stamps the caller's worktree there and reads it back as the team's bound root (tap-3vvf5). An enrolled bus-derived root never consults the stamp; an old-format bus registry refuses `old_store` before its stamp is read; an adopted root still meets the enrollment checks below; and a bus-authority lock recheck refuses `team_moved` once its root directory is gone. When the cwd walk finds no enrollment and `TAP_HOME` names a bus whose derived root is enrolled, the env bus must equal that team's acting bus or the selector refuses `bus_not_acting`. A pinned root probes `enrollmentAt` at that exact directory — no ancestor walk and no TAP_HOME fallback. Target axis, same-axis conflict, lock-held recheck, and detached-child comparison are library capability, not shipped write-path effects: `team/handle` is explicit; a bare handle, or a qualified address whose team equals the caller, reuses the caller root/registry; conflicting explicit selectors on the SAME axis refuse (`selector_conflict`); `send --team X Y/h` is caller X to recipient Y and is not a conflict; a mutating command **can** recheck the pinned `(team, root_real, registry_location)` under the branded `RegistryLock` minted by `acquireRegistryLock` (the index-recorded acting-registry path as given — mixed Bash/Bun writers share `${literal}.lock`; canonical realpath is equality only — never the `.lock` sidecar) from one parse of `global-registry.json` for every enrolled pin plus one parse of the acting file (`team.name` and `team.worktree_root` when present); detached children **can** carry `--team` or a pinned root, and the parent **can** compare returned team, canonical root, and registry identity (source may differ). There is no `TAP_TEAM` pin and no second Python authority. Remaining Bash/Python callers (`tap_apply_team_override`, `tap_resolve_team_target`, launcher `_team_bus_home`) are deferred inventory, not a second authority.

The selector derives an enrolled team's bus from its root (`bus_home`), never from `registry_location`; the literal remains the lock identity, as required by the target-bus fence rule under Session relaunch.

**Grounded empty reads.** A cwd-derived `tap poll` or `tap outstanding` may report exit `0` empty only after the acting registry resolves. When it does not, the verb refuses with exit `4` before `Bus.ensureDirs`, so an unenrolled worktree cannot be materialized into a phantom bus and then mistaken for an established empty one. Exit `4` is deliberately distinct from these verbs' existing result/status codes: poll and outstanding use `0` for any listing, empty or not, and `1` usage/integrity; peek uses `0` success, `1` usage/identity refusal, and `3` pane gone. An indexed caller pane receives the existing `cd <team-root> OR pass --team <team>` remedy; a genuinely unregistered but observable pane receives the registration door. `--team` and `TAP_HOME` are explicit bus assertions and bypass this check; in particular, registry-less scratch buses selected with `TAP_HOME` retain the ordinary exit-`0` listing contract. `tap peek` guards before `Bus.ensureDirs` too and uses the same indexed-pane diagnosis, with only its executable `cd` door; when the caller pane cannot be observed, it refuses without inventing a registration command.
