- The predicate reads **body bytes with any leading frontmatter stripped**, so envelope metadata (an `id:` line) can never supply the bead-id half on a positional payload.
- Both conjuncts are required. A bead id alone is ordinary status prose; a `## Plan` heading alone is ordinary writing.

- NOT exempt: `--fyi` (a no-op alias of the default, and the flag reached for by habit) and `--wake` (the five sends in that observed case were `--wake` sends).
- "Before any durable transport effect" means the refused send creates no canonical payload, receipt, or spool entry. A transient `-f -` staging file may already exist and is cleaned. Send never drains queued mail, whether accepted or refused (§Spool).
- **"Could not tell" never licenses the send.** The predicate is a Bun decision (`slices/order-shape.ts`) that the native send door calls in-process on the source it already holds. It has no "could not classify" outcome: an exception there fails the send loudly with a non-zero status and no canonical, and never reads as not-shaped. A negative verdict that licenses an action must come from an instrument that can refuse. (The retired Bash door called it as a child process and accepted only an exact stdout token, `order-shape:shaped` or `order-shape:not-shaped`, refusing anything else with `error_class=slice_failed`; the incumbent inline classifier before it exited 1 both for "not an order" and for a failure to read the body, so a classifier that could not run sent the message the guard exists to stop.) Sends the guard does not apply to (the exemptions above) never consult the classifier. The door judges the staged source (`-m`/`-f`: the synthetic empty fence then the body bytes; a positional file: its bytes before any wrap).
- **String semantics are the incumbent's.** Line boundaries follow Python `str.splitlines()` (LF, CR, CRLF, VT, FF, FS, GS, RS, NEL, LS, PS), fence lines are compared after a Python `str.strip()`-equivalent strip, the bead-id boundary is Unicode-aware on both sides, and a heading's leading indent uses Python's `\s` set. These are the contract because each one, transcribed into JavaScript's defaults, produced a verdict the incumbent did not — in three of four cases in the direction of licensing a work order as a note.

### Courier deferred auto-settlement (tap-31it)

**Retired for new sends (.96, 2026-09-06).** A plain send is a note with `reply=settle-only`; its recipient settles it with `tap read`. An ask requires `tap reply`. The courier never writes `.done`, including for already parked legacy `policy=autosettle` entries. Existing recipient or historical courier receipts remain immutable.

A bare composer receives an ordinary note or ask immediately without a flash, unless existing queued siblings need one shared delivery. A human draft receives one 30-second grace: green at park, red in the final 10 seconds, then the existing backup/clear/submit recovery. An urgent draft has a 10-second grace and an immediate red warning. Uppercase WAIT grants one snooze per draft for all mail, lasting up to two minutes or until confirmed empty after submission. Positive queued-followup evidence holds ordinary delivery without a flash until that list clears. Explicit interrupt delivery is immediate for a bare composer; it respects draft grace, WAIT, identity, copy-mode and clear-fence gates. A footer advertising “tab to queue” is not queued-input evidence.

`--wake` remains accepted as a compatibility spelling for a recipient-settled note; all new notes already have that settlement rule. It changes neither arrival nor the order-shaped-note guard. `--fyi` remains an alias of a plain note. Explicit `--polite`, safety holds, unbound relay and `--no-spool` contracts retain their own boundaries.

Already parked entries keep their stored windows and remain deliverable. Ordinary N≥2 coalescing remains; legacy autosettle entries may still use their existing N=1 digest path. Neither delivery path settles an item. `tap read <digest-id>` records the envelope's `.read`; items require their own reads/replies, or `--all` to read every body. Reading the envelope alone never settles its items.

### Public `tap done` retirement (tap-7r3fn.6)

Since tap-7r3fn.69, public `tap done` is a non-mutating tombstone. For every argument shape it exits 1 with `error_class=done_retired`, one line naming the replacement (`tap reply <id> --by <you> -f <file>` for an ask, `tap read <id>` for a note), and `effect: none`. It reads no bus, registry, pane or reset fence, settles nothing, and writes no receipt and no audit row. `tap help done` explains the tombstone and the verb is absent from help listings and completion.

The release window opened by tap-7r3fn.6 closed with the v0.23 version line. The retained `receipts/done-alias-hits.jsonl` logs and the counter `python3 skills/tap/scripts/tap-done-alias-count.py <log> --since <ISO-start>` stay as evidence only; nothing appends to a log, and a missing log is unavailable evidence (counter exit 2), never zero use. The private settlement primitive in `verbs/done.ts` stays live for `tap reply` (`via: reply`, with its evidence fields); the retired public door never reaches it.

### `tap reply` settlement (R6/AE6)

`tap reply <id|path>` composes the courier and settler over their exit codes and settles the inbound **only after the outbound is durable**:

If the inbound is `reply=settle-only`, `tap reply` prints a warning but does not refuse; corrections stay legitimate. If the original sender is registered `unattended`, inbound replies are refused by default unless the caller passes `--allow-unattended`. That unattended refusal is local-team only; cross-team replies cannot inspect the foreign sender registry and rely on the payload's `reply=` contract.

- send **exit 0** with `status=injected|queued` → outbound durably accepted → settle the inbound. `queued` covers both courier spool and poll delivery; it is not described as injected.
- send **exit 5** (submit-unverified) → the outbound canonical is queued on the bus (durable) → settle the inbound, render reply-owned prose that the outbound could not be confirmed, and exit 5 so the outbound stays visible in `outstanding <me>`. `tap reply` consumes send's frozen PC14 JSON internally; it never re-emits send's default text or k=v fields.
- send **exit 1/3** → no durable outbound → the inbound is **left unsettled** (the sender's `outstanding` still shows it); the error line names the recovery. A bare `done` is never sanctioned here.
- send refused **because the addressee has left** (a same-team sender whose registry row is gone, a departure tombstone exists under team-history for the sender's handle — and its `sender_instance` when the inbound carries one — and there is no forwarding successor; `--progress` never qualifies) → the outbound is placed, archived under cancel's convention, and given a `.cancelled` receipt (`via: cancelled`, `reason: seat_unresolvable`, `target_status: gone`) instead of being delivered or queued; the inbound settles and `tap reply` exits 0 with a `recorded` receipt line naming that the sender will never read it. The predicate refuses on unknown: an unreadable registry or history, a row that re-appeared, a suspended sender, and a revoked or ambiguous forwarding edge all keep the ordinary refusal. Foreign-team senders are out of scope. If the record's own custody write loses a reset race, the outbound stays placed rc 5 and `tap cancel <id>` retires it.
