# Watch layer (`tap watch` — the supervision sidecar) — source part 2 of 4

> Normative TAP v0.23 source fragment. Search the group index for adjacent parts.

**2026-09-22 spool pass:** The Bash spool-pass retention described below is
superseded. `spool-watch.ts` owns lease admission, the native drain call and tint
reconciliation. The tick passes its snapshot and watcher-only human-alert fact as
data. Retained callbacks and reowned waiters receive an environment without those
caller-only facts, including when the caller carried ambient exported values.

The loop awaits the tick, and the tick awaits the spool pass. INT/TERM/HUP latch
stop, unwind the owned child chain, and return the existing watch stop status 0
with the lease retained. Immediate-parent loss closes a private lifetime pipe and
stops the child in the same way. A stopped invocation performs no later queue-claim,
probe, notice, lease update or next tick. The persistent watch outlives its launcher;
the lifetime pipes apply to its foreground children. Abrupt KILL may trigger cleanup
in surviving descendants; it does not mean the killed process ran cleanup.

**Verbs.** `tap peek` has one native command owner (`runtime/bun/src/verbs/peek.ts`), used by both public entry points and both watcher transcript consumers. Watcher calls retain a subprocess boundary for their explicit environment and bus; peek's pane identity, paired capture and transcript read are native as well, with no Bash hop. The verb layer (`on|pause|resume|off|status|ack`) is native (`runtime/bun/src/verbs/watch.ts`), reached identically through `bin/tap` and the root `scripts/tap.sh`; `tick` is native too (`runtime/bun/src/watch-tick-run.ts`: the one pure evaluation over bus, repo and injected clock — the arm snapshot, the roster prefetch through the team observation door, the blocked-seat pass, the four detectors under the harness census, the spool pass, the queued-probe transition under the spool claim, the pause gate, the repo and bus activity clocks, the silence floor, the episode ladder, the rung, the exhaustion gate, the probe courier and its receipt), reached in-process from the `tick` arm and as a child of the sidecar loop; `run` is native too (`runtime/bun/src/watch-run.ts`, the entry, and `watch-loop.ts`, the loop): while the lease exists — refresh the sources, stamp the heartbeat (the file's mtime is the injected clock, `heartbeat_at`/`watcher_pid`/`watcher_command` in the record), run one tick as a child whose status is not the loop's, shorten the interval to the next reminder when a queue exists (a queue the loop cannot read — not JSON, a JSON root that is not an object, a refused lock path — is announced by the loop on one `tap watch:` line naming the file and the reason, and the loop sleeps the record's own interval and goes on: the reminders wait, the watcher does not end, and the next tick heartbeats again; the tick child's own reminders pass refuses the same queue first and says so on its own line, so a cycle over an unreadable queue prints two lines, one per door; `tap remind list` reads the queue through the same helper and refuses with the same reason; an injected clock the door cannot read is not a queue and still ends the loop with 1), sleep; the lease's absence ends the loop with 0, as does INT/TERM/HUP, and the lease stays for `tap health` to report. The record's `tick_interval_seconds` is read in the one grammar the two doors that write and consume it share (a positive integer, `--interval` and remind.ts's parser): an empty field is 60, anything else is announced on one line and slept as 60 — the Bash loop handed the raw text to `sleep`, which made a non-number or a zero a tight loop and, with a reminders queue present, made a decimal end the loop with the lease armed. The tick has one status semantics in both callers: a maintenance door that fails — a reminders finish, the blocked pass, a detector, the spool pass, a notice or a notification — is reported by that door's own `tap watch:` line and the tick goes on and exits 0 (the `tick` verb no longer dies at the first failed door); the tick exits 1 only when the reminders fire fails, when the record holds a value it cannot read as a number where it must compute one (`TAP_WATCH_NOW`, `current_rung` — one line, no side effect, the sidecar loop survives), while a non-integer in a compared field (`threshold_seconds`, `probe_timeout_seconds`, `episode_started_at`, `carried_probe_at`) is announced on one line and compared as false, as the shell's `[` did. The spool pass stays Bash behind one adapter call until the native drain lands: the human-alert fact and the tick's snapshot travel as arguments into a child shell that drops the ambient names first and holds them unexported, so a detached waiter the drain spawns never inherits them. The bus activity clock (`tap_supervision_bus_activity`) is native for the tick (`watch-detectors.ts`); the goalie keeps the Bash reader until its own closure. The tick's four pane detectors — context pressure, codex livelock, codex context-freeze, opencode wedge — and their per-seat sample maps (`context_pressure`, `livelock_alerts`, `livelock_samples`, `context_freeze`, `opencode_wedge`, the `blocked_map` steps) run natively too (`runtime/bun/src/watch-detectors.ts`, `watch-detect.ts`), called by name from the tick with the tick's own roster cache, bus and acting registry passed in; the maps keep python's bytes (insertion order, exact integers, the separator style each writer used). A detector's seat-state and pane-liveness reads stay on the Bash classifier through one adapter until the native pane reader lands. The detectors have one failure semantics in both calling shapes (the sidecar loop and the `tick` verb): a corrupt sample map in the record — unparsable, or not a JSON object — is announced on one `tap watch:` line naming the field, the reason and the reset, its bytes are kept (in that line when they fit in 200 bytes, else in `arm.json.corrupt-<field>-<now>` beside the lease), and the pass runs from `{}` and writes the map it computed back over it — never a python traceback, never a silent heal, never a detector that fails every tick on its own record; a pane whose capture fails is skipped for that pass with its sample forgotten (never a sample of a frame that was not read); a notice or notification that could not be made durable ends the detector with status 1 and no sample write, so the next tick retries it rather than recording an alert nobody received. The blocked-seat timer pass (`_watch_process_blocked`: the per-seat fire time, the recovered/still-blocked/continue-nudge outcomes, the write-before-send transition, the touched handles for the rung skip-set), the blocked-banner classification over a `tap peek` transcript, the reset-clause arithmetic (`<H:MMam/pm> (<zone>)` → the next epoch, python's fold semantics, the runtime's IANA database, the zone in the database's own spelling — `utc` is not a key, whatever the host filesystem would have found), the roster's active-row read, the activity floor, the rung skip-set and real-wedge sets, the exempt check and the probe courier's receipt parse are native too (`runtime/bun/src/watch-blocked.ts`, `watch-tick.ts`), with the incumbent's bytes: a `blocked_map` timer field bash's arithmetic could not read (`None`, a name, a float) ended the pass where it stood and the tick went on with the seats already touched — the port does the same, with one `tap watch:` line in place of bash's; a field bash would have EVALUATED (`1+1`) or a key it would have expanded as a pattern (`a*`) is refused instead. The evaluator rung and the escalation chain are native as well (`runtime/bun/src/watch-evaluator.ts`, `watch-evaluate.ts`): the unsettled-work pre-check, the ≤2/episode budget, the prompt render, the model invocation with its deadline, the verdict normaliser, the lease-nonce guards and the done/blocked/not_done actions, and the live rung order (overrides keep their authored order over probe-worthy seats; otherwise idle seats by recency, the goalie, the terminal seat when itself stopped, then `__human__`) with the identity-based probe cursor. The rung's status is the tick's advisory as before (a failed notice or notification is reported, never an abort); a non-integer `evaluator_calls` in the record — a value only a hand edit produces — is reported as one `tap watch:` line and ends the rung with status 1, where bash's expansion error ended the whole watcher; a model that does not answer within `TAP_WATCH_EVALUATOR_TIMEOUT` (python's `int()` reading, default 30; 0 or less expires at once) is killed and read as no verdict. `tap watch on` is **idempotent for the same goal**: re-running it while already armed with an unchanged `done_when` is a no-op that leaves the live episode/pause intact (it still ensures one sidecar loop — see self-heal). Re-arming with **any explicitly-passed setting that differs** — `done_when`, `--threshold`, `--probe-timeout`, `--interval`, `--evaluator`, `--chain`, `--terminal` — is **refused** (`error_class=already_armed`), naming an escape hatch chosen by the caller: the armer is offered `tap watch off` or `--rearm`; a non-armer is offered `tap watch off --force` and deliberately **not** `--rearm`. A setting the caller did not pass never participates, so a bare same-goal re-arm stays a no-op and cannot clobber a value set earlier (tap-0nzm). `--rearm` requires the caller to be the armer, or `--force` (`error_class=rearm_refused`); the forced path notifies the armer, mirroring `watch off` — re-arming another seat's watch is an authority act, not a shortcut past the refusal above (tap-pqf2). `--rearm` writes a fresh arm record (fresh `armed_at`/`silence_floor_at`, zeroed cursors, stale pause cleared). `tap watch pause -m "<reason>" [--for <N><s|m|h|d>]` keeps the lease armed and suppresses only silence-probe escalation for a default 4h; N is a decimal integer (a leading zero is not octal) and the product is exact; an explicit pause is capped at 7d and warns on stderr when clamped, an oversized N included; pause by a non-armer is allowed but sends the armer a notice. `tap watch resume` clears pause, resets the episode cursors and `silence_floor_at`, and likewise notices the armer when invoked by someone else.
