## Health (liveness, not integrity)

`tap health` is the read-only liveness counterpart to `tap doctor`: doctor validates bus integrity and never reads pane content; health reports observable team state and may call the supervision read adapters (`tap peek`/seat state) for registered seats. It has no side effects: it does not send, settle, register, refresh, retire, disarm, or advance a watch chain.

### Codex livelock advisory

An armed `tap watch` parses a Codex pane's semantic `Working (<elapsed> … esc to interrupt)` timer and crosses it with the canonical bus age of that same seat's oldest unsettled, non-supervision inbound payload. Inbound recipient authority is team + handle: `to` must name the seat, and a non-empty `to_team` must match the local bus team; an empty `to_team` retains legacy handle-qualified behavior. A foreign-team same-handle ghost therefore never ages the local seat's clock. Pane identity remains a separate delivery concern. When both ages meet the arm threshold, watch begins sampling progress. It strips the animated Working line and requires the remaining pane body and that seat's latest local-team outbound payload (canonical or queued in the spool) to stay unchanged for another threshold window while the timer advances. A first observation never proves a stall. Pane progress or a new outbound payload resets the sample; a settled inbound (a regular-file `.done`, or a `.cancelled` when the sender withdrew it) or a non-Working pane drops it. A foreign-team same-handle outbound is not local progress. Only sustained lack of observed progress sends one advisory `notice` to the armer per seat/payload pair. An outbound after the ask instead produces one `kind=progress` NOTE per pair, held for the courier digest with no wake or human-notify fallback. The reserved watcher identity may send this mechanical kind settle-only (no reply obligation; `--fyi` is optional), alongside its existing probe/notice exception. Supervision excludes progress NOTEs from work-activity and pending-work clocks; if progress later stops for the full sampling window, the stalled advisory remains available. Rearming resets both samples and advisory deduplication. Watch never auto-interrupts the pane.

The text report names the resolved bus/rule, unsettled payloads with ages, team seat states, watch arm status (including `armed-but-watcher-dead`), recent supervision traffic (`probe`, `notice` and `progress`), and the registry event tail. Exit `0` means healthy/no attention; exit `2` means the report found attention states (among them an invalid `[injection] behavior` in `config.toml`, the same refusal delivery raises, reported as `injection-behavior-invalid` with the validator's message and `tap doctor` carrying it as an `injection_behavior` warning finding; neither rewrites the config; a `config.toml` that cannot be read, parsed or is not a regular file is not that item and exits `1` instead); exit `1` is reserved for usage or unreadable state errors that follow the structured failure contract (§Structured failures).

Since tap-diagnostics-u1 the verb is native (`runtime/bun/src/verbs/health.ts`, reached identically through `bin/tap` and the root `scripts/tap.sh`; the Bash body `tap-health.sh` is deleted) and the whole call is zero-write: health reads the acting registry AS FOUND — the dispatcher's pre-verb server-restart reconciliation skips it, so a registry the restart hand already parked still carries its recorded evidence. Liveness is judged by the shared native classifier (`observe.ts`) over one census, and a reboot-shaped census counts as attention: when pane-backed seats exist, none is observed active, and the recorded restart evidence is present (classifier restart reasons, or a parked row's persisted `server_restarted`), health reports one `server-restart` attention item first and exits `2` instead of reading a quiet bus as healthy. An unenrolled working directory (`unanchored_bus`) is health's one fail-soft selection case — it renders the cwd-derived/default bus with `registry_present:false`; every other selector refusal propagates.

### Agent reminders on the watch sidecar

`tap remind <seat|me> --in <N><s|m|h|d>|--at <epoch> -f <body-file|->` schedules one settle-only `kind: notice`, `--wake` note on the selected team: the caller's team by the caller-team selector (§Caller-team selector), or `--team <name>`, which selects that team's whole context — its bus (the queue and its lease), its acting registry (the caller's identity and the target's membership), and the runner the schedule confirms. The verb is native (`runtime/bun/src/verbs/remind.ts`), reached identically through `bin/tap` and the root `scripts/tap.sh`; the queue behind it is `runtime/bun/src/remind.ts`. The supervision kind bypasses recipient delivery windows without interrupting an active turn or advancing the work-activity clock. `--every <duration>` repeats it. The caller must resolve to a registered pane ON THAT team — the verified calling pane, never `TAP_SELF` or `--by`; every way that resolution can fail (no tmux, an ambiguous terminal, an unverifiable server generation, an unregistered pane, an unanchored bus) is one refusal, `identity_unavailable`, exit 1, naming `tap in` — and `me` means that caller. `list` needs no identity. The body is read as bytes from the file or from standard input (`-f -`) and stored as the queue's UTF-8 decode of them, a leading byte-order mark included; a body that is empty or only whitespace (a lone byte-order mark is whitespace) is refused. `-f <path>` is checked by operator — the path must exist, be a regular file after following symlinks (a directory, a symlink to one, or a fifo is refused without being opened), and be readable — before the target's membership is consulted; the checks run in the incumbent's order (sub-command, `list`, identity, the reset fence, `cancel`, `me`, the target's spelling, the body, the target's membership, the queue), so an input with two defects is refused for the earlier one. The target must be a row in the selected registry (any status); a selected registry that is gone, or that exists and cannot be read — not JSON, a number outside the supported value domain, an I/O failure — is `registry_unreadable` (exit 1, naming `tap doctor` and the reason), never “target is not registered” (the retired Bash folded both into that answer; rule 19 of the migration charter forbids porting the fold). The reserved watcher sender delivers the note and its body identifies the scheduling seat. `tap remind list [--json]` shows schedule state and occurrence message ids (`--team <name>` lists that team's queue); only the scheduling seat can `tap remind cancel <id>`. Cancellation cannot retract an occurrence already handed to transport. A refusal from the queue itself (a malformed schedule, an unknown or foreign reminder, an unreadable clock, a queue file whose JSON root is not an object — one reason naming the file, the same reason the sidecar loop and its tick give for that queue) is one `tap remind:` line, exit 1.

Command triggers share this queue and sender: `tap remind <seat|me> --when-done '<cmd>' --circle-back <duration> --fallback <seat> [--to <seat>] -f <body>`. They exclude `--in`, `--at`, and `--every`: a repeating time trigger has no child terminal condition. Fallback is a required, different registered seat in the selected team. Admission records the caller's directory and command, then launches one finite Bun custodian which claims the row before spawning `/bin/sh -c`. The caller's environment is inherited; stdin is closed. This is spawn-and-wait, never predicate polling. The child has its own process group. The row retains child/custodian PIDs, a combined output tail bounded to 8192 UTF-8 bytes after decoding, heartbeat, terminal status, exit code and signal. Exit 0 is `done`; nonzero exits and signal deaths are `failed`. Optional `--unobservable-exit <1..255>` maps exactly that child status to `UNOBSERVABLE`, with the declaration named in the payload. The GitHub adapter uses `--unobservable-exit 2`; its argument errors exit 64. Spawn errors and a custodian not observed for 180 seconds are `UNOBSERVABLE`, never evidence that the command failed; lost custody persists that phase so `list --json` agrees with the wake. The finite custodian drains output and records exit even after watching is cancelled or circle-backs stop; neither action signals the child.

A command occurrence fires on every circle-back interval regardless of output activity; completion makes the next existing watcher tick due immediately. Terminal delivery can therefore lag exit by the watcher's sleep interval (at most its configured tick interval). Each occurrence contains the user's body plus elapsed time, last child observation, exit/signal if known, and the output tail. Actual `receipts/<id>.done` files acknowledge circle-backs; injected/queued/placed receipts do not. At the next firing, one settled circle-back resets the consecutive missed count. An unreadable receipts directory announces observation failure without counting misses or escalating. Refused sends count separately as undeliverable, with the delivery error retained; they never claim that the seat failed to acknowledge an accepted message. After three consecutive unacknowledged or undeliverable circle-backs, the next interval sends one notice to fallback and stops circle-backs; one eventual terminal wake goes to each of the original seat and fallback, recording both message IDs and send results; a seat may have been busy rather than dead. The queue remains scheduled only to observe completion or lost custody; it emits no periodic fallback wakes. Every occurrence is claimed before its single send attempt. An uncertain terminal delivery remains unresolved for inspection, never automatically replayed. A fallback notice is attempted once; its eventual terminal wake is a distinct occurrence, not a replay. New running observations may follow an unsuccessful earlier circle-back; these are distinct occurrences counted toward the same three-wake bound. Child exit or lost observation ends wakes independently of seat acknowledgement.

`cancel` retains a command row with status `cancelled`, disabling future wakes but preserving explicit kill custody. Only the scheduling seat can `kill`; it records a request consumed by the live custodian, which sends SIGKILL to its still-owned child process group. CLI success acknowledges the request; `list --json` exposes `kill_sent` and the terminal signal separately. Terminal or stale custody refuses kill rather than signaling a recycled stored PID. There is no timeout, implicit child termination, process census, or kill on cleanup. Custodians publish heartbeat/output every 15 seconds and read kill requests every second. Explicit reset/removal of the queue can prevent later terminal reporting; it still does not signal children. Rows and output remain available to `list --json` after completion, cancellation or escalation.
