**Team-bus component fates (v0.19 — supersedes the keep-registry / parked-preserve / warn-preserve table).** `tap team reset` declares an explicit disposition for every known top-level bus component and **refuses** (`error_class=unclassified_component`) when any other top-level name is present — clean-team claims forbid warn-and-preserve. The authority is `runtime/bun/src/team/reset-components.ts` (checkpoint copy, inventory, live cut, and restore validation all derive from it — no parallel hardcoded fate loops). Optional 4th column `scope` is `bus` (default; live under `$TAP_HOME`) or `acting` (live at `<root>/.tap/<name>`, sibling of bus/ — tap-epb0). Both scopes archive under `$BUNDLE/bus/<name>`. Checkpoint (copy-verify into `archive/team-reset/<bundle>/bus/`, then remove live): `payloads/`, `receipts/`, `registry.json` + `registry.json.lock`, **`team-registry.json` + `team-registry.json.lock` (acting)**, entire `spool/` **including parked entries**, `watch/`, `goalie/`, `collab/`, `seat-state/`, `pane-effects/`, `drafts/`, `handoff/`, `input-backups/`. Discard then recreate empty: `tmp/`, `delivery/` (best-effort verified-delivery batching clocks; reset starts fresh recipient state, and these clocks are not checkpoint evidence), `clear-fence/` (per-seat clearing fences, tap-dgdn — a fence is a live claim about the generation being destroyed; restoring one would park standard sends and refuse urgent sends to that seat on a clear that no longer exists — when the restore lands inside the family await ceiling of the original stamp (45s/90s); past it the fence reads expired and fails open — and discard rows never enter restore's inventory set-equality, so older bundles stay restorable). A LIVE clear fence — original stamp still inside its family await ceiling — refuses reset up front (`error_class=clear_in_flight`): a clearer that already passed its one-time reset-fence check can respawn-kill the reset caller mid-checkpoint, so reset waits out the ceiling instead of racing it; expired or torn fences do not block. The handshake is two-sided: `tap clear` rechecks the reset fence AFTER its own fence is visible and yields (releasing the fence) if reset claimed first, so whichever side claims second always sees the other's claim — no lock is held across the respawn in either arm. Historical review scratch has no discard exemption; an unclassified file refuses before effects. Preserve in place (never nested into the new checkpoint): prior `archive/` siblings, `archive.lock` (the `tap bus archive` job lock: reset takes it with no wait before it writes its fence and holds it through the cut, and refuses `archive_active` before any effect while an archiver holds it, or `reset_in_progress` when a live reset owns the fence; a dry-run probes an existing lock, refuses the same way and releases it at once), `registry-events.log` + lock, `tap-deliver.log`, `.tap-bus-authority` (pane-effect authority stamp, tap-ncd4 — this bus stays the same bus across a reset, so its authority never re-earns and never rides the checkpoint). Ephemeral guards (never checkpointed): `reset.fence.json` + `reset.fence.json.lock`, `reset-generation.json` (prior marker recorded in checkpoint meta; pristine stamp rewritten on success). **After the live cut (tap-w3op):** reset rewrites a blank acting `team-registry.json` (+ lock) so reboot consumers stay `live`; restore treats that blank registry (empty `seats` object) and its sidecar lock as pristine live state and may overwrite them from the checkpoint. `TAP_RESET_COMPONENT_TABLE_OVERRIDE` is honored only when `TAP_SCRATCH_ONLY` is set (mutation tests); production reset/restore ignore a leaked override. `--keep-registry` is removed — use `tap team down` to stop sessions while retaining registry and traffic. Parked-spool co-fate-with-receipts is retired: the whole spool rides the checkpoint so a post-reset bus cannot later deliver pre-cut parked entries.

**Retention policy: no discard (tap-kf9).** A burst of repeated resets can never discard an archive holding content the burst did not itself produce. The team archive root reserves each bundle directory by exclusive creation; a taken name uses the next `-2`, `-3`, … suffix rather than writing through it. Retention is count-free and age-free. Every consumer uses the exact bundle id or path printed by `tap team reset`.

### Scratch-only interlock (`TAP_SCRATCH_ONLY`)

A caller may declare, once and in its own environment, the directory prefix every state root it clears must live under: `export TAP_SCRATCH_ONLY=<abs-dir>`. When that variable is non-empty, a state-clearing verb compares the **final resolved** state root — the exact value it is about to act on, read at its own resolution point, never an argument or an earlier copy — against the declared prefix, and refuses (`error_class=scratch_only_refused`) when the root is neither the prefix itself nor a path component-wise beneath it. The refusal names both the declared prefix and the resolved root, and nothing is archived, cleared, or deleted.

Guarded verbs and the root each one checks: `tap team reset` → the resolved bus (`TAP_HOME`) · `tap team purge` → the exact archive directory to be deleted · `tap admin rebuild-registry --yes` → each acting registry the plan resolved (the non-writing bare preview is not gated) · `tap out --kill` → the resolved bus (`TAP_HOME`) whose seat row is being deleted and whose session is being stopped. Each shell-side refusal exits `1` with the ordinary structured failure and performs no archive, clear, delete, or session stop.

Two properties are load-bearing. **This interlock** (not the retention change above, which is a real behavior change stated on its own terms) is **purely additive**: with the variable unset, behavior is byte-identical to a build without it, and when set it can only ever refuse more — never permit more — so no sanctioned path can lose access. And it is **not defeatable by the failure it exists to catch**: its inputs are this process's own environment plus values assigned in the executing shell, and every call site runs in the current shell (never inside `$( )`, a pipeline segment, or a background job) so the refusal's exit ends the command rather than a subshell. The failure it defends against: a review harness set its scratch overrides inside a command substitution, those exports never reached the parent, and a machine-wide reset ran against the real state root: every sanctioned gate on the command held, and what was missing was any mechanical link between the declared scope and the resolved root.

**What the belt does not cover, and the doctrine that still does.** Being opt-in is exactly what makes it additive, and exactly what bounds it: a session that never exported `TAP_SCRATCH_ONLY` — including one whose *declaration* was itself lost to a subshell, the same way that failure lost its overrides — has no belt at all, and every verb behaves as it always did. The mechanism converts a declaration into a check; it cannot supply the declaration. So the operating doctrine is unchanged and still load-bearing: declare ONCE, at session top level, outside any subshell, and verify the declaration landed (`printenv TAP_SCRATCH_ONLY`) before invoking anything destructive. What the interlock removes is the *next* failure in that chain — a declaration that landed while the scratch overrides it was meant to describe did not.

### `tap team purge <archive> [--dry-run] [--yes]`

Deletes one exact archive directory under this team's `$TAP_HOME/archive/team-reset`. `--dry-run` reports the target's file count and size without mutation; a real deletion prompts on a TTY and refuses a non-interactive caller without `--yes`. Success names the exact archive plus its freed file count and size. The native owner rejects public `--root` and `--verb` arguments as `unknown_option` before archive inspection or deletion, removing the shell owner's accidental ability to override the team scope. Deletion uses the exact lexical archive path: a directory symlink is removed without deleting its referent, and nested symlink targets remain intact. Statistics or removal failures never produce a successful deletion receipt.

### `tap admin retire <team> [--force] [--json]`

The **only** operation that de-enrolls a team from the machine index (`~/.tap/global-registry.json`; with no marker it refuses `unanchored_bus`, next `tap init`). Index-only — retire never archives a worktree's `.tap/` bus (payloads, receipts, archives stay; `tap team reset` owns archiving).

**Refusal without `--force`:** retire refuses (`error_class=retire_refused`) when the acting registry has poll-mode members. Current registry membership is the recovery boundary; archived journal rows are not blockers.

**With `--force`:** de-enrolls regardless of blockers; appends an audit event on the team's bus when its root still exists.

Success prints `tap admin retire: de-enrolled team '<team>'`; `--json` emits `{ok: true, team, root, forced}`.

### Tombstones (`tap roster`, `tap admin prune`)

Hard-renamed verbs exit `1` with `error_class=renamed_verb` and name the new spelling — no silent alias. `tap roster` → `tap team`. `tap admin prune` → `tap admin refresh` plus `tap admin retire <team>`.
