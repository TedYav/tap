# Roster observations

Crew seats are included in an unfiltered `tap team` roster. `--harness`, `--model`, `--state`, `--online` (including its `--active` alias), `--offline`, and `--stalled` exclude crews unless `--include-crews` is supplied. Included crews must match the filters themselves. Human output retains a matching crew's otherwise excluded parent as a dimmed row labeled `(crew parent)` with `context only` in the state/status column. This parent is display context, is not enriched just for display, and is absent from `--json` and `--names`. `--recent` and `-n` order and count matched seats; an added context parent precedes its first matching child without consuming a slot. `tap crew list` remains crew-only and needs no opt-in. Context styling honors `NO_COLOR`, `TERM=dumb` and redirection; the labels remain in plain text.

Human output is column-shaped. Native bare `tap team` prints seven columns (`handle` / `harness` / `state` / `context` / `family` / `model` / `preset`). On an interactive terminal narrower than the row, native default human output drops whole columns from the right — `preset`, `model`, `family`, `context`, then `harness` — until the row fits, keeping `handle` and `state` in every view, and emits at most one stderr line naming the hidden columns and `--wide`; `--wide` keeps every column. Pipes, redirections, `--json`, and `--names` are never fitted, never truncated, and never hint. `--all` keeps its nine-column schema (only redirected `--all` gains the no-truncation guarantee). `context` is the last reported request input count over the known window (`145k/380k`), a bare count (`340k`) when the window is unknown, or `—` when no count is available; JSON also retains the footer percentage from the existing state capture. `model` renders the model@effort observed in the bound transcript (Claude assistant records, Codex `turn_context`; observed tuning in [Model reference and launch tuning](model-reference.md)), as a bare model name when the effort is unobserved, and falls back to the recorded launch snapshot marked `(launch)`, else `?`. `family` is vendor lineage, `-` when unknown ([Model reference](model-reference.md)). Attached-client counts and delivery intervals remain in JSON and `--all`. Forced/fallback Bash retains its legacy six-column projection. In native default human output, crew rows are grouped hierarchically under their parent non-crew seat (the seat sharing their registered tmux session). Children sort by tmux window index under their parent and are prefixed with pure-ASCII `|-- ` (intermediate children) and `` `-- `` (closing child). Parents maintain their existing relative roster order. When a crew seat has no parent non-crew seat in its session (rootless crew defect), native output renders the row flat in normal roster order and emits at most one stderr warning line naming `tap-zhx82`. When multiple non-crew seats share a session, native output nests crew seats under the first in roster order and emits at most one stderr warning line naming `tap-7ph7f`. Both warnings are scoped to the native default human projection; `--all`, `--json`, `--names` and forced or fallback Bash emit no tree prefixes or defect diagnostics. Default human `status` is a lossy projection, not JSON `status` / `status_reason` / `agent_state`. Native uses the `● <label>` cell in its `state` column: `unbound` renders `unbound` without capture, every other non-`active` lifecycle renders `offline`, and active rows render `working`, `idle`, `waiting`, or fail-closed `unknown` from the one-shot detector plus roster activity (tap-i5fzq; part 06 `team --json`), aged when dated. Detected blockers render `blocked`, and failed turns with usable input render `error`; JSON retains `agent_state_reason`. The existing unsubmitted-sentinel label remains distinct. Forced or fallback Bash cannot observe agent state, so its default `status` is `unknown` when the classifier result is `active`, `unbound` when it is `unbound`, and `offline` for every other lifecycle result; it does not overwrite the lifecycle value that `--all` still reads. Each eligible active pane is captured at most once on the native path. The state dot alone is colored on an interactive TTY; any presence of `NO_COLOR` disables ANSI, and the text label remains authoritative. The default table has no `roles` column. The `preset` cell carries the seat's recorded launch provenance, `n/a` when the row has none, and `<name>?` when the value was matched from the handle text rather than read from a record — an inferred value never prints with the authority of a recorded one (tap-8nob). `tap team --all` and `tap crew list` do not widen the default table or observe agent state; they SWITCH to a separate zero-capture nine-column schema (`handle` / `kind` / `harness` / `pane` / `status` / `attached` / `unattended` / `reason` / `notes/asks`) which omits `preset` and `roles`, with `kind` labeling durable rows `SEAT` and crew rows `CREW` and `reason` carrying the classifier `status_reason`. That wide `status` cell is the observed lifecycle (`active` / `unbound` / `gone` / `offline` / `unknown` / `suspended` etc.), not the lossy default projection. `tap team --json` keeps its existing machine shape, including lifecycle `status` and `status_reason`, native `agent_state` / `agent_state_reason`, and `crew: true|false` on every agent row, plus optional `preset` and `metadata` when a handle joins, and `family` (null when unknown) on every agent row. Per-seat offline reason trailers, the offline warning block, and the gone-seats warning are omitted; `--all` and `--json` still carry classifier `gone`.

## Lightweight mode

`tap team --no-state` (also `team roster` and `crew list`) skips pane captures, compute queries, transcripts and token samples. It keeps lifecycle and recorded launch facts. JSON keeps its fields: `agent_state` is `unknown`, `agent_state_reason` is `not_observed`, context and observed tuning are null, and `context_unknown_reason` is `not_sampled`. `--state`, `--model`, `--stalled` and `--context` require enrichment and refuse with this flag. Without the flag, the existing observation and JSON contract remains.


`tap admin ps --no-state` keeps lifecycle and process metrics while skipping activity captures and transcript reads. JSON `activity` stays `unknown`; `--model` and `--state` refuse because they require those observations.

## Observation cache

`tap team`, `tap team roster` and `tap crew list` reuse display observations for five seconds. A cache hit starts no Git, tmux, `ps` or compute process. It reuses pane, activity, token and crew-lifetime samples. The registry file fingerprint invalidates the observation after registration, retirement, role or crew changes. Changes to resolved preset and delivery facts also invalidate it. Team, socket, enrichment mode and selectors must match. Changing selectors replaces one of two fixed files (`roster-full.json` and `roster-nostate.json`) under the acting bus's `runtime-cache/` directory (normally `.tap/bus/runtime-cache/`); a cold filtered read still excludes seats before capture.

The record retains the server epoch it sampled. A restart within the TTL can leave the display stale until expiry. `--no-cache` bypasses cache reads and writes and takes a fresh observation. Missing, stale, corrupt or unwritable cache files never prevent a fresh roster. Cache publication uses an atomic replacement.

JSON adds top-level `observed_at`, the completed observation's ISO timestamp, unchanged on a hit; it is null for an empty roster. Each agent's existing `observed_at` still dates its observed model tuning. Human output adds `cached observation Ns ago` on a hit. `--names` remains handles only. Message-queue and stalled-debt facts are read for each request.

The cache belongs to the display entry point. Delivery identity checks, registration, readiness, nudge, relaunch, health and doctor keep their live readers. A reporting cache hit can resolve an enrolled checkout locally before Git or pane fallback; unresolved or ambiguous reporting scope uses the ordinary fresh path. `admin ps` retains `--no-state` but has no observation cache.

Plain roster reads with `OPENCODE_SESSION_ID` set keep native session-based team resolution and skip the shortcut: a shared-service child may belong to a root seat outside its cwd. Naming a team explicitly still permits caching. The cache never creates its bus directory: reading a team that has no bus writes no cache.

## Advanced settings

`[advanced]` in the existing `config.toml` holds expert operational settings. Normal installations should leave the defaults alone:

```toml
[advanced]
roster_cache_ttl_seconds = 5
```

The TTL must be a finite nonnegative number; zero disables caching. Unknown keys and invalid values refuse with `advanced_config_invalid` naming the key. The shared catalog loader validates this bucket; consumers reuse its parsed settings.

`TAP_ROSTER_CACHE_TTL` overrides the file for an invocation; zero disables caching and an invalid override falls back to the file value. `--no-cache` takes precedence over both. Any set `TAP_WATCH_NOW` bypasses the cache, so frozen-time reads never reuse wall-clock samples.
