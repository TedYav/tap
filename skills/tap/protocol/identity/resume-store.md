# Native-store evidence for resume identity (v0.23)

**Rule (tap-dt6kf).** Native-store evidence may gate resume without row mutation, or withdraw the record-owned id; it may never promote or nominate any other id; missing or unreadable store behavior is an explicit per-harness decision.

**OpenCode.** OpenCode 1.18.33 does not fall back on an unknown `--session` id: it prints `Error: Session not found: <id>` and exits 1, with no TUI, no new session and no picker. The shared launch transaction therefore binds every resume-family kind (`resume`, `resume-all`, `restart`, `seat-up`, dry runs included) through one OpenCode check before any reservation or effect. A store that opens read-only, has a `session` table and lacks the stored id refuses `no_exact_resume_identity` with the action `tap session launch opencode <handle> --fresh`. The row keeps its id unchanged, so a restored store makes it resumable again. Any store that cannot answer proceeds with the stored id, and OpenCode remains the authority: a missing file, a refused or degraded catalog policy (unreadable, malformed or insecure `config.toml`), an open or lock error (100 ms busy timeout), a WAL store missing `-wal` or `-shm` (detected from the header before any open), or an unexpected schema. The check opens SQLite read-only without create, so it never creates the store or its journals. It reads the store with the seat's composed child environment (catalog policy, then `harness_env`, then `harness_unset_env`), so a seat whose launch moves `HOME` or `XDG_DATA_HOME` is checked against the store its OpenCode will open. It does not use `immutable=1`, which would skip uncheckpointed WAL sessions.

**Store resolution.** One resolver serves this check and every other OpenCode store reader: `OPENCODE_DB_PATH` (TAP's pin, which OpenCode ignores), else `$XDG_DATA_HOME/opencode/opencode.db`, else `~/.local/share/opencode/opencode.db`. The resume gate drops `OPENCODE_DB_PATH` from the seat's environment before resolving, because OpenCode never opens that path; the gate always reads the store the child opens.

**Limit.** When the harness itself exits during readiness, the launcher's pane-died rollback removes the pane before the failure report can capture its tail, so `Session not found` is not surfaced on the fail-open arm.

The captured-id provenance this gate preserves is [OpenCode resume](registry-unit-1-part-08.md); the cursor counterpart is [tap-we6b](seat-relaunch-tap-session-relaunch-v0-22-part-03.md).
