## Rebind recap (`tap in` on an existing handle, `tap recap`) (v0.21)

A **rebind** is a fresh instance of an existing seat: same handle, same obligations, no memory of either. It is what a seat refresh produces, and the recap is why refreshing is safe — the obligations survived on the bus, so the successor can be re-pointed at them.

**On rebind (`prior_existing`), `tap in` prints the recap** instead of the terse reconnect line: the identity (`you have re-joined as <team>/<handle> — a fresh instance of an existing seat`), then **one counts line that always prints, zeros included** — `N unsettled inbound, N of your sends awaiting a reply, N recent exchanges on record.` — then unsettled inbound obligations by id, the seat's own outstanding sends by id, and recent exchanges, each detail line present only when its bucket is nonzero. The zeros are load-bearing: suppressing them left the recent-exchanges count carrying the whole signal, and a fresh instance reads settled history as work owed. The first two counts are obligations and the third is traffic — `on record` marks that axis change, because the buckets are **not disjoint** (an unsettled send is counted in both the second and the third, and by a varying amount: a send older than the scan window leaves history while staying outstanding). Because the counts line answers the empty case, there is no clean-slate special case. A genuinely first-time registration keeps today's terse output — there is nothing to recover, and a recap would be ceremony. `tap in --json` gains an additive `outstanding` array; every existing key keeps its shape.

**Small-and-pull.** Counts and ids inline; depth behind `tap recap [<handle>] [--json] [--limit <n>]`, which is also callable mid-session by an agent that has lost the thread (a seat cannot re-register itself just to remember what it owes). An empty recap exits **0** and says so: "you owe nothing" is a real answer, and a nonzero exit would read as breakage and invite a retry loop.

**Ids and paths, never prose.** The recap hands over durable refs and explicitly scopes itself: coordination state is recoverable from the bus; what the predecessor was building and why is not. A reconstructed summary is precisely what a fresh instance cannot verify, so the output names beads and PRs as where work-state rationale lives rather than inventing a narrative. That disclaimer is asserted by regression, not left to good intentions.

**Standalone reader.** `tap recap` reads the selected bus's canonical payloads. A present envelope id that differs from the filename id is excluded from both obligations and history; a missing id retains legacy handling, and accepted rows emit the filename id. Inbox and outstanding rows with a recipient or sender instance stamp require a positively obtained matching current instance, including before the registry flip. An unknown instance does not admit stamped obligations; unstamped rows remain eligible under the existing handle and `to_team` checks. Done, cancelled and archived settlements are excluded from obligations through the shared settled predicate.

History remains historical: it includes settled and unsettled traffic and is not instance-filtered. It examines the newest `max(20, limit * 4)` canonical candidates before selecting matching traffic, with descending filename-id order for tied mtimes; `--limit 0` returns no history. Registration retains its separate compact briefing and history policy. The standalone reader writes no bus, registry or receipts and performs no tmux effects. Existing public-entry onboarding and reconciliation remain outside that reader guarantee.

Registration and standalone recap collect coordination state from one shared census of the bus's canonical messages. The outstanding-message iterator checks done, cancelled and archived settlement before callers stat or read bodies, and both obligation directions use that one pass. History draws from the same canonical census within each caller's bounded window; registration examines at most the newest 20 messages and excludes unsettled inbound from history. Caller-specific parser, instance and rendering policies remain distinct.
