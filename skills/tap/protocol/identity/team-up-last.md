# Team startup and latest restart cohort

## Ordinary team startup

`tap session resume --all` / `tap team up` recreates every relaunchable stopped acting-registry seat whose exact tmux name is absent, including a pane-backed row stored as `pane_gone`, `session_replaced`, `repair_failed`, or `restart_failed` when its recorded `boot_id` or `server_epoch` is positively stale versus a readable current observation; crew, poll, `user_removed`, same-boot `pane_gone`, and any row whose boot/generation cannot be compared stay excluded; a live occupant of that canonical name on the current server is unverified and is skipped (bulk) or refused before registration (named resume).

This membership decision never rewrites a retained failure reason. Both socket
provenance and readable current server generation are required; an unavailable
server is not proof that its prior generation is gone.

## Latest restart cohort

`tap team up --last` (`-` is an alias) narrows recovery to the newest prior server generation on the resolved team's physical socket. The server epoch's start time orders generations; equal newest start times with different generation identities refuse. One epoch groups legacy and current boot-stamp formats together; conflicting boot identities within either format still refuse. Generation selection includes deliberately stopped rows before eligibility filtering, including legacy stopped rows whose delivery and pane fields were cleared, so a fully stopped newest generation never exposes an older cohort. Only absent parent sessions stored active (without a launching or retirement reason), or suspended with `server_restarted`, `pane_gone`, `session_replaced`, `repair_failed` or `restart_failed`, can join. Crews, poll delivery, explicit retirement and `session_stopped` stay excluded. Unknown row stamps are skipped; unreadable current boot or namespace evidence refuses. A recognized no-server response permits selection without creating a server, using the would-be physical socket. A successful empty namespace from a live server still requires a readable current generation. Valid server epochs remain comparable when legacy and current boot stamps use different formats. No exit timestamp is synthesized: `exited_at` is first-observation evidence and does not define a simultaneous-exit window.

This selector pins rows before bootstrap. Dry-run validates the pinned cohort without writes; a real invocation previews the same rows before confirmation (`--yes` is required without an interactive terminal). Only `--yes` before the option separator grants consent; a literal operand after `--` refuses. Explicit consent skips the consent-preview pass in both output modes; JSON then reports only actual outcomes. `--last` cannot combine with only/except selection. Launches use the existing resume-all transaction and recheck membership, identity and recipe fields under registry custody; a changed row refuses that seat without selecting a replacement. A failed pinned resume never offers an automatic fresh start. An explicitly pinned row with an undecodable launch recipe refuses rather than becoming an empty success. Named-team pin compatibility is checked even when no cohort is eligible. No eligible cohort returns success with `no_restart_cohort`; same-generation individual exits require explicit handles. A seat that disappeared earlier within the chosen generation cannot be distinguished from one lost at restart; the human preview includes its registration timestamp. Crews remain excluded in this release; the crew-resume proposal carries future parent-first recovery separately.
