**The addressee grant is one implementation on both doors (D2-u1, batch 2).** `runtime/bun/src/addressee-grant.ts` decides who may act on an inbound — the addressee itself, its adopted successor (`adopted_handles` / `adopted_instances`, the grant keyed by successor + fork [+ instance]), or an explicitly forwarded recipient — and, when it refuses, which class (`not_addressee`, `instance_unresolved`, `registry_unreachable`) with which clearing remedy (the tombstone `--restore` door only where the handle holds no current seat, the LOOK `tap team` where one does, `--list-history` where the history could not be read, and the named absence of a path otherwise). The native `tap read` calls it in-process; the Bash `read`, `reply` and `cancel` doors reach the same module through lib.sh's `tap_addressee_grant_check` and `tap_instance_clearing_remedy`, which resolve only what the incumbent resolved — the flip marker (an invalid or unreadable marker still refuses in Bash before the call), the acting registry, the team history dir — and decide nothing. The incumbent's `tap_adoption_grant`, `tap_adopted_instance` and `tap_instance_in_history` are gone with their Python bodies. Measured against the pinned base program over the fixture matrix, the outputs are byte-identical, including two polarities kept on purpose: a registry that cannot be parsed leaves adoption ungranted silently, and the clearing remedy treats an unparseable registry as a PRESENT row. One ratified deviation (2026-09-16): a registry outside the native reader's value domain — a float or an unsafe integer in any field, which `loadRegistry` refuses for every native verb and which no TAP writer emits — now refuses the grant on BOTH doors as `registry_unreachable`, the refusal naming the offending field and value as the loader does (`registry: number '0.5' at field 'observer_metadata' is outside the supported value domain …`); the incumbent's Python `json.load` accepted such a registry and granted from it. Seat presence is an own, non-null row: a handle spelling an inherited property (`constructor`) or a JSON null row is absent. The native `reply` door keeps its own `assertRecipientAuthority` until D2's reply unit folds native reply onto this module.

**Team-qualified addressing is native (D2, member 2 of the `reply` stack).** A `tap send` / `tap assign` whose destination is `<team>/<handle>` or `<team>:<handle>` runs on the native door with a live marker and takes the incumbent's remote route (`runtime/bun/src/remote-target.ts`, `verbs/send.ts`): the colon form normalizes and the address splits with `tap_resolve_team_target`'s refusals (`usage_error`, `tap help`); the caller's own team must be a token first (`usage_error` / `tap help` / `local team '<name>' is not a valid token (<re>)`, lib.sh:7265's refusal, before anything is staged — on a bare handle as much as a qualified one); a team other than the caller's binds through the machine index read by the marker-aware loader (an unreadable document, the wrong schema, or a non-dict `teams` is `invalid`, never `ok` for a team that happens to be listed) — `historical_team`, `unreachable_team` (a stored `registry_location` that is unreadable or absent from the entry), `stale_enrollment` (a stored `registry_location` that is positively absent, the worktree removed while enrolled; next `tap admin refresh`, tap-xbpuc), `invalid_flip` (lib.sh:7285's fixed sentence), and `unknown_team` carry the incumbent's classes, actions and details, the last two naming the manual-relay fallback (`tap send <handle> <payload> --cross-worktree --pane <tmux-target>`); the recipient's own team is a local send. The recipient's row is read from the REMOTE acting registry under that registry's lock — every lock a send holds is taken in the sorted realpath order of the sidecars, the placement helper's discipline, so two cross-team sends in opposite directions never wait on each other — and answers with the incumbent's remote verdicts in its order: `not_found` (unknown handle, with the registered handles; or no pane), `seat_pending`, `seat_launching`, `suspended`, `poll_member_remote` (a poll member is never addressed across teams: the canonical would sit where it never looks), `identity_unverified` (no `pane_id`, or a malformed one — `target seat '<handle>' must run 'tap in' from team '<team>'`; a non-string value is malformed on both doors and the quoted value is each door's own rendering of it, Python's repr on Bash, JSON's on native — they agree on `[]` and `{}` and differ on booleans and null), and `pane_gone` with exit **1** and the fallback when the remote pane is not alive (the local route's exit 3 is after the local checks; the remote check precedes them). An enrolled recipient's bus is resolved from the machine index row's root through `busHomeForEnrolled`, independently of `registry_location`. A relocated acting store remains addressable; its clear and reset fences stay at the enrolled root's `.tap/bus`; a legacy-only bus refuses `old_store` before delivery. The explicit `--remote-registry` door still pins a file and derives its bus from that path without reading the machine index; see the [clear-fence location rule](seat-clear-tap-clear-v0-21-part-01.md#clear-fence-location). A torn remote registry, or one carrying a number outside the registry's value domain (a float, an integer past the safe range), is `forwarding_unavailable` / `tap team; retry with a current recipient` / `cannot resolve pinned forwarding for '<team>/<handle>'; no payload was placed` on both doors: the incumbent's first reader of that file is the forwarding resolver, and the native door reads it in-process to the same verdict. Forwarding resolves on the remote registry. The recipient's reset fence and clear fence are inspected on the RECIPIENT's bus (`tap send (recipient bus)`), the sender's on its own; a clearing recipient parks on the SENDER's spool with `to_team` and the remote registry recorded. The canonical, `.placed`, `.sent`, the spool and the harness queue all stay on the SENDER's bus, stamped `cross_worktree: true`, `from_team`, `to_team`, and the remote row's `recipient_instance`; the delivery clock is the recipient's (its bus sidecar). Slash qualification is sentinel-only: `[[TAP v0.23 <ask|note> <sender-team>/<id>]]`, with `path=` exactly when the sender's team does not resolve through the index; an index that has turned INVALID — unreadable, or rewritten with the wrong schema — between the caller's own binding and the sentinel render is the constructor's refusal on both doors, not a pointer — exit 1 after placement, the canonical and its `.placed` kept, nothing injected — where the native door prints `die`'s bytes (`error` / `fix_command` / `sentinel_render: registry marker is invalid_flip; refusing to render rather than guess whether team '<team>' is reachable`) and the Bash door, whose refusal fires inside the `SENTINEL="$(…)"` substitution, exits 1 silently under `--json` (measured deviation: the native door keeps the bytes the incumbent loses). Receipts name the bare handle, as the incumbent's did. Identity drift on the remote route carries the incumbent's one remote action, `target seat '<handle>' must run 'tap in' from team '<team>'`, before and after placement; the pre-placement drift keeps each door's own detail sentence (native's own, as on the local route since D1; Bash's `bound pane_id '<stored>' does not match live pane_id '<live>'`). After placement the doors part, as they already do locally: the native point-of-effect reauthorizer rereads the REMOTE acting registry and answers a `pane_id` or instance change with the certified pre-effect `identity_mismatch` carve-out (exit 0, `queued`/poll, canonical and `.placed` kept) where the Bash door's pre-submit recheck refuses a `pane_id` drift with exit 1 AND retracts the canonical (`tap-send.sh:1687-1695`) and reads no instance at all (`tap_bound_pane_identity_state`, lib.sh:7437-7460, compares status, pane, `pane_id`, delivery, epoch, boot and harness — the row read carries no `instance`), so a replaced instance injects there. Both are measured deviations, pinned in `runtime/bun/test/send-remote.test.ts`; the native side is the safer boundary and is not weakened to match. Still Bash-owned: the manual relay (`--cross-worktree --pane`) and `--remote-registry` — operator doors, not addressing — which retire or port with the verb; and the absent-marker route, which the router keeps on Bash until the verb closes (a closed verb refuses under an absent marker as a typed repair, after first enrollment on a machine with no legacy stores writes the marker — lane C's born-live prefix). The deviations this member measures are the four named above (the silent Bash refusal at render, the post-placement drift disposition, the instance recheck, the drift detail sentence); the `invalid_flip` arm of the binding is reachable only when the index becomes invalid between the caller's own resolution and the binding, and carries the incumbent's fixed sentence. Two cross-team sends in opposite directions complete concurrently on both doors; the pane outcome of each is the courier's under the tmux client budget (a starved budget parks `no-input-prompt` or returns submit-unverified), which the lock row tolerates by name.
