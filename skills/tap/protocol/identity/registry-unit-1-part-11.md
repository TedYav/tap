**Reclaim adoption (tap-p6el):** when the seat-dedup release above deletes a stale fork handle `H_fork` into the reclaiming seat `H_succ` (same-pane or proven same-session corpse — never an `ALIVE`/`UNOBSERVABLE` incumbent), the courier **adopts** `H_fork`'s unsettled team-local mail *under the same registry flock*, as a consequence of the release — there is no adoption verb. Each such payload on the local bus with `to == H_fork` and (`to_team` absent or the local team) is rewritten `to := H_succ` with forensic `to_adopted_from` / `adopted_at` stamped; `id`, `from`, body, and `reply=` are untouched, so `in_reply_to` chains stay valid on the original id. `H_succ`'s registry row records an `adopted_handles` grant (used for foreign-bus `--payload` settle without rewriting the sender's canonical), and its `session_epoch` bumps by one **only when at least one payload transferred**. Adoption never crosses `to_team` (never adopts another team's mail), never rewrites settled receipts, and never moves native-session or quarantine identity (payload adoption ≠ identity capture). Settlement and reply after adoption use actor `H_succ` only — the receipt carries `by=H_succ` plus `adopted_from=H_fork`, never a fiction actor. `tap read|reply --by H_fork` refuses (`handle_adopted`) once `H_fork` is released, naming the `--by H_succ` next action; a currently-active same-named seat is never treated as adopted-away, so a re-registered handle settles its own mail and a stale grant never blocks a live seat. Over-cap adoptions fail closed with a loud remainder on stderr — never a silent truncation — at two CONTRACT constants: **at most 8 handles adopted per register release-sweep** (a pathological register that releases many stale suffixes into one successor still frees every corpse — dedup is preserved — but adopts only the 8 lowest-sorted; the surplus handles are surfaced as stranded), and **at most 64 payloads adopted per released handle** (the over-cap payloads stay addressed to the fork for manual settle).

**Trim strand report (tap-q2v4):** adoption rides register release only. `tap team refresh` (and any equivalent trim) deletes a dead handle row with **no successor** in the same locked write, so it never adopts — but it must not silently drop the obligation either. When a trim would remove a handle that still has unsettled team-local inbound (same eligibility predicate as adoption: `to == H`, `to_team` absent or local, not settled, not outbound), refresh emits an operator **`WARNING`** on stderr naming the handle, the count, and the stranded payload ids, plus a next action. The advertised action must RUN in the failure state (tap-fcd3's principle), so the report directs the SENDER to cancel each stranded id by its own `from:` — `tap cancel <id> --by <from>` — and, where a live seat already holds an `adopted_handles` grant for `H` (a prior reclaim), names that successor; the landed adoption-aware `read`/`reply` gates honor its exact predecessor-instance grant without rewriting `recipient_instance` (a reclaim release writes no tombstone, so `--restore` is offered for neither handle). The report is **read-only** — it rewrites no payload and settles nothing — and rides stderr in both human and `--json` modes so the trimmed/kept/skipped stdout and `--json` shape stay byte-stable. It runs in `--dry-run` too, since the preview is the most useful moment to warn. Auto-adopting on refresh (no successor present) and rewriting settled history are non-goals.

**Registry event log:** successful `tap register`, `tap register --offline`, same-pane release, `tap unregister`, `tap teardown`, and `tap restore` append one single-line record to `registry-events.log` on the bus (`ts`, `actor`, `action`, `handle`, `pane`, `team`, with `team` appended last). The write is protected by a kernel `flock(2)` on the `registry-events.log.lock` sidecar — shared by every writer, Bash or native — and tail-truncated at write (`TAP_REGISTRY_EVENT_LIMIT`, default 200); a caller that cannot take that lock within its bound warns rather than waiting indefinitely. This is an operator visibility tail, not an audit database; append failure emits a warning but never turns the already-applied registry mutation into a failed command. Permanent teardown does **not** redact this log (tap-wn9w ruling 1); property 2 is what reopen *shows*, not what bytes remain on disk.

**On-demand suspension rule:** An entry is marked `suspended` only when a deterministic tmux observation positively proves the pane is gone **and the current tmux server is readable**. Reachability is fail-closed: a missing server identity or failed pane query without positive missing-pane evidence is unobservable and refuses the `pane_gone` write, including failures with empty stderr. Empty stderr from an incomplete mock does not prove reachability. A successful current-server observation followed by a successful empty pane expansion or an explicit missing-target result still proves absence. This follows the status-lifecycle rule: observation failure never proves absence or exit. This observation happens inside `tap send`'s pre-canonicalize validity check, never on a clock or background poller. A missing or synthetic socket (classic leak: `TMUX=/fake/socket` left in a long-lived agent shell after a smoke preamble) is **not** evidence the pane is gone: `tap_registry_mark_suspended` refuses the `pane_gone` write (`error_class=tmux_unreachable`, exit 1) so fail-closed means no-write, not a false suspension (tap-o4ae). `tap doctor` reports suspended entries from the registry; it does NOT probe tmux to discover new vanished panes.

**In-lock registry authority (tap-yn2y):** After acquiring a registry sidecar flock, membership writers re-prove the locked path is still authority before mutate. Under a live flip marker, a lock on the retired bus mirror exits retry (17) or refuse (4) — never stamps the decoy. `tap_registry_mark_suspended` rebinds once on retry. An absent marker refuses (4): with no machine index, no store is authority. No shell writer bootstraps an unenrolled root; first entry belongs to native `tap init` and first launch.

Native send suspension and pane-address healing validate that authority using the selected team's root. An explicit remote-registry binding obtains the root from its derived bus. Both `<root>/.tap/bus/registry.json` and `<root>/.tap/team-registry.json` use the same root; an indexed relocated registry retains its selected root. The locked file must still match the current enrollment before either write.

**Socket namespace display (tap-9jfyl):** Native `tap team` marks a positively known foreign-socket row offline with `foreign_namespace`, names its socket basename (full path for ambiguous `default` sockets) in human output, and includes `server_socket` in JSON. It leaves the row unchanged. Both native and Bash `team refresh`, including `--hard`, retain known foreign-socket rows outside trim authority. Legacy rows without a socket remain readable but are not automatically invalidated; re-registration or repair supplies current provenance. Sender eligibility still rejects a positively stale epoch or boot at read time, including through the Bash fallback, without rewriting that legacy row.

**Team list observed status (tap-6nqj):** `tap team` is read-only but classifies pane-backed rows at display time from one exact-session observation: current boot/server generation, designated-pane membership inside that session, and the expected harness all have to agree. Observed statuses are `active`, `unbound`, `gone`, `offline`, or `unknown`. `unbound` positively observes one matching harness pane for a restart-suspended row while retaining its non-delivery state until reconciliation restores the binding. `gone` is an observation, not a stored membership tier: the registry row stays intact until `tap team refresh` explicitly trims it. `offline` preserves the recovery pointer and `unknown` proves too little to mutate. Poll-mode rows are never probed and display their stored status. For an active crew row, the same observation supplies the supported live harness without mutating the registry, repairing an initial pre-exec `harness: zsh` view.
