A refusal at that boundary writes no nonce, performs no respawn, and never reaches the post-effect nonce cleanup; the clearing fence is released on that path like any other. The single-seat form uses the same census and identity expectation as a batch; `tap clear`'s behavior is unchanged.

**Human output is one summary followed by one result per candidate.** For example, `Relaunching 3 active codex seats on all teams` (or `on team tap`), followed by `● team/handle`: green only after two consecutive observations of the same replacement harness process and no known zero-result native picker, red with one short reason on failure. Without terminal color the same dots and failure reasons remain. No candidates prints `No active codex seats on team tap; nothing to relaunch.` and exits **0**. Dry runs say `Would relaunch` and report `would-resume` in JSON; they never claim readiness.

**Exclusions remain inspectable without console chatter.** Missing or unreadable team registries are skipped silently, including a named team's missing registry. Invalid rows, nonmatching harnesses and inactive seats are recorded with reasons. `--json` includes `results` (worker exit code, stdout, stderr and timing), `candidates`, `excluded_inactive[]`, `skipped_teams[]`, `excluded_caller[]`, and additive `counts`. Exclusion entries carry `team`, `handle`, and `reason`. An unknown team, empty scope, or unreadable global authority still refuses before effects. The opt-in diagnostics integration is pending the shared `.149` writer; JSON already retains the complete receipt.

**The requested team's verdict comes from the snapshot that supplies enumeration.** Resolving `--team` from one read of the global registry and enumerating from a second let a team removed or made historical between the two reads produce an empty selection and a clean exit 0 — the typed refusal downgraded by a race. One snapshot answers both questions.

**A failed candidate never aborts its siblings.** Exit **0** means every candidate relaunched (or there were no candidates); **1** means at least one candidate failed, including pre-effect refusals. `results[].code` preserves the worker distinction: **2** with a refusal class means refused before replacement; **7** means replaced but readiness or registry verification failed. A failed tmux respawn preserves its raw status with `error_class=tmux_error`, so numeric **2** alone is not proof that no effect was attempted. A failure after replacement is never an invitation to retry blindly. Skipped teams and excluded inactive rows do not fail the candidate set.

**THE CALLER'S OWN SEAT IS EXCLUDED BY CONSTRUCTION, and that is a property of the selection.** Every handle sharing the caller's pane is dropped before any pane is touched, and each remains in `excluded_caller` with reason `caller-pane`; the human console does not list exclusions. `tap compact --all` states the same rule for the same reason: a verb that replaces the process it is running in cannot survive to finish the run, and the seats after it in the list are the ones that pay. The per-seat caller observation refusal remains as the **second** line and never the first, because it refuses an *unprovable* caller only when it can see it is inside tmux — a caller that is provably elsewhere sails straight past it, which is exactly the shape a `--harness` batch takes when it reaches its own pane. **From outside tmux there is no caller pane and nothing is excluded, which is correct**: a cron or watcher invocation is not a seat, has no conversation to lose and no turn to end.

**Seats are relaunched concurrently through the standard bounded worker pool.** Each worker holds the target seat's own clearing fence, so one slow harness no longer serializes the rest of the cohort behind its readiness window, while a machine-wide cohort does not mint one polling thread per seat. Human result rows appear as each candidate completes, without waiting for pending siblings. JSON remains one complete final receipt in census order. Mail for each affected seat parks against that seat's fence independently.

**Enumeration validates the global authority and reads team registries independently.** Team format and seat shape are checked before harness filtering, so a filter cannot hide an invalid row or old store. An invalid global schema or present non-object `teams` map refuses before selecting a cohort; an omitted `teams` map means an empty machine. A team registry in an old format is recorded in `skipped_teams` with an `old_store: <detail>` reason and never enumerated. Missing, malformed and historical teams are recorded there too, without console rows or an exit-6 path. An unknown named team refuses; an unknown exact handle refuses with exit **1** and `tap team roster <team>` guidance. A known inactive row remains a quiet exclusion. Empty candidate sets otherwise exit **0**, including when some team registries could not be read; the structured receipt distinguishes these cases.

**The JSON receipt is a cross-repository contract.** Callers outside this repository consume `tap session relaunch --harness codex --team='*' --json` and pin that receipt in their own tests. Treat a change to it as breaking: keep fields stable and add rather than rename. JSON retains per-seat status (`resumed`, `replaced`, or `failed`), worker code and elapsed time, plus caller exclusions and skipped teams. Dry runs report `would-resume` or `would-replace`. Worker refusal codes retain the distinctions described above; the aggregate exit code describes candidate results, not complete team coverage.

**It refuses anything that is not a launcher-managed seat of its own.** A **crew** row shares its DRIVER's tmux session and has no launcher record; resolving by session name returns the *driver's* record — a different harness and a different conversation — so a relaunch would kill the crew's process and start the driver's conversation in its pane. Two independent guards stand there: the shared `seat_is_relaunchable` predicate (which excludes crew, poll, and suspended corpses), and construction of the launch record directly from the guarded handle row, with its stored session checked against the observed pane session. No session-name lookup can select a driver's record for a crew handle. These worker defenses retain code **2** (`error_class=seat_not_relaunchable` / `launch_recipe_missing` / `seat_session_mismatch`) having written nothing; the public aggregate is **1** for a failed candidate. The census therefore never hands a crew row to the resume worker. **A live crew row is replaced fresh in its own pane instead** (tap-odt1d.1), in Bun, by the same function as `tap crew relaunch`. Its persisted recipe (`harness`, `model`, `permissions`, `harness_env`, `passthrough`, `cwd`, plus `harness_unset_env` and `harness_tail`, absent on older rows) renders a new-session invocation replaying the recorded permission mode, with no catalog or preset read, no session or conversation id, and `TAP_HOME` unset in the child. Refusals before any effect are code **2**: a missing recipe field (`crew_recipe_missing`), a row or env/tail recipe that differs from the one read, the caller's own pane, a pane not live in the row's session, a `server_socket` that is not the live server, a cwd selecting another registry, and `-m`/`--workdir`, which have no meaning for a fresh crew process. `--env`, `--unset-env` and `--` fold into the recipe with launch semantics (part 03, Session overrides) and are saved to the row once the respawn succeeds; a failed save still verifies and re-arms, then exits **1** (`crew_recipe_unpersisted`). `--dry-run` runs all of them and reports `would-replace`. Under reset custody, then the registry lock alone with a 1 s bound, it rechecks the row and drops `harness_session_id`, `transcript_path` and `identity_capture_result`, releasing both before tmux; it then rechecks the pane and the reset fence at the effect and runs `tmux respawn-pane -k` in the recorded pane. Any refusal or respawn failure (code **1**) restores the dropped identity. Success is `replaced` only after a stable new process is observed in the pane; otherwise code **7**. The pane id is kept, so the fresh harness's SessionStart rebind keeps the row crew. Poll rows stay exclusions. **Row classification happens BEFORE pane resolution**, so a poll row always leaves through `seat_not_relaunchable` rather than through a pane refusal phrased for launcher-managed seats. The refusal names the driver's session and points at `tap crew list`; this relaunch refusal does not authorize a driver-record replay, while `tap clear <crew>` now resolves the crew’s own persisted launch recipe and refuses if that recipe is unavailable. For the same reason `tap session restart`'s capped-seat suggestion is filtered through the same relaunchable predicate: `session_seat_states` carries no crew exclusion, so a driver session's crew rows appear in its busy map.

**It refuses a seat whose built launch carries no conversation id, and the refusal is the contract rather than caution.** The gate reads the launcher's **own resume-target decision** (`resolved_resume_identity`, the single function the invocation builder itself calls), not the `revive` tier and not the built argv: the tier is a listing-level proxy over `harness_session_id`, and claude resolves its own resume target independently and falls back to the picker when the stored id has no transcript on disk — a ghost id renders tier `exact` and argv `--resume` with no id. Gating on the proxy would pass, replace the process, and park the seat at a picker. **The gate resolves first and BINDS its answer to the launch**: the value it decided on is passed into the invocation builder, which consumes it verbatim rather than resolving again. One function called twice is not one decision — the resolver reads mutable on-disk transcript state, so a gate and a builder that each call it can disagree, and the disagreement that matters is the gate seeing an identity while argv is built id-less: the seat is replaced by a picker invocation, which is the degradation the gate exists to refuse, reached through a narrower window. An earlier form of this gate asked whether the stored id appeared anywhere in the built argv; that was rejected in review as neither sound nor complete — `-m` text equal to a ghost id satisfies it while claude has resolved to its picker, and a claude target legitimately derived from `transcript_path` or a quarantined id does not appear as `harness_session_id` at all. That is `tap clear` wearing this verb's name, performed on a working seat at the moment nobody is watching. The refusal exits **2**, `error_class=no_exact_resume_identity`, changes nothing, and names the fresh-context recovery — including the target team's worktree, since `tap clear` is caller-team-scoped and cannot reach across teams. The gate is evaluated **before** `--dry-run` returns, so a dry run reports the refusal rather than printing an invocation that would not be run. For OpenCode, a captured id passes this ordinary gate and becomes `--session <id>`; an id-less row receives the same `no_exact_resume_identity` refusal as every other harness.

**Codex directory prompt (tap-4tclq).** Codex stops at a "Working directory · resume" prompt when the rollout's latest recorded cwd differs from its start directory (codex-cli 0.159.3), and a relaunched seat has no one to answer it. Every composed Codex resume therefore adds `--cd <launch workdir>` ahead of the session id, whether or not the folders differ: resume by explicit id is not cwd-keyed, so naming the folder the seat already starts in is redundant, and nothing reads the saved transcript. Fresh launches and forks are unchanged, and a seat flag, tail or policy param that already sets `--cd`, `-C` or `tui.resume_cwd` keeps its choice. Resume, restart and relaunch share it.
