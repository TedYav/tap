# TAP Contract (v0.23)

**Installation completion (tap-7r3fn.135):** A completed install exits zero when only the current shell PATH lacks the installed bin directory, and prints the quoted add-to-PATH remedy followed by a completion line. Failed setup remains nonzero. Matching symlinks are left untouched. Uninstall names removed blocks and unset Git settings precisely; only containers recorded as absent before installation may be removed when empty.

**Harness wiring gate (tap-gjwtw):** The installer, the skill linker and `tap setup --machine` share one eligibility rule (`runtime/bun/src/install-harness-state.ts`). A harness home is wired only when its command is on PATH (`claude`, `codex`, `cursor-agent`, `opencode`, `agy`, `hermes`) or its hooks file already exists; an existing home with neither is reported `present, not wired`, left untouched by every writer, and wired by a later `./install.sh --sync` once the harness exists. A missing home is `absent`; a home whose hooks file already carries TAP's entry is `already wired`. Every install prints one state per harness before it writes any harness home or link (a `--sync` prints it after updating the checkout), and `./install.sh --report` prints the same states and writes nothing. `TAP_INSTALL_HOOK=0` is shown in that report per family: it skips the Claude, Codex, Cursor and Antigravity hook entries and OpenCode's session plugins, while skill links and the Claude/Codex native skill plugin stay managed.

**Installation prerequisites (tap-7r3fn.83):** The installer requires git, Bash 5 or newer, Bun, jq, and tmux, and names the missing-requirement remedy before installation writes; Python is not a requirement. The default command location is `~/.local/bin/tap`; `TAP_INSTALL_BIN` overrides it. With no override, an existing `~/Scripts/tap` symlink resolving inside this checkout is journaled with the new link before being removed; foreign links and user files are preserved with a refusal notice. TAP never manages the personal `~/Scripts` directory. The manifest retains the migration record, but uninstall removes only the current link and never revisits the old pathname. The checkout can live in any directory the operator keeps. A shared executable shim at the install location makes `tap` invocable from any shell whose PATH names that location; the shim resolves its checkout and execs the runtime, and adds nothing to child PATH — the optional marked shell block is what puts the install directory on PATH. A non-dry-run `session launch` checks for tmux and the selected harness executable on PATH before enrollment or reservation; missing tools receive installation instructions, not an unobservable-session or failed-start report. Cursor uses `cursor-agent`; Hermes uses `hermes` from PATH. Executable presence does not attest authentication. Dry-run planning does not require those executables. After linking and reporting the checkout, the installer runs any eligible machine wizard through the checkout before checking PATH. Its optional marked shell block includes the install directory when missing from PATH. If that directory is absent from the current shell PATH, the completed installer returns zero, reports the completed setup/config write when applicable, and prints a quoted PATH remedy followed by a completion line; a new terminal after shell integration or the printed export makes the links usable without reinstalling. It never prints `install: done` in that state.

**Recipient digest windows (tap-20ao):** `tap register|in --digest-window <seconds|off> [--include-asks]` and `tap digest-window <seconds|off> [--include-asks]` update the caller's qualified `[delivery.overrides."<team>/<handle>"]` table. Seconds are integers from 0 through 2147483647; zero has no coalescing hold, and off removes this recipient's short-window override and declaration. A declaration writes `now_window_seconds` and `digest_include_asks=false` unless the seat opts asks in. Notes use the declared short window; asks otherwise use the fleet short window (10s by default). Existing operator overrides without the declaration flag keep their prior all-message meaning. Explicit polite windows and urgent bypasses are unchanged. `tap team` displays effective short windows as notes/asks, with `digest_window_seconds` and `ask_window_seconds` in JSON. The setter accepts no foreign handle; registration with a digest option cannot target another pane. Existing batches retain their stamped deadlines; only subsequently armed batches see the new value. Declarations survive rebinds and clears until off. This supersedes v2's clear/reset and hold-recomputation clauses: changing an already-armed deadline would restore the earlier two-clock defect, and clearing context is not a change in cadence needs.

**Antigravity feedback survey:** A recognized terminal CLI survey (question, `[1] Good [2] Fine [3] Bad [0] Skip` choices and Gemini footer) is recoverable harness chrome. Native and Bash-compatible courier submission admit it to one bounded recovery under the existing submit lock. With a complete registered pane/instance/harness binding and clear reset/recovery/copy-mode boundaries, cautious and aggressive modes send one literal `0` (Skip), then reread and require an empty composer before attempting the sentinel. Report-only sends no keys. Recovery adds no Enter; Enter belongs only to the subsequent verified sentinel submission. Changed frames, missing authority, a remaining modal or pending composer text defer delivery without a sentinel attempt. Survey text in a draft, transcript or task card is data. Existing queued/possible-attempt evidence still prohibits blind redelivery; survey recovery distinguishes an exclusively created marker for the current attempt from an already-present marker and never erases either, and a cleared survey or placed sentinel does not prove recipient processing. No settings changes or additional daemon are required.

**Verbose diagnostics (tap-7r3fn.71):** Leading `-v` / `--verbose`, or `TAP_VERBOSE=1`, enables stderr diagnostics on both dispatchers. Verbose diagnostics describe the executing dispatcher and are not a cross-runtime parity surface. Flags after the verb retain their existing meaning, including argument values equal to `-v`. With verbosity disabled, stdout, stderr, return codes and execution paths retain their prior behavior. Bash tmux calls and launcher subprocess calls report argv, cwd, socket selection, TAP environment key names, exit status and captured stderr; native Bun tmux calls do the same. State diagnostics identify registry, payload, receipt and spool paths as those seams resolve them. Credential assignments, credential flag values and known credential environment values are redacted in diagnostics; environment values are not dumped. Existing command output is not rewritten. Failed launcher spawn/respawn calls make one bounded read of pane pid/status and the last 20 pane lines before the caller's existing cleanup, without the diagnostic read itself retrying the spawn; the initial-launch ENXIO retry has its own rule (§Initial-launch fork refusal). Diagnostics describe the commands TAP issues; commands subsequently executed inside a harness are outside this surface.

**Per-seat up/down:** `tap down <seat|team/seat>` stops one exact durable session and retains its row as `suspended:session_stopped`, including the instance, native conversation, launch recipe and outstanding mail. It collects crew rows sharing the verified owner session; stopping that session removes their windows. It never follows a crew pane into another session. A live-owner down names the affected crews in both human and JSON receipts and warns before removal that their unsettled inbound or outbound mail remains on the bus without a live recipient. Owner down does not scan or block on crew obligations and does not transfer them: hand off crew work before stopping the owner. Already-absent owner sessions leave all rows and mail unchanged. `tap up <seat|team/seat>` resumes the retained conversation detached with the stored launch settings and instance; it never recreates crew seats. Both accept `--team`, `--dry-run` and `--json`; a qualified target and `--team` together refuse. Unknown names, crew and poll rows refuse before effects. Up requires explicit native resume identity and never falls back to a preset, picker, latest conversation or fresh launch. A live ready seat is an up no-op; a positively absent session is a down no-op. An unreadable server or mismatched live pane/session identity refuses. A self-down saves its suspended row and prints `stop_requested` before stopping the session; that receipt describes the request, not post-stop verification. A surviving session restores its original row when the caller remains able to observe it. Neither verb settles or cancels mail. Only mail already accepted onto the bus is preserved: new sends to a suspended seat retain the existing refusal behavior. `tap team refresh --hard` may remove a stopped row and its resume authority; after that explicit cleanup, create a seat with `tap session launch`.
