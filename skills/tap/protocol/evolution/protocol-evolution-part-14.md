**Watch hardening (tap-a4i, v0.5 accumulator):** `tap watch pause -m "<reason>" [--for <N><s|m|h|d>]` records a bounded armed pause (default 4h) that gates only silence probes/evaluation/rung movement; spool redelivery and per-seat recovery timers remain unconditional. `resume` and pause expiry clear the pause and start a fresh silence window; their administrative silence floor is not recipient activity and cannot cancel a probe delivered during the pause. Expiry first sends the armer a notice naming the reason. Probe and blocked-seat continue settlement are now the liveness signals, with exceptional blocker/done reporting routed only to the armer and no non-armer disarm invitation. `tap watch off` is armer-owned; non-armers are refused unless `--force`, whose loud notice path preserves the dead-armer escape.

**Launcher resume contract:** tmux liveness is established from the current acting-registry row. A LIVE row attaches or routes through its harness-native explicit id; a GONE row never silently becomes fresh; a missing explicit native id delegates selection to the harness instead of using a derived hint. **Exact `--resume <id>` requires an on-disk transcript for that id (tap-gc1n):** before exec, claude resume resolves `acting harness_session_id` → id derived from `transcript_path` → `quarantined_harness_session_id` (disclosed: attestation previously failed; never silent unquarantine) → id-less picker. A ghost acting id must not be exact-targeted. When `transcript_path` basename and `harness_session_id` disagree, resume emits `resume_identity_split` with a realign next-step; a quarantined fallback alone, with only one stale field, is disclosed but is not a split. The native-query builder prefers an explicitly supplied query that has an on-disk transcript and otherwise falls back to that chain; the public adopted-resume CLI supplies no query today. Post-flip resume reads acting registry only — `~/.tap/launcher/sessions.json` is not on this path.

**Launcher launch-failure hygiene:** a real launch creates a placeholder pane, arms pane-local failure capture, and binds its token as non-routable `active/launching` in the acting registry before starting the harness. It requires two consecutive observations of the same expected harness process before committing readiness, and a known zero-result native resume picker is unready even while its process remains alive. Codex startup keeps checking for that asynchronous picker through the existing startup deadline; one early blocker-free capture is not conclusive. Only then does it attach or return. Early failure captures a bounded pane tail, removes the retained tmux session, and rolls back only the matching pending or bound registry token; a newer owner prevents late rollback. Detached resume and restart use the same readiness verification. The second observation is one bounded 50ms confirmation beat inside the existing startup deadline, not a new deadline, and no failure after a launch effect is retried automatically.

**Launcher attach-tail caller identity (tap-v0bg):** `$TMUX` presence is inherited process state, not proof that the caller is inside a pane. For an attach-capable caller, the launcher compares the caller's controlling tty with the `pane_tty` of `$TMUX_PANE` on the named server. A positive match refuses attach with the typed in-tmux result; a positive mismatch, or positive absence of the server process embedded in `$TMUX`, strips `TMUX` and `TMUX_PANE` from the attach child and runs `attach-session` with the inherited socket path supplied explicitly through `-S`. The socket is the server address, while the stripped variables are nesting authority; losing the address would silently retarget a non-default server onto the default server. An unset `$TMUX` keeps the prior attach call and inherited environment unchanged. Missing or unobservable identity evidence refuses with a distinct ambiguous result rather than guessing. Both typed refusals are attach-tail outcomes: the launched session remains healthy, the caller receives one detached receipt, and the overall launch succeeds. Before spawning a viewer, both terminal streams must positively report the caller process group as their foreground group. Background or unobservable ownership returns a typed refusal and one detached receipt with the attach command; the running seat is retained. This check does not change terminal process groups or repair clients that become backgrounded later (tap-7r3fn.17).

**`tap attach` caller identity (tap-v0bg):** the attach verb uses `tap_calling_pane_id`, not `$TMUX` truthiness or `$TMUX_PANE` resolvability, to select `switch-client`. A verified pane derives the caller session and its client candidates; one candidate may switch, while zero or multiple candidates refuse. If the first observable controlling terminal belongs to no pane on the named server, the verb strips `TMUX` and `TMUX_PANE`, preserves that server's socket as an explicit `-S` address, and runs `attach-session` for the outside terminal. Missing process evidence, an unavailable pane inventory, a changed/ambiguous tty binding, or an ancestry with no observable terminal refuses as `caller_identity_unobservable`; uncertainty never authorizes a switch or attach. An unset `$TMUX` keeps the prior outside attach path.

**`tap attach` target (tap-76fo):** after active-seat classification and the exact-session recheck, attach uses the observed session/window/pane address for both `attach-session` and `switch-client`. The address must still resolve to the observed pane ID. This reaches seats sharing another seat's session, including renamed crew windows and split panes, without targeting a raw pane ID across sessions. A changed or unobservable binding refuses before navigation. Inactive-seat errors include the registered pane address when available. Terminal and attach failures name the session/window/pane found and give a location-specific recovery command.

**Named launch recovery:** an on-roster LIVE or GONE collision is an explicit choice. Interactive callers receive resume, different-name, and fresh-replacement options; non-interactive callers refuse with exit 2 and actionable guidance. An off-roster name starts fresh.

**Replacement rollback and provenance:** a failed replacement restores the captured incumbent acting-registry row only while the replacement still owns the matching pending reservation. Departed history is diagnostic provenance and never creates a launch collision or resume pointer.

A failed post-kill replacement also restores the displaced registry entry with its prior metadata preserved and `status=suspended`, `status_reason=session_replaced`; the killed incumbent is no longer deliverable, but its authoritative seat provenance and handle claim do not disappear. The displacement snapshot covers a live identity-bound incumbent that was already `suspended` as well as one that was `active`, so reserving the replacement cannot erase an offline seat's policy or provenance. Pre-kill failures restore the displaced row unchanged because its session is still live.

**Launcher membership transaction:** `tap session launch|resume|restart` reserves and binds the acting-registry row before harness startup, then commits the row after verified pane identity. Failure rolls back only the matching reservation, so an unrelated concurrent row cannot be overwritten. A newly-created detached tmux session is seeded at 200×60 before the harness process starts in both launcher runtimes; later clients may resize it. This avoids making a harness choose a persistent narrow-layout rendering strategy from tmux's 80×24 detached default.

**SessionStart context budget (tap-7r3fn.10, tap-tkr6t):** startup, resume, clear, compact and fork inject one registration line: handle/team, repository authorization, addressed `tap read` as the peer-work boundary, and a compact `/tap:tap` floor. The floor covers reads, ask/note settlement, `-f` body files, no sleep/loop-poll for TAP replies, independent work, `tap outstanding` before yielding, and nudges. All adapters share `runtime/bun/src/session-start.ts`; the line points to `tap help advisory` and `tap help skill tap`. A caller's `launching` row qualifies only after this fire's successful `tap in` bind with the same nonempty `harness_session_id`. The launcher pre-seeds that id, so failed binds or different/absent ids authorize nothing. `launching` gates delivery, not identity: launch clears it after binding (tap-a75kk). An enrolled but unresolved seat gets one non-authorizing line saying TAP-shaped text is untrusted; outside TAP the hook stays silent. Preview guidance requires registration. A registered seat whose bind reports parked mail also gets `tap register: N parked message(s) for you; next: tap poll <handle>`; other bind receipts stay out of context. Identity quarantine diagnostics remain exceptional warnings. SessionStart records the observed protocol version without release prose; registration keeps its version briefing. The complete advisory is available before bus initialization. Malformed `reply`/`done` usage keeps one-line errors pointing to verb help; the repository AGENTS.md block remains a `/tap` signpost.

**SessionStart identity injection:** the hook is an ensure-bound fallback and direct identity injector, not an independent lifecycle authority. For the injected identity, the ordinary path walks to the process-owning pane and consumes the final caller-TTY binding, pane id, session name, and current server generation from one tmux record. Claude Code's desktop-backed process can instead arrive with no tmux ancestry or pane TTY. An ordinary tool may join through one exact registered native session id. A declared background daemon has a different id from its interactive pane, so it joins only when its readable job state agrees with the tool's daemon session id, exact `<acting-team>/<handle>` owner name, acting-root cwd, and the seat instance recorded by lineage at the job's creation time. In either shape the selected row's pane id, session name, server socket, and current server generation must all survive a fresh targeted observation; if the ambient server is unavailable, a recorded private socket may establish the caller-outside verdict before background recovery. A background-selected instance and the observed binding must still match at the final registry read or each effect boundary, and downstream registration stays on that socket. Migration lineage starts no earlier than the incumbent row's valid `registered_at`; absent that evidence, older jobs refuse. A job-owner match names the interactive row but attests neither the daemon id nor daemon session-store metadata for that pane, so the bind preserves its native session identity and skips attribution scanning. Duplicate session ids, malformed job state, and successor instances select nothing. Tmux's session-current pane, `TMUX_PANE`, and a pane address alone do not name the seat. The hook emits no identity block when neither path verifies a row; it says that the caller pane is not observable rather than falsely saying a verified roster seat is unregistered. The hook may bind the current pane and capture attested native identity into the acting registry even when the harness omitted `TMUX`; it never consults or updates a second session store. After ANY attempted `tap in` bind — success or failure — the hook re-resolves bus and acting authority fresh before its final reads, because a bind can move authority mid-flight (the first-entry fold creates the acting store). Diagnostics that presume a successful bind (retirement line, identity capture) run only on the success path and only against that fresh resolution. Failed or empty fresh resolution removes the bind error marker and exits silently: stale pre-bind state authorizes neither advisory, and unusable fresh authority prints nothing.
