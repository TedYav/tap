**No per-turn roster push (tap-hx4r, removed 2026-08-19; was tap-he46).** TAP does not inject a team roster, or anything else, on every prompt. Availability is a PULL model: agents learn TAP's transport and their own identity once, at SessionStart, and a send/attach/resume verb that targets an unreachable seat answers with a structured refusal naming the actual state (unknown handle, suspended, still launching, and similar) at the moment the question is asked. That refusal surface is the availability answer; there is no separate standing broadcast to keep in sync with it. The removed roster line pushed a one-line team snapshot on every UserPromptSubmit specifically to keep a compacted transcript from acting on a stale earlier roster — and its wording, which asserted more than a team-local snapshot could support, caused a bidirectional cross-team deadlock between two seats each correctly following what it told them (tap-w1hg). Per-turn injection needs a very strong reason to earn a place in the protocol: conditional and load-bearing (injects only when a specific detectable condition makes the information necessary right then), or it is not shipped — see docs/solutions for the full criterion this removal is the first application of.

**Installer checkout safety (tap-3wl):** `install.sh` derives the persistent primary checkout from Git's canonical common directory before its first write. Any checkout not provably that primary — including a linked worktree or non-git source copy — refuses real/default targets loudly; a linked-worktree refusal names the primary path, while a non-git refusal names the missing proof. Execution from an unverified checkout is allowed only when all eight mutable target surfaces are explicitly redirected (`TAP_INSTALL_BIN`, `TAP_CLAUDE_HOME`, `TAP_CODEX_HOME`, `TAP_HERMES_HOME`, `TAP_CURSOR_HOME`, `TAP_OPENCODE_HOME`, `TAP_CURSOR_AGENT_HOME`, and `TAP_AGENTS_HOME`), or when the caller deliberately sets `TAP_INSTALL_FORCE_NONPRIMARY=1`; every force path emits a stderr breadcrumb describing the checkout. Target defaults and the all-redirected exception are driven by the same target set so adding a surface cannot silently make the exception fail open. Target overrides are an all-or-nothing intent signal; the installer does not guess whether arbitrary paths look temporary.

**Installer checkout freshness (tap-3ywn):** the installed `tap` reads the persistent primary working tree. A merge updates `origin/main`; it does not update that tree. Live code is the ancestor predicate `git merge-base --is-ancestor origin/main HEAD` on the tree `bin/tap` resolves to — not "N commits behind" (a beads-only ahead pile already contains origin/main). Default `install.sh` relinks and reports `live` / `STALE` / `CANNOT-CHECK`; a missing `origin/main` ref is CANNOT-CHECK, never live. The check fails open (informs; exit 0). `install.sh --sync` is the opt-in mutator: fetch + fast-forward/rebase the primary iff the working tree is clean except `.beads/issues.jsonl` — unstaged drift of which `--sync` restores to HEAD before mutating (STAGED changes to it refuse: staged is a deliberate act, not regenerable noise), with a second restore immediately before the pull closing the classification-to-mutation window — and unique local commits touch only `.beads/issues.jsonl` — asked as the **merge-base** diff `origin/main...HEAD` (three dots), never the two-dot `origin/main..HEAD` (tap-feqg). Two dots compare the two endpoints, so every file changed by commits the primary is BEHIND on reads as local work, and `--sync` refuses its own merged fix as stranded — the false refusal that fired once per merge day until it was fixed. The predicate asks what the LOCAL commits touch, which only the merge-base form answers. Then relink from the primary. `--sync` is invokable from a linked worktree; git writes and the subsequent relink target the primary, never the worktree (tap-3wl stands). `--sync` refuses closed — STAGED beads → `bd sync` from primary (it commits the staged export) then re-run `--sync`; sibling non-beads dirt → wait and ask the bus (tap-hl8i); unique non-beads commits → stranded-work alarm, ask the bus, do not reset. A refused `--sync` is a HOLD: the merged fix is not live. `tap doctor` emits the same checkout finding as a warning; it does not flip torn-payload exit. This is not a deploy system: no auto-pull, no fetch on every `tap`, no copying binaries out of the checkout.

**Installer replay recovery (tap-7r3fn.72):** `--sync` requires primary `main` with no existing rebase and rechecks its starting HEAD before pulling. Its pull selects Git's merge backend so rebase metadata exists before checkout hooks run. The Beads checkout hook defers database access during current-worktree or primary rebase state; the existing pre-commit export guard stays active, as do unrelated Git hooks. After success, the installer invokes the existing checkout importer once on final `main`, retaining its advisory import-warning policy and adding no unconditional database export. A failed pull aborts only a replay whose original HEAD, branch and last reflog action identify this invocation. Recovery is reported only after verifying the original `main` and absence of rebase metadata; failed or unowned recovery refuses relink and leaves state for inspection. Duplicate-key import warnings are a separate Beads import defect.

**Bun decision slices:** Bun is a prerequisite in every TAP runtime mode; `install.sh` refuses before installing links when Bun is absent from PATH. Migrated notice and digest decisions require it. Their shared `tap_bun_call` boundary has no Bash fallback. Missing Bun emits `runtime_missing`; failed or malformed classification emits `slice_failed`, naming the slice and original id.
