**Registry lifecycle — reboot vs shutdown (tap-w3op):** three states for the acting team registry under a live flip marker — present-populated, present-blank, absent. `tap team reset` stops and retires selected parent families through the same engine as `tap team out --hard`. It retains the acting registry envelope, enrollment, bus, mail, watch state and retirement history, including when `seats` becomes empty. The caller is selected by default and stopped last; `--except <self>` spares it. An unreadable caller identity refuses hard retirement before any family is retired. Checkpoint cuts and reset's old override flags are retired; restore and purge are non-mutating tombstones. Existing archive bundles remain untouched. Shared reset fence/generation guards remain until their separate retirement; stale fences require manual recovery after confirming no reset owner is running. See the seat-lifecycle contract for current selection and consent rules. `tap team shutdown` is **shutdown**: after stopping verified sessions it **deletes** the acting registry file so resolve becomes `live_unreachable` until re-init, including when the registry is already blank (`seats: {}`); it **retains** the `<registry>.lock` sidecar so every opener shares one flock identity (never unlink-after-release). Existence checks, generation consumption, and deletion run under that sidecar flock — generation is consumed **before** registry absence is exposed so an interrupt cannot leave a false deliberate-reset marker. `--keep-self` retains spared seats in-file instead of deleting. `tap team down` continues to retain the acting registry. `tap init` recreates the blank acting registry at the **stored** `registry_location` on `live_unreachable` using the enrolled global team key (not `basename(root)` when they differ); canonical sibling only for `live_unenrolled`. It must run from a bare shell with `TMUX` unset (seat registration via `tap in` needs a pane and is a different verb). `resolve_team_registry_for_root` returns the stored location alongside `live_unreachable` when known. `tap doctor`, on `acting_registry_unreachable`, reads `reset-generation.json`: `state=pristine` means deliberately-reset residue → next `tap init` (never restore, which undoes the reset); otherwise lost/shutdown-absent → next `tap init` only (shutdown consumes the generation marker, so restore's pristine-generation gate cannot succeed on that path — do not advertise restore).

**Matched tap-in identity update:** when an explicit team+handle claim matches the existing seat's pane, or its recorded pane is gone, registration adopts an observed identity only for an unattested SessionStart drift or an untrusted-resume orphan on the registry surface; duplicate-owner and launcher-expectation quarantine remain refusals — the launcher-expectation one **withdrawable by the operator** with `tap register <h> --accept-observed-identity`, the duplicate-owner one not, since only the first is a question an operator can answer, with the quarantine chain ordered duplicate, expected, untrusted, unattested. Updates record `action=updated` with old/new identity detail in `registry-events.log`; the operator receipt is an additional convenience. Claims from a different live pane remain outside this arm: mismatch enforcement and `--force` provenance are pending in U4.

**Session-name authority (no sentinel version change):** an active pane seat is now an observed conjunction, not a stored-row assertion: the exact tmux session name exists in one readable current-generation snapshot, the row's designated address/id is a member of that exact session, the row's boot/server stamps are current when present, and the expected harness is positively observed in that pane. macOS boot stamps prefer the stable `kern.bootsessionuuid` as `bootuuid:<uuid>`; hosts without that oracle fall back to `boot:<sec>`. During migration, a numeric legacy row stamp matches only when it is within five seconds of the independently observed current boot epoch; UUID stamps remain exact. A legacy row with no expected harness refuses as `unknown/harness_unattested`: observations may confirm an expectation but never mint one at read time, and `tap in` is the attested write-boundary repair. `harness_mismatch` remains reserved for a positive conflict with a present expectation. Exact-name absence on the current generation is `gone`; so is a valid recorded pane ID absent from a readable pane set in an epoch-matched existing session, unless its address has rebound. This shared predicate also governs `out --last` (`-` alias), which excludes stored pending, poll and suspended rows except delivery-marked `pane_gone` rows; prior boot/generation or a positively observed exited harness is `offline`; conflicting or unobservable evidence is `unknown`. Every non-active result blocks pane delivery. Bare `tap team refresh` deletes only `gone`; `offline` preserves native resume provenance and `unknown` never licenses mutation. For commands that act on the current session-name namespace (`session launch`, `session resume --all` / `team up`, `session repair`, `session list` / completion, and `team refresh --hard`), tmux's canonical `no server running on ...` and `error connecting to ... (No such file or directory)` responses positively prove an empty namespace because sessions are children of the server process; every other failed or malformed snapshot remains unobservable and fails closed. The separate liveness observer still returns unobservable for no-server, so its answer alone never licenses generic row reclamation; namespace-scoped consumers choose their documented polarity. `resume --all` passes its already-authoritative namespace snapshot into pending-launch expiry instead of re-probing. Active registration and launcher binding stamp `boot_id` and the observed tmux `server_socket` alongside `server_epoch`. `tap register` refuses a known foreign socket namespace in the team unless `--namespace-crossing` is explicit; that flag permits membership, not invalidation or deduplication of foreign rows. Unknown socket provenance never authorizes namespace invalidation. `tap session repair` re-attests and re-stamps both values under the registry lock even when the stored pane coordinates are otherwise current. **No dispatch-time rewrite (2026-09-23):** a positively observed epoch/boot mismatch is judged at every reader, which renders the row `offline` (`server_epoch_stale` or `boot_id_stale`) and never trusts its stored coordinates; ordinary dispatch no longer catches the durable row up. The installed entry (`bin/tap` → `main.ts`) never ran that rewrite, only the retired Bash preamble did. A stale `active` row therefore keeps its stored fields and remains a relaunchable resume member (`seatIsRelaunchable`, runtime/bun/src/launcher/complete.ts). `tap cancel` and `tap compact` still invoke the lib.sh rewrite for their own teams; there, a row already suspended keeps its stronger lifecycle reason, so a deliberate removal never becomes relaunchable because the machine restarted. Direct send, spool replay, digest, and nudge re-authorize the full conjunction before the first pane write and again at submit effects. Watch builds each tick's pane-reading roster from the same observer and never captures a stored-active row that the current cycle classifies non-active. Tmux observation and PTY input are not atomic; the checks minimize that window, while eliminating it requires a future harness-native delivery channel.

**Agent-facing version brief:** `runtime/bun/src/version-briefing.ts` owns the briefing shared by registration and SessionStart. `SENTINEL_VERSION` in `runtime/bun/src/sentinel.ts` is the protocol version source; `skills/tap/VERSION-BRIEF.md` carries one `## TAP v<version>` section per protocol release. Registration consults machine-local `~/.tap/version-seen.json`, keyed by `<team>/<handle>`, and emits the matching release detail when the recorded version differs. A seat with no record is silently baselined. Visible output must finish before the new version is recorded; publication uses an exclusive 0600 temporary file, fsync, then rename. State failures preserve existing bytes and unknown fields. The persistent sidecar lock interoperates with Python flock and has a one-second acquisition budget plus bounded helper overhead, replacing the former indefinite wait. On contention or unavailable state, visible calls emit the degraded pending notice and a diagnostic; record-only calls emit only the diagnostic. Neither proceeds unlocked, and a later ordinary invocation retries. Briefing failures, including stdout failure, cannot fail a committed registration. JSON registration and qualified SessionStart calls record without release prose. Skipped calls, including OpenCode's quiet bind, record nothing; OpenCode's briefing surface remains separately tracked. Identity qualification stays with the caller's active `<team>/<handle>` resolution, and version state stays separate from registry files.
