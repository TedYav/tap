Native hybrid forms include `whoami --json`, `poll --json` (including `--quiet`), and machine-wide `team list` discovery before cwd bus selection. An unanchored poll delegates before directory creation to preserve Bash's caller-terminal diagnosis and exit-4 remedy. JSON output retains Bash's fields and exit codes; malformed poll payloads are quarantined before routing, with the aggregate notice on stderr in JSON mode. Wrong-cwd `whoami` preserves the registered-pane diagnosis and executable `cd` remedy. `poll --team` uses the shared root-derived enrolled bus (tap-7r3fn.84); named `team list <name>` retains Bash's roster projection, and team lifecycle forms remain Bash-owned.

**Pane and obligation lock roots:** `panelock.lockRoot` (`runtime/bun/src/panelock.ts`) resolves the root in this order: non-empty `TAP_LOCK_DIR`, then non-empty `TAP_INDEX_HOME` plus `/locks`, then non-empty `TAP_HOME` plus `/locks`, then `$HOME/.tap/locks`. The `TAP_HOME` tier applies only to a caller-pinned bus: when `TAP_HOME` equals the `TAP_TEAM_OVERRIDE_BUS` marker (the `--team` override sets both), the tier is skipped and the root stays the default, so a derived bus does not get its own lock directory. A child spawned for a resolved bus receives the parent's root as an explicit `TAP_LOCK_DIR` (`childBusEnv`), so parent and child exclude each other. Empty pins fall through as unset pins do. Pane-submit sidecars use `pane-submit-<sanitized-pane-key>.lock` under that root, so a pinned index cannot put the two runtimes in separate critical sections. A register whose caller had no pin publishes the derived bus in-process only after pinning the lock root the process had resolved (the `childBusEnv` rule without a spawn boundary), so the publication never moves that register's own lock root under the bus.

**SessionStart command authority:** the shared context hook invokes the TAP shim in the checkout that owns the hook. Its `ROOT` argument selects the user's bus, not an executable; a same-named command on `PATH` cannot replace the hook's TAP runtime. An unavailable owned shim follows the existing failed-bind path.

**Old registry formats are never converted:** `registry_migrate.py` is deleted. `tap admin migrate-registry` stays for one release as a stub that always refuses `old_store` (exit 1). Every `old_store` refusal names the file and why it is old. A team or bus registry is upgraded by hand (rename `agents` to `seats`, add `"schema": "0.20"`) or moved aside before `tap init`; an old `teams.json` or launcher manifest is moved aside. New global registries carry no `migrated` stanza; readers never required one.
