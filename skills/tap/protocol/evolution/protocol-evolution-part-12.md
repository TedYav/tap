**Changes since v0.17 (the v0.18 sentinel diet — tap-wt0i):** `path=` was roughly half the bytes of an ordinary same-bus sentinel and carried nothing the recipient did not already hold — the `id`, plus the recipient's own bus root — so it is now **omitted when it is derivable and kept whenever it is not**. **The predicate is evaluated courier-side at send time and is path-equality, not team-equality:** `path=` is dropped IFF the payload's absolute path equals `<bound-recipient-bus>/payloads/<id>.md`, where the bus is derived from the registry the send actually bound via `tap_bus_home_for_registry` — the SAME derivation `tap_authority_context` uses for `TAP_AUTH_BUS`, so delivery and the wire pointer cannot disagree about where the recipient's payloads live. **(tap-tz52 correction, v0.20):** this was originally specified and implemented as `dirname <target-registry>`, which was correct only while the bound registry lived INSIDE the bus (`<root>/.tap/bus/registry.json`). The v0.20 flip moved it to `<root>/.tap/team-registry.json`, one level ABOVE the bus, so the dirname form expected `<root>/.tap/payloads/<id>.md` while the bytes sat at `<root>/.tap/bus/payloads/<id>.md` — the equality failed on every same-team send and `path=` returned fleet-wide until the predicate was pointed at the shared helper. A registry shape the helper cannot map to a bus (a relocated acting store outside `<root>/.tap/`) FAILS CLOSED to keeping `path=`; the predicate stays a pure function of its arguments and never consults the machine index at render time. It is deliberately NOT derived from two tempting proxies: the recipient's TEAM NAME (same team is not same bus — a `TAP_HOME` override, a legacy `tmp/tap` tree, or any custom root breaks that inference) and the courier PROCESS's ambient `TAP_HOME` (a watcher draining a spool entry may hold a different root than the seat it is delivering to; the entry's stored `target_registry` is the authority). **Recipient rule:** a sentinel with no `path=` means the payload is at `$TAP_HOME/payloads/<id>.md` resolved through the SAME order the CLI already uses — env, `<repo>/.tap/bus`, legacy `<repo>/tmp/tap`, default — never a `<repo>/.tap/bus` string invented from cwd, which would break every `TAP_HOME` seat and legacy bus on the machine. `tap reply <id>` / `tap done <id>` already take bare ids and need no new flag or verb. **`path=` is still KEPT, unconditionally, wherever the recipient cannot derive it:** cross-team and cross-worktree relays (the canonical lives on the SENDER's bus, and the cross-team reply route derives `sender_bus = dirname(dirname(path))` from that very field — §Cross-worktree relay); digests (their pointer names the courier index `<bus>/spool/digests/<id>.json`, which can never equal `payloads/<id>.md`, so the equality declines on its own rather than by carve-out); and an unbound target (a manual `--cross-worktree --pane` send does no registry lookup, so it can prove nothing about the recipient's bus and never drops the pointer on a guess). **Scope fence:** this is the SENTINEL WIRE only — the payload envelope's own frontmatter `path:` field is unchanged, because `tap poll` and the surrounding tooling read it. **One constructor:** all three injection sites (direct send, redelivery replay, courier digest) now render through `lib.sh`'s `tap_sentinel_render`, so the predicate cannot be implemented three ways or missed at a fourth site; `tap_reconstruct_sentinel` and `tap_digest_sentinel` each grew the bound registry as a parameter, and `tap_reconstruct_sentinel` now REFUSES a payload argument that is not the ambient canonical for its id: it reads frontmatter from the argument but derives the wire pointer (and now the diet predicate) from `payloads/<id>.md`, so a caller handed a file elsewhere would otherwise emit — or silently omit — a pointer to bytes that are not there. Its only caller moves the payload to that exact location first, so the check is a no-op invariant that fails loudly for any future one. No other field is dieted — `v=`, `kind=`, `from=`, `to=`, `reply=` each carry information that is not derivable and all stay. **Migration is social, not mechanical (deliberate ruling — capability negotiation and a persisted locator mode were both considered and rejected as overcomplicated for a single-machine bus):** old sentinels already sitting in panes still carry `path=` and still work; both stuck-sentinel parsers (`tap_stuck_sentinel_id`, `tap-nudge`) key on `id=` and already tolerate absent trailing tokens; and a seat that meets a sentinel shape it does not understand should **ask the sender** — on a push bus the sender is one `tap reply` away.

**Changes since v0.16 (server-epoch identity):** tmux pane and session ids are scoped to one server lifetime. Current acting-registry rows carry the observed server epoch; a stale-epoch locator may aid diagnostics but never proves current identity or resume authority.

**Changes since v0.15 (the v0.16 cross-team reply ergonomics — tap-g3o6):** a cross-team `tap reply` derives its return route from the inbound payload's own absolute `path=` (`sender_bus = dirname(dirname(path))`) via a new `tap send --remote-registry <path>`, so a reply delivers even when the peer team is absent from the machine index (tap-j20w: the index is routinely incomplete; the payload is self-contained). `from_team` is display-only; the path is the route. **PRE-FLIP ONLY, and superseded for the post-flip case (tap-7r3fn.8, ruling 2026-09-04).** Post-flip, `tap reply` requires `tap_authority_context` and refuses `unreachable_team` rather than falling back to the retired bus mirror, so the machine INDEX is the route and the path-derived one is the pre-flip `else` branch. What makes the index dependable is enrollment at register (R13, tap-nvtx): every git-worktree team is enrolled before its first seat binds, so a team that can send has a registered sender and a registered sender in a git worktree is enrolled — what remains outside are non-git directories, which are not stable machine-wide addresses. tap-j20w is a 2026-07-22 pre-v0.20 observation. The v0.23 pointer rule follows from this: `path=` iff bare-recipient relay **or the sender's team is unindexed at construction — probed, not declared** (§Sentinel). The `no_actor` error **prefills** the exact `--by <to>` from the payload's addressee but never auto-adopts it (explicit settlement provenance); a bare `tap reply <id>` for a foreign inbound stays a teaching `not_found`. `tap outstanding` tags a cross-team row `[cross-team: settles on their bus]` (retiring the terse `outbound-relay`) with JSON `addressed_team`/`settles_on: "peer_bus"`, and `tap poll` names the polled inbox (`inbox for <team>/<me>`, JSON `team`) — poll = my-bus inbound, outstanding = my outbound, never conflated. §Cross-worktree relay adds a verify-landing recipe: confirm a cross-team send by its own `injected`/`queued` result and the payload on the sender bus, never by listing the peer's `payloads/` directory. See §Cross-worktree relay.

**Changes since v0.14 (the v0.15 courier digest — tap-ix63):** a spool drain that finds **N≥2 plain-redeliverable entries bound to the same recipient** in one claim snapshot injects a v0.23 note sentinel with the `digest` tag whose id resolves a courier-owned index of the N payloads; `path=` is retained only when the enrolled-bus resolver cannot locate it — N wakes collapse to one doorbell. The digest is a delivery envelope only: each listed payload keeps its own `reply=`, receipts, and `tap outstanding` visibility, and `tap done`/`tap reply` on the **digest id refuse** (`error_class=not_obligation`) naming the index and per-id settlement. `courier` is reserved-and-unroutable (`tap register` refuses it as a handle; `tap send` refuses it as a destination and `--from`). Coalescing is always-on at N≥2 with no knob; `urgency=urgent`/`kind=escalate` are carved out pre-claim and flush solo first. The transaction is submit-then-move (spool copies stay through the attempt, then all N move to canonical on verified or submit-unverified outcomes), claim-snapshotted via the per-id `.claim` CAS, splits oversized claims into successive digests (never truncates), discards the index on a pre-effect refusal, and otherwise retains it until all N are terminal and the minimum read window has elapsed. See §Spool → Courier digest.
