**Gone-row launch collision takes the reseat door, not the attach door (tap-jcma):** an on-roster row that the epoch-aware observed-gone judgment condemns — recorded pane absent, or its ids stamped under a prior server generation with no live session name vouching for it — is offered the RESEAT chooser, never the attach chooser. The two are not interchangeable and the difference is what `[r]` can deliver: the attach door's `[r]` reattaches to an existing session, so offering it for an incumbent that is not there sends the operator into a resume that finds no record, whose create-fallback re-enters launch and arrives back at the same prompt having changed nothing — a dialog cycle `[r]` can never escape. On that door `[r]` follows RECORD PRESENCE, and the gloss states which it will do. With no surviving record there is no conversation to restore, so `[r]` reseats fresh under this name — taking the same replacement authority as `[k]`, emitting its gone-row receipt, and advertising the `fresh` tier rather than a picker or an id it cannot open. This is U5 as already stated above: a gone row still occupies the name and launch reseats it. A gone row whose record SURVIVES keeps `[r]` on the resume delegation, so a recorded conversation is never discarded by a door that just offered to restore it; the loop cannot return through that path, because the create-fallback that caused it fires only when no record is found. An incumbent that is merely UNVERIFIABLE rather than positively gone keeps the attach chooser, because unobservable state means protect, not recreate. Non-interactive callers are unchanged: exit `2` with the same recovery doors.

**U5 intent-verb and retired lifecycle surfaces (tap-9tqt, tap-3xw3):** `tap session launch <name>` is create-intent. An off-roster name starts fresh and does not consult departed history. An on-roster LIVE or GONE row occupies the handle: an interactive caller chooses resume, a suffixed sibling, fresh replacement, or quit; a non-interactive caller exits `2` with the same recovery doors. A direct `tap session resume` whose name is roster-occupied but has no launcher record refuses with those fresh/suffix doors; it never offers or executes a create fallback under the already-owned name. A live tmux session with no roster row is reported as a tmux-namespace collision and offers suffix / replace / quit, never resume. `tap session resume` and `tap team up` are the restore doors. A registry row's explicit `harness_session_id` may drive exact native resume; when that field is absent, the harness's own picker/latest behavior is used and `derived_harness_session_id` is never promoted to authority. GONE state is visible in `tap team`; the retired census and prime verbs are absent from help and dispatch. `tap session launch` alone may bootstrap and enroll a genuinely `live_unenrolled` root; resume and restart never create membership.

**Changes since v0.19 (the v0.20 registry single-source flip):** `tap admin migrate-registry --yes` is the sole explicit cutover and `registry_migrate.py` is the sole legacy `~/.tap/launcher/sessions.json` reader. After publication, the acting team registry is the complete current session authority: routing, collision checks, list, completion, resume, restart, repair, stop, reset, restore, and relaunch read and write that row. The global registry only locates the acting file; the bus registry and the archived journal are never fallback authority. Launcher-owned rows carry the session name, harness, cwd, model, passthrough, timestamps, status, delivery, and explicit native session provenance. Registry `session_attribution_trust=env` outranks stale migrated provenance. Relaunchability excludes crew, explicit poll delivery, and rows suspended for removal or pane loss; `session_stopped`, `restored_from_archive`, and `server_restarted` pane rows remain eligible. **Native lifecycle target (Lane C, no version bump — verbs still Bash-owned):** `runtime/bun/src/lifecycle-target.ts` is the Bun twin of those two functions, plus the per-seat grammar and the durable out/down/up/shutdown matrix later native team-stop units implement. Canonical session names are `<team>/<handle>` (slash only; `team:handle` remains input-only). `--except`/`--only` still take bare team-local handles. Canonical acting-team selection is selector Stage 0 (`tap-1t0h.1`); this module does not export a second acting-team authority, consult the global index, or choose a team. The four durable seat operations are distinct: `out` deletes the row and leaves the session running; `down` retains a suspended row and stops the session; `up` retains and resumes; `shutdown` and `out --hard` share one hard-removal mechanism (delete row and stop). The shared fate object names the mechanism, not the invoked public verb; receipts, events, logs, and rendering use the requested action so `out --hard` is never labeled `shutdown`, and crew `out` is never labeled crew `shutdown`. Team-wide `down`/`up`/`shutdown` keep team scope; team-wide shutdown keeps its historic no-tombstone acting-file deletion. Crew `up`/`down` refuse (ephemeral); generic crew `out`/`shutdown` dismiss the process and row. Crew dismiss tmux fate is `none` — window teardown is D's kill-window contract, never `stop-named-sessions` (that would stop the operator/driver session the crew window lives on). Owner `up` never recreates crews. Crew window effects consume D's callable contract and are not implemented here. Native `team down|up|shutdown` and `tap out --kill` remain Bash-owned until a later C unit routes them.
