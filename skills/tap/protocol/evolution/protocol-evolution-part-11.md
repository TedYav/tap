**Picker fresh replacement (tap-5ils; 2026-08-06):** choosing `[k]` in the named-seat collision picker, or its `--fresh` equivalent, is unconditional authority to stop the canonical session name displayed by the picker (`<team>/<handle>`). Stored pane/session identity may neither veto that stop nor redirect it to another name; `[r]` resume and `[n]` suffix semantics are unchanged. Before the pending reservation mutates the row and before tmux is stopped, the launcher writes a COMPLETE-last bundle under `<root>/.tap/backup/session-kill/`. For a rostered seat it contains the full registry row, team metadata, and normalized launcher record (including native id, transcript, quarantine, and passthrough state). A rowless/off-roster collision is not a backup failure and does not veto the stop: the bundle explicitly records absent registry/launcher state and includes `tmux-forensics.json` with the canonical session metadata available at capture time. File and directory durability precede publication by atomic rename; any actual backup or publication failure aborts without registry mutation or tmux stop. With seat state, the kill receipt names the exact bundle and `tap restore <handle> --archive <path>`; restore accepts only a COMPLETE matching-handle bundle, reinstates the full row as `suspended/restored_from_archive` (adding `delivery=pane` only when the older launcher row omitted its delivery class), and points to `tap session resume <handle>`. Without seat state, the receipt names the forensic bundle without offering restore, and `tap restore` refuses with `archive_no_seat_state` rather than silently succeeding or inventing a row. The normalized launcher record remains an independently readable recovery artifact; v0.20 does not revive the retired launcher manifest as a second authority.

**Terminating call-site audit (Lane C / Amendment 4):** every session-terminating path is classified — not filtered-and-omitted. Routes through the twins: chooser `[k]` / `prepare_new_launch` replacement (python), `tap team shutdown` / `tap team down` (bash), `tap out --kill` (bash), `tap team reset --kill-self` (bash). Already name-keyed without a displaced registry row (own just-created `record.name` cleanup on launch failure / respawn exception; resume/restart absorbing a shell or incumbent at the seat's own canonical name after live `classify_session` / `tmux_has`). **Documented exemption:** `tap-goalie.sh` `_goalie_stop_owned` `kill-pane` is pane-granular sidecar self-lifecycle, not seat-identity destruction. It targets the exact named window `=<owner-session>:goalie-sidecar` and kills only when that pane's current PID equals the stored watcher PID; a stored pane id is retained only as diagnostics and is never the kill key. **Licensed window-granular kill:** `tap crew remove` may `tmux kill-window` only after the obligation gate and registry-row deletion path, and only when the stored `pane_id`'s live tip reports `#{session_name}` equal to the row's registered `session` (session membership / E2 refuse — same identity disagreement as `tap_destructive_session_target`'s `pane_live_elsewhere`). A live tip in a foreign session deletes the row, skips the kill, and prints the exact `tmux kill-window -t '@N'` operator hint; a gone tip or empty `pane_id`/`session` likewise skips kill after row deletion. The kill key is the observed `#{window_id}` under that membership check — never "wherever this `%N` currently points." Chooser/`prepare_new_launch` kills append `action=killed` to `registry-events.log` (best-effort); silence on that log is never negative evidence a session survived.

**Registry behavior (tap-bzyz, no version bump — the sentinel wire is unchanged):** the launcher's session-terminating verifier now corroborates a row's generation stamp against the generation carried on the SAME tmux record as the pane ids, rather than against a separately-read one. Reading the two as two observations let a server replacement land between them, so the verifier could return the REPLACEMENT server's session while still gated on the earlier generation; `PANE_FACTS_FORMAT` already requests `#{pid}:#{start_time}` alongside the ids, so the corroborating value was on the record and simply unread. The empty case splits by ROLE and is decided deliberately: as an AUTHORIZER the verifier refuses a record that cannot state which server answered, while the same helper used as a DETECTOR stays fail-open, because `observed_server_epoch` honours `TAP_SERVER_EPOCH` exactly as the standalone probe does — so a force-unknown pin empties the record too, and refusing there would silently convert tap-24f's ratified reader semantics into fail-closed. Unstamped rows are untouched; whether a row making no generation claim may confer identity at all remains tap-zk1w. The bash twin `tap_destructive_session_target` is NOT changed here (separate language, separate scope): the two must agree on the AUTHORIZATION DECISION — which rows may name a target — not on the reason vocabulary, since the bash side carries five operator-facing refusal strings and the python side has no such consumer.
