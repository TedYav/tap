> **M1 amendment (2026-09-19, send/reply entry bridge):** the paragraph below still describes entry-point selection, and that entry behavior changed. `route()` in `runtime/bun/main.ts` is the only selector for `send`, `assign` and `reply`: `bin/tap`, `tap.sh`, `tap-send.sh` and `tap-reply.sh` now bridge those three verbs into the Bun tree even when `TAP_RUNTIME=bash` or `$HOME/.tap/runtime-bash` selects Bash, and the selector honors that selection by choosing the Bash fallback for exactly those verbs. (Both runtime selectors were later deleted; `route()` now runs these verbs natively.) Every fallback child carried the reserved internal guard `TAP_INTERNAL_OVERDUE_CHECKED=1` so the Bash tree did not bridge back; it was plumbing, not authentication, and R11 stopped setting it with the last Bash leaf (`bin/tap` still discards an inherited copy). The router holds the caller's terminal while it waits for a fallback child, so after the child exits it drains its streams and exits without Bun's termios write-back: a mode the foreground owner set meanwhile survives (tap-uzhrp). The zero-crossing recovery through `tap.sh` (missing or unexecutable Bun, missing entry point) was later removed: `bin/tap` now refuses in those cases, as the paragraph below states (verb-prelude row C). All other verbs keep the entry behavior described below.
