**A fence release that cannot prove ownership refuses, and says so (tap-7gxu).** Releasing the fence is token-proven: the holder's token must match the record. A release that matches unlinks the fence and reports success; a release that cannot establish ownership **refuses, unlinks nothing, and names the reason on stderr** — `token mismatch` when a different owner holds the fence, and `record unreadable` or `record incomplete` when the record is damaged or parses while naming nobody. A JSON root that is not an object — `[]`, `null`, a bare scalar — is the incomplete case, not an error: it parses and identifies no owner, so it refuses the same way rather than failing undocumented. So is a token that is present but not a nonempty string: a number, list, bool or object is truthy and compares unequal to every real token, which would report it as a mismatch and send the reader waiting for an owner that does not exist. **Absence is decided under the lock.** A fence released by its real owner while this call waited for the lock is absent, not unreadable, and reports rc 0; the pre-lock existence check is a fast path that avoids taking a lock in the already-released case, never the decision. The distinction is what the operator must do: a mismatch clears when the other owner finishes, so waiting is sensible, while a damaged record never clears on its own, because the liveness rule above reports missing identity factors as LIVE and nothing will reclaim it. Refusing is a change from reporting success: an unreadable record used to release quietly with nothing unlinked, so a caller was told it had released a fence that is still there. The unlink polarity is unchanged — a record that cannot be proved ours is not ours to remove, since it may belong to a live owner whose record was damaged mid-write. A refused release also leaves the caller's token in place, because blanking it would report that the caller had stopped holding something it may still hold. Tests: `reset-fence-release-contract.test.sh`.

**Team-lifecycle exclusion (`--except`, tap-nt4c):** `tap team attach|detach|down|shutdown|up` accept `--except <h1,h2,...>` — spare the named seats, act on everything else. ONE parse / validate / membership path serves all five (`lib.sh` `tap_except_*`), so the flag cannot come to mean different things on different verbs; the verbs differ only in what they DO to a spared seat. Handles are bare and team-local and go through the shared token predicate: a `<team>/<handle>` (or legacy `<team>:<handle>`) form, an empty value, an empty element between commas, and `--except` with no operand are each `error_class=usage_error`. A handle no seat on the acting registry answers to is `error_class=not_found` naming the unmatched handles AND the live roster — never a silent skip, because a typo'd handle quietly stopping the seat the operator meant to spare is the failure the flag exists to prevent. The roster is the acting registry's own seat keys, resolved through the acting-registry rebind (never the bus decoy), so one roster answers for all five verbs. Duplicates dedupe silently. `--except` composes with `--keep-self`: the spared set is their UNION and receipts report it as one set. Sparing is SESSION-granular wherever the effect is — down/shutdown kill a session, detach detaches a session's clients — so a spared seat also spares every co-tenant of its tmux session, and `shutdown` retains those rows in-file instead of deleting them (the same orphan rule `--keep-self` follows for pane-crew siblings). Sparing every candidate is a LEGAL no-op: exit 0 plus the line `tap team <verb>: no seats matched after exclusions (excluded: ...)`, never a silent success. `down` / `shutdown --json` carry `excluded_handles[]` (the union) and `spared_sessions[]` alongside the acted-on `stopped_sessions[]`; `tap team up --json` is a per-record stream rather than one aggregate object, so its exclusion receipt rides stderr (the same rule team refresh uses to keep JSON stdout byte-stable) and only the all-spared case emits an aggregate carrying `excluded[]`; `attach` and `detach` have no `--json` surface and name the spared set in their text receipts. `tap team detach --handle` and `--except` are opposite selectors and refuse together (`usage_error`). `tap session resume --all` deliberately grows no public `--except`: `tap team up` gates the set and hands it to the launcher internally, so there is no second door past the roster check.
